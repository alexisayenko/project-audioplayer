# Library screen

Code: `web/js/library.js`, `web/js/store.js`, `web/js/playable.js`, `web/js/track-sub.js`, `web/js/genre-cell.js`. Status values reflect code read on 2026-10-13. Source of truth: the code and

## Screen

- LIB-001 MUST: Library is the default route (`#/library`); a signed-out visitor is redirected to Settings (sign-in only, WEB-001). Status: implemented
- LIB-002 MUST: it loads `GET /library` once per session, refreshes after every add, edit, delete and BPM re-detect, and shows "Loading your library...", then on failure the error with a Retry button. Status: implemented
- LIB-003 MUST: the header shows the total ("N songs"); when a filter or search is active a status line shows "N songs match" plus up to three selected value names; an empty library shows a "No songs yet" card ("Paste a YouTube or SoundCloud link to save the song to your library.") with an "Add song" button; no match shows "No songs match. Clear the search or the filters." Status: implemented
- LIB-004 MUST: search, sort and filter selection persist while navigating between tabs in the same page session (not across reloads). Status: implemented

## Song card

- LIB-010 MUST: a Library row is one line of the table (WEB-031): cover (lazy-loaded, blank if missing); Track (title, with a muted "Artist · Year" line below it); Genres (from 900px; the BPM badge sits at its start, LIB-019); Time (m:ss) or, for a song without server audio, the service logo link (WEB-023); the row menu button. The row shows no album or tag chips; BPM is a badge in the Genres cell (LIB-019). Status: implemented
- LIB-011 MUST: Play now (`player.playNow`; the cover button of a playable row, LIB-121, or the row menu item "Play now"; the title click opens the song card instead, LIB-014) inserts the song after the current one and plays it, keeping the user on Library. Rows without server audio have neither (WEB-023). Status: implemented
- LIB-012 MUST: the row menu item "Add to playlist" (`player.add`; planned wording with Playlists, PLS-008: this item is renamed "Add to queue" and a new item "Add to playlist..." opens the playlist picker; only on rows with server audio) appends to the queue; toast "Queued" (queue was empty, not played), "Added", or "Already in queue" (duplicate ignored). Status: implemented
- LIB-013 MUST: the currently playing song's card is highlighted. Status: implemented
- LIB-014 MUST: the row menu (the "..." button, `aria-label` "More: <title>") offers "Edit song" (opens the Edit dialog) and "Share link" (opens the share dialog, SHARE-006); clicking the title opens the song card (LIB-120; changed 2026-10-14: it used to play the song, before that it opened Edit). There is no separate edit or delete button on the row; Delete lives in the Edit dialog. Status: implemented
- LIB-015 MUST: where tag chips are shown (Playback details, tag editor, tag picker) `key:value` tags render with the key as a highlighted prefix; Library rows show only the genre text (LIB-010). Status: implemented
- LIB-017 MUST: `decade:` tags show as "the 90s" on chips and in the Years filter sheet (chronological); search matches "90s". Status: implemented
- LIB-016 MUST: `country:` tags show a human name on chips and in the Countries filter sheet ("Lithuania", via `Intl.DisplayNames`, raw value as fallback, raw tag in the tooltip); search matches both the code and the name. Status: implemented
- LIB-019 MUST: a song with a BPM shows an outlined pill badge (rounded integer plus a tiny "BPM" caption, monospace tabular digits, tooltip "Beats per minute (estimated)", `aria-label` "BPM 132") at the start of the Genres cell, before the genre text, on the same line (fixed-width slot, also reserved as an empty spacer in rows without BPM so genre text stays aligned; the genre text shrinks and clamps to 2 lines first); the Genres cell exists from 900px, so below 900px the row shows no badge (the song card still does, LIB-120); no badge when BPM is null or 0; it is not a column. Status: implemented (layout not browser-verified)
- LIB-018 MUST: on the web the list columns are cover / Track / Genres / Time (plus the menu button), with no row-number, Album, Artist or Year column (WEB-031, LIB-010); the iOS list is unchanged. Status: implemented

- LIB-120 MUST: clicking or tapping a Library row anywhere except the cover button, the playlist toggle, the "..." menu button and links opens the song card, a read-only dialog (`web/js/song-card.js`, `<dialog id="song-card">`, a bottom sheet under 720px, a 560px dialog above) with a square cover the same size as the Now playing cover (up to 420px, centred, full width on phones; `--cover-max`), the title with its muted remix part (LIB-112), a muted "Artist · Year" line (year left out when missing, as the Now playing subtitle) and the album on its own muted line below it (omitted when empty); each is shown once, long names wrap, tag chips grouped by Genre, Decade, Country and other keys with human names (`lang:` tags hidden as on Playback), the BPM badge, the duration, the download state ("Downloaded to the server", "Not downloaded" or the fetch status), the stored links as real new-tab icons (YouTube, SoundCloud, Spotify, Wikipedia, MusicBrainz, Discogs; `storedLinkStates`, ADD-053), and the buttons Play now (Pause or Play for the current song), Add to playlist or Remove from playlist, Download (server audio only), Download to server (no audio, no fetch running), Edit and Close. The row title is a button (`aria-label` "Open: <title>") so the card is reachable from the keyboard. Status: implemented (not browser-verified)
- LIB-121 MUST: the cover of every Library row is a real button (`web/js/row-cover.js`, `aria-label` "Play <title>", "Pause <title>" or "Download <title>", at least 40px; the thumbnail is `--row-cover-size`: 60px in the table from 720px, 84px (at most 25% of the width) on the phone, 1.5x the earlier 40 and 56px, rows 76px high from 720px): hover or keyboard focus shows a centred translucent round icon; clicking plays that song now (same as the menu's Play now, the user stays on Library). A song without server audio and with Auto-download on behaves the same (the fetch starts, PLY-110); with Auto-download off the icon is a download arrow and the click fetches the audio to the server; while a fetch runs the button is inert. Status: implemented (not browser-verified)
- LIB-122 MUST: the current song's cover shows its state without hover: a semi-opaque (about 75%) Pause symbol on a dark round scrim while it plays (click pauses), a Play symbol the same way while it is paused (click resumes). The row rebuilds on every player event and keeps keyboard focus on its cover button. Status: implemented (not browser-verified)
- LIB-123 MUST: where the device has no hover (`@media (hover: none)`) a non-current cover shows no overlay and no tooltip; tapping the cover plays or pauses, tapping elsewhere in the row opens the card. With `prefers-reduced-motion` there are no transitions. Status: implemented (not browser-verified)
- LIB-124 MUST: the card stays in sync while open: it repaints after a library refresh (so after the Edit dialog saves, which opens on top of it), on player and download changes (focus on the action buttons is kept), and closes itself when the song is deleted. Close, Esc and a backdrop click close it; focus returns to the row's title button. Status: implemented (not browser-verified)
- LIB-125 MUST: when the song has a `remix_year` the song card (LIB-120) shows a "Remix year 2024" line among its facts, and the remix part of the title carries the tooltip "Kav Verhouzer Remix (2024)"; the visible parenthesis and the "Artist · Year" and album lines are unchanged. Library search does not match years. Status: implemented

## Search

- LIB-020 MUST: search (placeholder "Search title, artist, album, remix or tag") is a case-insensitive substring match over title, artist, album, the Remix & additional production value (whole string, so each " - " token matches too) and all visible tags, updated on every keystroke. Status: implemented

## Tag filter

- LIB-030 MUST: four category chips (Tags, Genres, Years, Countries, with counts) open a filter sheet of value pills with counts, multi-select (values in a category are OR, categories are AND), Clear, and a "Show N songs" button (WEB-011); changed 2026-10-13: single-select chips grouped by key are gone (TAG-033 is the iOS-era rule). Status: implemented

- LIB-031 MUST: when a filter and/or search text is active and at least one song is listed, an "Add all N to playlist" button (N = songs currently listed) sits in the sort bar; it is hidden when neither is active (no "add entire library"). Click appends the listed songs that have server audio (WEB-023) to the queue, de-duplicated, at the end, without starting playback (same as per-song Add), toast "Added X songs (Y already in queue)". With exactly one filter value selected it becomes a chip in the playlist controls (as in PLY-035, only the listed songs are added) so Clear removes them; otherwise (several values, or search only) the songs are added as manual. Status: implemented

## Sort

- LIB-040 MUST: sort options (a select styled as an accent text button): Recently added (`added_at` descending, default), Title (A-Z), Artist (A-Z, then title), Year (newest first, missing last), BPM (ascending, songs without BPM last). Status: implemented
- LIB-041 MUST: text sorts are case- and accent-insensitive (`localeCompare`, base sensitivity). Status: implemented

## Edit dialog

- LIB-050 MUST: the Edit dialog is the shared song form of the Add dialog (WEB-033): Title (required), Artist and Remix & additional production as token pills with one tokenizer (WEB-039) (WEB-028, WEB-029), the "Wikipedia says" hint, "Get metadata" with service icons (fills only empty fields, `POST /metadata` with the song's current title, artist, Wikipedia links and sources), Album, Year (0..3000), a read-only BPM label ("<n> BPM" rounded, or "Not detected yet") with a Re-detect button (no manual entry; the Add dialog shows the muted line "BPM is detected after saving"), Genres (with autocomplete, WEB-030) and Countries chip fields (WEB-024), Tags (shared tag editor, LIB-055), and the two Wikipedia inputs (always visible, article name only). The dialog has Cancel, Save and "Delete from library". Status: implemented
- LIB-133 MUST: the Edit dialog starts with the song's cover (96px, the placeholder disc when there is none) and a "Change cover" button that opens three choices: "Upload file" (JPEG, PNG or WebP, at most 5 MB, checked in the browser first), "From address" (an http or https image address, then "Use this image"; Enter submits) and "Remove cover" (only while a cover exists). A choice is applied at once, not on Save: the catalog is refreshed, a toast says "Cover updated" or "Cover removed", and the Library rows, the song card, the mini-player and Now playing show the new image (the cover URL carries `?v=<cover_v>`, API-097). Errors stay in the dialog in plain English ("Use a JPEG, PNG or WebP image.", "The image is larger than 5 MB.", "Could not reach that address.", "That address is not allowed."); Escape closes the choices; all controls are native buttons, so the keyboard reaches them. Guests and read-only users never see it (WEB-061); the song card reaches it through its Edit button. `web/js/cover-edit.js`. Status: implemented (not checked in a browser)
- LIB-051 MUST: Save sends `PATCH` with all fields except `bpm` (empty year becomes `null`), closes, refreshes, toast "Saved"; a server error shows inline and keeps the dialog open. Status: implemented
- LIB-052 MUST: Re-detect calls `POST /songs/{id}/bpm/detect`, updates the BPM label (the server saves the new value immediately, independent of the Save button); a failure shows inline. Status: implemented
- LIB-053 MUST: Delete is inside the Edit dialog and asks for confirmation ("Delete song?"); it removes the record, audio file and cover; a 404 (already gone) just closes and refreshes. Status: implemented
- LIB-054 SHOULD: the BPM value carries a tooltip saying BPM is a heuristic that may be off by half or double. Status: implemented
- LIB-055 MUST: the Tags field is the shared tag editor (`web/js/tag-editor.js`, also used by Add, ADD-004; WEB-033): a text input (Enter or comma adds a chip, accepts `key:value`, filters the list below as you type, matches code and display name), the song's current tags as chips with an x (without `genre:`, `country:` and `lang:` tags, which the Genres and Countries fields hold, WEB-024), in Add a "Suggested" row, and below every other library tag as a toggle chip (assigned ones selected) grouped Decade (chronological), other keys, Tags, most-used first with counts; the list scrolls inside the dialog (max height). Changing the Year input immediately shows the derived decade chip (preview only, TAG-038). Save sends the full tag array. Status: implemented

- LIB-056 MUST: the Edit dialog has "Wikipedia: song" and "Wikipedia: band" inputs showing the article name only (WEB-032; empty clears the link; no fill button, see ADD-051); Save sends `wikipedia_song` and `wikipedia_artist` with the other fields. Library rows do not show the links. Status: implemented
