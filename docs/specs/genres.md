# Genres map

The Genres map (`#/genres`) shows the user's `genre:` tags as a graph of related genres. Genres form a directed acyclic graph (a genre has many parents and many siblings), not a tree. The relations come from Wikidata, cached on the server (ADR-0014). It is a browsing aid: nothing here changes a song, and playback never depends on it. Requirement format: see [README](README.md).

## Graph model and data

- GEN-001 MUST: the genre graph is a directed acyclic graph. A node is a genre, an edge `child -> parent` (`kind: "parent"`) says "is a subgenre of"; a node may have several parents. A second edge kind `related` (undirected, weaker) links two genres that are both in the graph and are not already parent and child. Cycles in the source data are broken at build time (depth-first back edges are dropped), so the served graph never contains one. Status: implemented
- GEN-002 MUST: each distinct `genre:` value of the user (lowercase, spaces collapsed) is resolved to a Wikidata item by `wbsearchentities` (English, 10 hits) restricted to music genres: the item's `instance of`/`subclass of` contains `Q188451` (music genre), or its English description reads as a music genre; the hit's label or matched alias must equal the value (a "label" match beats an "alias" match, then the search rank). Two tags that resolve to one item become one node. A value without a match stays a loose node (`qid: null`, no parents, family "Other"). Status: implemented
- GEN-003 MUST: ancestors are fetched by `subclass of` (P279), up to 6 levels above the user's genres, in `wbgetentities` batches of 50 ids (`languages=en`, `props=labels|claims|descriptions`); only ancestors that are music genres are shown, and only up to 4 levels above a user genre. `related` edges come from `influenced by` (P737), only between nodes already in the graph, never fetched for their own sake. (Wikidata has no usable "stylistic origin" property; P7937 is "form of creative work".) Status: implemented
- GEN-004 MUST: the resolved slice is cached server-wide in `genre-ontology.json` under `AUDIO_DATA_DIR` (label to QID, and per QID the label, parents, related, genre flag and fetch time). An entry older than 30 days is refreshed; the cache is used as is when Wikidata is unreachable (offline start, failure: the graph shows what is cached and further attempts wait 5 minutes). Requests carry the `AUDIO_MB_USER_AGENT` header, a 8 s timeout and at most one call per 0.3 s. The file holds only Wikidata facts, never a song, tag count, user or email. Status: implemented
- GEN-005 MUST: a request never waits for Wikidata. What the cache lacks is fetched by one background worker (one at a time, server-wide); the response then has `pending: true` and the web asks again every 5 s (at most 24 times, about 2 minutes) and recolours the nodes it already shows without resetting their positions (GEN-022). Status: implemented
- GEN-006 MUST: `count` of a node is the number of DISTINCT songs of this user tagged with that genre or any descendant genre (a song reachable through two children is counted once); `ownCount` counts the node's own tag only. Counts are computed per user from that user's library; nothing about one user's songs reaches another user's graph. Status: implemented
- GEN-007 MUST: the graph has at most 400 nodes. Over the cap, ancestor nodes with no song of their own are dropped first (deepest first, smallest first), then the user's least-used genres. Status: implemented
- GEN-008 MUST (family list and mapping superseded by GEN-037 to GEN-039, ADR-0021): each node has a `family`, one of the Discogs top-level genres (Electronic, Rock, Pop, Hip Hop, Jazz, Funk / Soul, Classical, Reggae, Latin, Blues, Folk, World, & Country, Stage & Screen, Non-Music, Children's, Brass & Military) or "Other". It is the first match found walking the node and its ancestors breadth-first (closest first) in the reviewed table `server/data/genre_families.json` (superseded); no match, and every loose node, is "Other". Status: implemented
- GEN-009 MUST: node ids are slugs of the label (made unique with the lowercase QID, then `-2`), stable for a given cache; `tags` lists the user's own normalised genre values that resolved to the node (empty for pure ancestors), so a client can turn a node into `genre:<value>` Library filters. Status: implemented

## Page

- GEN-010 MUST: the sidebar has a "Genres map" item (route `#/genres`) after Playback and before Settings, in the existing nav-icon style; in the 64px rail it is the icon with the tooltip, below 480px a tab-bar item. A signed-out visitor does not see it (WEB-001). Status: implemented
- GEN-011 MUST: the page shows a force-directed graph on a canvas (no external library: `web/js/genre-sim.js` is a compact simulation with link springs, Barnes-Hut many-body repulsion, centring, collision and alpha decay; `web/js/genre-graph.js` draws and handles input) filling the whole page (GEN-020) with the outline as a side panel (GEN-021). The graph rests at a low alpha with a slow bounded oscillation so it stays alive; dragging a node pulls its neighbours through the springs and releasing lets it settle. Status: implemented (not checked in a browser)
- GEN-012 MUST: pointer and touch input: drag a node, drag the background to pan, wheel or pinch to zoom around the pointer, double click a node to zoom to it and its neighbours, hover only shows a tooltip "label - N songs" and a ring on the node (GEN-026), click selects. Keyboard on the focused canvas: plus, minus, arrows, 0 (fit), Escape (deselect). Status: implemented (not checked in a browser)
- GEN-013 MUST: a node's area follows the square root of its `count` (radius capped), its colour is its family's (a fixed categorical palette in `web/genres.css` with light and dark values), parent edges are thin lines with an arrowhead pointing to the parent, related edges are dashed; labels follow GEN-023; the family legend is part of the toolbar (GEN-022). Status: implemented
- GEN-014 MUST: selecting a genre (graph, outline or search) opens a panel with its name, a small W icon (GEN-035), family, song count, subgenre chips (click selects; parents are no longer listed on the card, the outline's "also under" and the graph edges show them)  and the button "Show N songs in Library", which opens Library filtered by the union of the genre's own and all descendant genre tags (several tags of one category already mean "any of them", LIB filter semantics), with search cleared. The button is disabled at 0 songs. Counts are recomputed in the browser from the loaded library, so they follow edits without a reload. Status: implemented
- GEN-015 MUST: the search box finds genres by name (exact, then prefix, then substring; best 8), and choosing one centres and selects it (Enter takes the first). Status: implemented
- GEN-016 MUST: the outline is an expandable tree: a row per family (Discogs order, "Other" last), under it the genres without parents, then their subgenres by song count. A genre with several parents appears under each of them, with "also under X, Y" naming its other parents. Clicking a genre selects it in the graph; selecting in the graph expands the outline to it and scrolls to it. The expanded rows are kept in `localStorage` (`electrophone.genresOutline`, tolerates failing storage). It lives in the collapsible outline panel (GEN-021), opens with every family expanded the first time, and is the keyboard and screen-reader alternative to the canvas. Status: implemented (not checked in a browser)
- GEN-017 MUST: states: loading ("Loading genres..."); no genre tags ("No genres yet - add songs with genre tags"); the server graph unavailable (error) or without any resolved genre ("Genre data unavailable - showing your tags only": a flat graph of the user's genre tags, family-less, no edges); background lookup running (status chip "Resolving genre families..."). Status: implemented
- GEN-018 MUST: `prefers-reduced-motion: reduce` gives a static, pre-settled layout with no jitter, no animated zoom and no drift; dragging moves only the dragged node. Status: implemented
- GEN-019 MUST: performance: 400 nodes simulate and draw within one 60 fps frame on a current laptop (measured: simulation of 400 nodes, 300 ticks, a few ms each); the loop stops when the route is left (`destroy`), when the tab is hidden (`visibilitychange`) and is not scheduled at all under reduced motion between changes. Status: implemented (frame time not measured in a browser)

- GEN-020 MUST: the page is a full-viewport workspace: the graph canvas fills all space right of the sidebar or rail, from the top of the stage to the bottom (above the mini player, whose height stays free, and above the tab bar on phones), with no maximum width and no card margins. It follows the canvas size with a `ResizeObserver` (device-pixel-ratio aware), keeps the graph centred on resize, fits the graph on first load once the layout has settled, and "Fit all" fits it again. The title "Genres map", the search box, the status chip and the legend button form a compact translucent toolbar at the top left, the zoom buttons sit at the bottom left, the "Outline" button at the top right and the selected-genre card (GEN-014) floats at the bottom right. Status: implemented (not checked in a browser)
- GEN-021 MUST: the outline (GEN-016) is a collapsible card (min(360px, 100% - 24px), top right) that floats over the canvas at every width and never resizes it or moves the map; below 720px it is a bottom sheet (55% high). Esc closes it; rows wrap long names and cap indentation at 6 levels. The "Outline" button or the panel's close button toggles it; the state is kept in `localStorage` (`electrophone.genresPanel`, tolerates failing storage) and defaults to open from 1100px and closed below. Status: implemented (not checked in a browser)
- GEN-022 MUST: family colours come from the server's `family` per node. While `pending` is true the web asks again (GEN-005) and applies the new families in place: positions are kept, nodes fade to their new colour, and a status chip says "Resolving genre families...". A collapsible legend in the toolbar lists the families present with counts; clicking a family hides or shows its nodes and their edges, "Show all" resets. Status: implemented (not checked in a browser)
- GEN-023 MUST: labels are drawn largest node first and a label is skipped when its box intersects one already placed (grid-based collision in screen space), so zooming in shows more labels; the selected node and its neighbours are always labelled. Text has a halo in the surface colour for contrast on light and dark. Status: implemented
