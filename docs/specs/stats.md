# Statistics (web)

Code: `web/js/stats.js` (page), `stats-chart.js` (canvas render and pointer/keyboard handling), `stats-data.js` (pure logic), `stats-table.js` (table view), `stats-genres.js` and `stats-genres-view.js` (Genres tab), `web/stats.css`. Tests: `stats-data.test.mjs`, `stats-table.test.mjs`, `stats-genres.test.mjs`, `stats.test.mjs`. Why: [ADR-0016](../tech/decisions.md) sub-note. No server change: the page plots the songs already in the store.

## Page

- STA-001 MUST: `#/stats` ("Statistics", nav item after Genres map, icon: axes with four dots) is a full-viewport workspace like the Genres map: a canvas fills the area right of the sidebar down to above the mini-player; below the standard page head (STA-050) a translucent toolbar top-left holds the count "N of M songs plotted", a Colour by select, Legend, View as table, "Center chart (C)" and (only while zoomed or panned) Reset. Status: implemented (not checked in a browser)
- STA-002 MUST: one dot per song that has a valid year (the displayed year: the version year when the song has one, else the original; for a remaster always the original, LIB-150) (finite number, 1900..current year + 1) and a valid BPM (finite number, 20..300, the server range); 0, negatives, null, strings and out-of-range values count as missing; the others are not plotted and a note reads "N songs without year or BPM are not shown". With nothing plottable the page says "Songs need a year and a BPM to appear here"; before the library has loaded it says "Loading songs...". Status: implemented
- STA-003 MUST: the y axis never goes below 0 (zoom-out, pan and Center are clamped); x axis = year and y axis = BPM, both fitted to the field limits (STA-025); integer ticks; light grid, muted tick labels, axis titles "Year" and "BPM". The canvas is DPR-aware and follows a ResizeObserver. Status: implemented
- STA-004 MUST: dots are 5px radius, 55% opaque so overlaps show; a deterministic jitter seeded by the song id (under 0.34 year and 1.4 BPM) keeps songs with the same year and BPM from hiding each other. Tooltips and tables show the true values. Status: implemented
- STA-005 MUST: Colour by Genre family (default when nothing is saved; the Genres map family colours, the same `--gf-0..15` CSS variables read at draw time so light and dark match the map; a song's family is the family of the first of its `genre:` tags, in tag order, then a legacy plain `genre`, that resolves to a genre-graph node via the shared matcher in `genre-playing.js`, else "Other" in the map's grey; the legend lists the families present with counts, by count, Other last), Decade (from the year), Audio on server (has audio or not) or None; the choice is remembered in `localStorage` (`stats.color`; a saved choice always wins). The graph comes from `GET /genres/graph`, fetched once per page visit; while it is missing or `pending` the dots are neutral grey and the legend reads "Resolving genre families...", polled every 5 s up to 24 times (about 2 minutes) and recoloured in place (positions, zoom and selection untouched). The tooltip adds the family and genres; the table has a Family column. Status: implemented (not checked in a browser)
- STA-006 MUST: a collapsible legend lists each colour with its count; clicking an item hides or shows that group (dots, selection and table follow). Status: implemented
- STA-007 MUST: nothing animates continuously: the base canvas is redrawn only when data, view, size or hidden groups change; hover, selection and focus are drawn on a second canvas; draws are coalesced with `requestAnimationFrame`. Hit testing uses a spatial grid (9px hit radius, nearest dot wins) so about 5000 dots stay smooth. The route's cleanup disconnects the observer and cancels the pending frame. Status: implemented

## Interaction

- STA-010 MUST: hovering a dot highlights it and shows a tooltip with the title (remix part via `display-title.js`), artist, year and BPM; clicking a dot opens the song card (falls back to the edit dialog if `song-card.js` is missing). Status: implemented
- STA-011 MUST: dragging on empty chart draws a rubber-band rectangle that selects the visible dots inside it; a floating panel reads "N selected:" with Show in Library, Add to playlist, Play and Clear. Add to playlist and Play call `player.addListed` / `player.playListed` with the selected songs, exactly like the Library buttons (auto-download behaviour included); Clear (or Escape, or a click on empty chart) empties the selection. Show in Library is shown disabled with the tooltip "Coming soon" until Library gets an id filter. Status: implemented (Show in Library: planned)
- STA-012 MUST: the wheel zooms both axes around the cursor (limited to 2 years and 8 BPM minimum span); Shift+drag or middle-button drag pans; double-click, `0` or the Reset button restores the full view. Status: implemented (not checked in a browser)

## Accessibility

- STA-020 MUST: the chart canvas is focusable with `role="img"` and the label "Scatter plot of N songs: year on the horizontal axis, BPM on the vertical axis."; arrow keys move a dashed focus ring to the nearest dot in that direction, Enter opens the song, and a polite live region announces the focused song (title, artist, year, BPM). Status: implemented
- STA-013 MUST: right-button drag on the chart pans both axes (same pan as Shift+drag and middle-drag; the dot under the cursor stays under it); the context menu is suppressed on the canvas only; a pan never selects or opens a song; the tooltip is hidden while panning. The view stays inside the field limits (STA-025). `C` or the Center button centres the extent midpoint keeping the zoom (instantly); Reset, double-click and `0` fit everything. The toolbar tooltip lists these gestures. Status: implemented (not checked in a browser)
- STA-021 MUST: "View as table" swaps the chart for a sortable table of the plotted songs (Title, Artist, Year, BPM, Decade; header buttons set `aria-sort`); a row's title opens the song card like a dot click. Status: implemented
- STA-022 SHOULD: tempo bands (shaded 90-110, 120-130, 170-180). Status: planned

- STA-025 MUST: field limits: from the plotted points (with their jitter) take the leftmost, rightmost, top and bottom values, width w = maxX - minX and height h = maxY - minY; the limits are left = minX - 20% of w, right = maxX + 20% of w, bottom = minY - 20% of h, top = maxY + 20% of h (the y floor stays 0, STA-003). A zero or tiny extent grows symmetrically to at least 10 years / 40 BPM; with no points the previous default (2000..2010, BPM 60..200) stays. The initial view, Reset and Center fit these limits; zoom-out stops at them and pan/zoom cannot move the view outside them. Pure functions `fieldLimits` and `clampRange` in `web/js/field-limits.js`. Test: `web/js/field-limits.test.mjs`. Status: implemented (tests not run, not checked in a browser)
