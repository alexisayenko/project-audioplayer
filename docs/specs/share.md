# Share link

Share a song at a chosen time with a chosen visualizer (task-0028). Code: `web/js/share.js` (pure URL build and parse), `share-ui.js` (dialog), `share-open.js` (opening a link), route handling in `app.js`. Web only; iOS universal links are not built.

- SHARE-001 MUST: a link is `<origin>/#/play/<songId>?v=1&...` and uses the existing hash router; `parseShareParams` and `buildShareUrl` in `web/js/share.js` are pure and tested. Status: implemented
- SHARE-002 MUST: the song id matches `[A-Za-z0-9._-]{1,80}`, anything else is rejected ("This song is not available"). Status: implemented
- SHARE-003 MUST: parameters are `v` (format version, 1), `t` (start second, integer 0..86400), `viz` (`bars|ring|terrain`), `style` (Terrain style id, only with `viz=terrain`), `bg` (`1|0`, Visualizer background), `fs` (`1` opens the full-screen visualizer), `cam` (`eye,pitch,yaw`), `fl` (`1` turns Camera flight on, only with `viz=terrain`; never part of `cam`). Omitted parameters change nothing. Status: implemented
- SHARE-004 MUST: every value is validated and clamped on parse (`t` to the song duration once known, `cam` through `camClamp`); invalid values are dropped, unknown parameters ignored. Status: implemented
- SHARE-005 MUST: a link contains no email, token or other personal data. Status: implemented
- SHARE-006 MUST: a Share link button (icon, accessible name "Share link") sits on Playback and in the top-right cluster of the full-screen visualizer, and "Share link" is in the Library row menu. Status: implemented (not checked in a browser)
- SHARE-007 MUST: the dialog has the checkbox "Start at current time", an editable mm:ss field (invalid input shows "Use mm:ss, for example 1:23" and disables the buttons), "Open in full-screen visualizer", "Include camera" (only when the camera differs from the default, Terrain mode), a read-only link field, and the summary of the visualizer settings that are included. Status: implemented (not checked in a browser)
- SHARE-008 MUST: "Share" uses `navigator.share` when present; "Copy link" uses `navigator.clipboard`, falling back to a hidden textarea and `execCommand('copy')`; success is announced in a polite live region as "Link copied". Status: implemented
- SHARE-009 MUST: opening a link replaces the hash with `#/library` first, so a reload does not repeat it. Status: implemented
- SHARE-010 MUST: a song the viewer cannot see (missing, or not in the guest or own library) shows "This song is not available" and stays on Library. Status: implemented
- SHARE-011 MUST: a song without audio on the server opens its catalog card with "No audio on the server yet" (guest view without audio: "Audio is not available in the guest view"). Status: implemented
- SHARE-012 MUST: shared `viz`, `style`, `bg`, `cam` and `fl` apply for this visit only and never overwrite the stored preferences (`ap2.viz.mode`, `ap2.viz.terrain.style`, `ap2.viz.bg`, camera key); opening the Settings toggle for the background ends the override. Status: implemented
- SHARE-013 MUST: autoplay is not attempted; a "Tap to play at 1:23" gate (or "Tap to play" at 0:00) with "Not now" opens on Playback, and the tap starts the song, seeks to `t` on `loadedmetadata`, opens the full-screen visualizer for `fs=1` and unlocks the AudioContext (VIZ-036). Status: implemented (not checked in a browser)
- SHARE-014 MUST: the gate and dialog are keyboard operable (focus moves in, Escape closes, Tab stays in the gate); typing in the dialog does not trigger visualizer hotkeys. Status: implemented
- SHARE-015 MUST: styling uses `web/tokens.css` variables only; no animation is added (reduced motion holds). Status: implemented
- SHARE-016 SHOULD: a signed-out visitor with no public view can open a link after signing in; today the link is dropped on the redirect to Settings. Status: planned
- SHARE-017 MUST: Camera flight (VIZ-074) is shared as `fl=1`, written only when `viz=terrain` and the sender's flight is on and the dialog checkbox "Camera flight on" (shown only in Terrain mode, checked when flight is on) is ticked; parse accepts only `fl=1` together with `viz=terrain` (anything else is dropped); it applies for this visit only (the stored `ap2.viz.flight` is restored) and reduced motion still wins. Status: implemented (unit-tested; not browser-checked)
