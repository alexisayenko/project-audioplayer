## Semantics

- TAG-001 MUST: tags are the only grouping mechanism; there is no playlist entity and no `genre` field. A "playlist" is a tag filter. Status: implemented
- TAG-002 MUST: a tag is a plain string (`workout`) or namespaced `key:value` (`genre:synthwave`, `mood:chill`). Status: implemented
- TAG-003 MUST: the first `:` splits key and value. Status: implemented

## Normalisation (server: create, PATCH, preview, migration)

- TAG-010 MUST: whitespace is trimmed and runs of spaces collapsed. Status: implemented
- TAG-011 MUST: a valid `key:value` (both parts non-empty) is stored lowercased. Status: implemented
- TAG-012 MUST: a plain tag keeps its case. Status: implemented
- TAG-013 MUST: a tag with `:` but an empty key or value is dropped, never saved as a plain tag (`mood:` and `:x` vanish). Status: implemented
- TAG-017 MUST: the tag editor commits leftover input text on Save only if it is a complete tag (non-empty; for `key:value` both parts non-empty); an incomplete `mood:` or `:x` is ignored. Status: implemented
- TAG-014 MUST: empty tags are dropped; duplicates are removed case-insensitively, first occurrence wins, order preserved. Status: implemented
- TAG-056 MUST: `country:` and `lang:` values are canonicalised to ISO codes (`server/app/countrycodes.py`, `server/app/langcodes.py`, embedded tables, no dependency): a country given as alpha-2, alpha-3, English name or alias (`usa`, `U.S.A.`, `United States of America`, `uk`/`england` to `gb`, `russia`/`Russian Federation` to `ru`, `holland` to `nl`, `Deutschland` to `de`, `Türkiye` to `tr`) becomes `country:<alpha-2>`; compared case, accent, punctuation and a leading "the" ignored. A language name (English or native, `russian`, `Deutsch`), 639-3 code or region-tagged code becomes `lang:<639-1>`. Duplicates collapse after mapping (`country:usa` + `country:us` give one). Historical countries are a closed list of first-class values (TAG-058): `ussr`, `cccp` and `Soviet Union` map to `country:su`; other former states map to nothing. Applied in `library.clean_tag` on every write and on load (the load migration; idempotent, saved with the next write). The web client canonicalises and merges counts defensively (`mergeTagCounts`, `web/js/tagname.js`, `countries.js`). Status: implemented
- TAG-059 MUST: the web resolves every typed or suggested country through ONE function, `canonicalCountry` in `web/js/countries.js` (alias, name and code table `countries-data.js`, generated by `scripts/gen-countries.py`); `countryCode` in `metadata-apply.js`, the tag editor, the chip field and the tag display all call it, so the picker, the pills and the Add form never disagree on a code. Status: implemented
- TAG-057 MUST: `country:` accepts only known countries: creating or editing a song with an unknown `country:` value is refused (API-052); legacy unmapped values are kept untouched on load (a warning is logged) and shown in the editor as flagged chips that can be removed; suggestions from MusicBrainz and Wikidata emit only ISO codes (`XW`, `XE` and similar are dropped; MusicBrainz `SU` is kept as `country:su`). The tag editor opens a searchable country list (English names, codes and aliases) after `country:`; typing an unknown country shows "Pick a country from the list" and adds nothing. `lang:` stays free for unknown values. Status: implemented
- TAG-058 MUST: historical countries. `country:su` (display name "Soviet Union", ISO 3166-3 former code, alpha-3 `SUN`) is a predefined value: accepted on write, never flagged as unknown, offered by the country picker (search `soviet`, `ussr`) and suggested from MusicBrainz or Wikidata code `SU`. Aliases `ussr`, `u.s.s.r.`, `soviet union`, `the soviet union`, `cccp`, `sssr` map to `su`. The table marks such codes `historical` (`countrycodes.is_historical`, `isHistoricalCountry` in `web/js/countries.js`); names come from the table, not `Intl.DisplayNames`, which does not know them. Reason: flags will be shown later, and no emoji flag exists for a former state, so flag assets for historical codes must be images. Candidates, add on request: `yu` Yugoslavia, `cs` Czechoslovakia, `dd` East Germany. `web/js/countries-data.js` is generated from the table: run `python3 scripts/gen-countries.py` after editing `countrycodes.py`. Status: implemented
- TAG-016 MUST: namespaces `country:` (ISO 3166-1 alpha-2, e.g. `country:lt`) and `lang:` (ISO 639-1, e.g. `lang:ru`) are ordinary tags with normalised values: lowercase; `lang:` is no longer suggested (languages dropped, ADR-0012 note) but existing `lang:` tags keep this normalisation: a 3-letter code with a 2-letter equivalent is mapped (`rus` to `ru`) and a region suffix is dropped (`ru-RU` to `ru`); unknown `lang:` shapes are kept as plain lowercase tags, never rejected (`country:` is stricter, TAG-057). Status: implemented
- TAG-050 MUST (v2: DATA-161, computed at runtime from the displayed year): decade tags: the server derives `decade:<NN>s` from `year` for every year from 1950 up to `max_year()` (the current UTC year + 1; `decade:50s` ... `90s`, `00s`, `10s`, `20s`, then `30s` once the clock reaches 2029 with no code change; rule: floor(year/10)*10 mod 100 as two digits + `s`; 1994 gives `decade:90s`, 2007 `decade:00s`, 2013 `decade:10s`); a year below 1950, above `max_year()` or missing derives nothing. Groups sort chronologically, future decades last. Status: implemented
- TAG-051 MUST: on every create, PATCH and load, when `year` is in range the song's `decade:*` tags are replaced by exactly the derived one (a manually typed or stale decade tag is overwritten, so changing the year updates it); when the year is missing or out of range existing `decade:` tags are left untouched. Existing songs with a year are migrated on load and saved on the next write. Status: implemented
- TAG-052 MUST: the `decade:` value is lowercased like any `key:value`; a value not matching `^\d{2}s$` is kept as a plain-normalised tag, never rejected. Status: implemented
- TAG-053 MUST: the Genres field suggests values from `GET /genres` (API-050) while typing: the user's own genres first, then common ones (built-in names that would be rewritten on save, an alias or retag source such as `edm`, `euro pop`, `indie`, or a dropped name, are left out, so a suggestion is always stored as offered); a suggestion is added as a `genre:<value>` tag, free text stays allowed. Status: implemented (server, WEB-030, IOS-067)
- TAG-054 MUST: feat-aware artist matching: the saved artist keeps its `feat.` credit; `titles.lookup_credits` splits it into the primary artist and the featured names (split on `,`, `&`, ` and `, ` x `). The query text stays the primary artist, but among the MusicBrainz recordings credited to the primary artist the lookup prefers the first one whose credit also has every featured name (case and accent insensitive; else the first one, as without feat), and takes the primary artist's id from that credit for country, genres and the Wikipedia/Wikidata artist links, so two same-named artists are told apart ("Kato feat. Jon" gives the Danish Kato, `country:dk`). It extends the fallback chain of TAG-047: song page genres, then the artist page's infobox genres, then Wikidata; in the guessed path (`/preview`, and the guess of `POST /metadata`) a song page whose infobox `artist` does not match the primary artist is never attached (no genres, album, year or link from it); links the user gave are used as given. Status: implemented
- TAG-055 MUST: suggested `genre:` tags are filtered and canonicalised before the caps (TAG-047 order and caps unchanged, so dropped tags use no slot) in `metadata.finalize_tags` (`server/app/genre_filter.py`), the one rule shared by `POST /metadata`, `POST /preview` and `POST /lookup/wikipedia`: values that are not genres are dropped (nationalities and countries, roles such as dj/producer/band, MusicBrainz meta tags such as seen live/favorites/female vocalists, decade-like tags and plain years, language names, city names, and the words music/songs/single/remix/cover/live/official), matched lowercase, accent-folded, ignoring spaces and hyphens; a trailing " music" is stripped ("house music" gives "house") unless the built-in genre list has that exact name ("bass music"); a spelling matching a built-in genre uses the built-in spelling ("hip-hop" gives "hip hop"); duplicates then collapse, first one kept. Genres the user enters (create, PATCH) are never filtered, but they are canonicalised (TAG-071). Status: implemented
- TAG-071 MUST: `genre:` values are merged permanently. `library.clean_tag` applies `genre_filter.canonical` to every `genre:` tag on write and on load: a trailing " music" is stripped unless the built-in list has that name ("house music" gives "house", so the Library filter has one entry), built-in spelling wins, and the plain dict `genre_filter.ALIASES` maps other loose spellings (`electronic dance music` to `electronic dance`, `punk rock` to `punk`; `dnb`, `drum & bass` and `drum n bass` to `drum and bass`; `edm` to `electronic dance`; `euro pop` to `europop`; `euro-disco` and `eurodisco` to `euro disco`; `eurohouse` to `euro house`; `electronic pop` to `electropop`; `festival progressive house` to `progressive house`; `festival trap` to `trap`; `red disco` to `disco`; extend it there; an alias is only a spelling or synonym of the SAME genre, a vague tag that stands for another genre is a retag, TAG-075; junk is dropped, TAG-073; leading demonyms become country tags, TAG-074); duplicates collapse per song (TAG-056 rule). The Genres map resolves the bare form to the Wikidata item of "<value> music" when the bare label has none (GEN-031), so nodes keep their edges. `server/app/migrate_tags.py` runs once per server start (idempotent): for every `users/*/library.json` holding a non-canonical genre tag it first copies the file to `<data repo>/backups-genre-merge/<uid>/library.json` (outside the git-added `audioplayer/` tree; kept if present) and rewrites the library under the user lock and a git transaction; canonical files are not touched. Status: implemented
- TAG-073 MUST: junk `genre:` tags are dropped for good: `genre_filter.DROP` (plain set, compared by `key`, on the whole value and on the value with a trailing " music" stripped: mkj, deb, stadiumx, sam smith, dancin, relaxed, love song, progressive music, underground music, dystopian music, comedy music, comedy, novelty music, novelty song, novelty, popular, underground, cyberpunk, aaron smith, joris, skrux, medley, music video, party, popcorn, functional music, event music, party music, west coast swing (TAG-085), and `genre_filter.REMOVED_GENRES`, the names of the four removed families Stage & Screen, Children's, Brass & Military and Non-Music with their synonyms and genres, including soundtrack, trailer, score, musical, theme (Alex, 2026-10-18; [genre-levels.md](../tech/genre-levels.md#removed-families-alex-2026-10-18)), `lo-fi` (owner, 2026-10-20: a production aesthetic, not a form; [genre-levels.md](../tech/genre-levels.md#lo-fi-removed-owner-2026-10-20)), and `epic` (owner, 2026-10-20: a descriptor of mood, not a genre; [genre-levels.md](../tech/genre-levels.md#epic-removed-owner-2026-10-20)); so `popular music` goes too; `club` and `club music` are no longer dropped but fold into `electronic` (AP1, 2026-10-16; songs that lost `genre:club` in the earlier deployed clean-up are not restored); plain `dystopian` is NOT dropped, it is retagged to darksynth, TAG-075; `dystopian music` stays dropped) makes `is_genre` false (suggestions never offer them) and `library.clean_tag` return "" (removed from songs on write, load and by `migrate_tags`); a song left without a genre tag is fine. More loose spellings merged through `ALIASES` (euroda to eurodance, deep progressive and melodic progressive house to progressive house, mor to middle of the road, retro-synth to synthwave, hip-hop & rap to hip hop, rock and indie to indie rock, pop and chart to pop, russian electro pop and russian electropop to electropop). Real genres (dance pop, pop punk, sunshine house, dreamsynth, synth-rock, and the subgenres of TAG-076) are untouched; west coast swing is dropped (a dance style, not a genre; TAG-085). The Non-Music outline group disappears on its own when no genre is left in it (groups come from the roots present). Status: implemented
- TAG-075 MUST: vague tags are retagged to the named genre they stand for: the plain dict `genre_filter.RETAGS` (old to new, matched by `key` on the WHOLE tag only, after the " music" strip: `appalachian folk` and `bard` to `folk`, `romantic` to `classical`, `psychedelic` to `psychedelic rock`, `nederpop` to `pop`, `orchestral` to `modern classical`, `alternative` to `alternative rock`, `indie` to `indie rock`, `progressive` to `progressive rock`, `dystopian` to `darksynth`, the symbol tag `⚈⚈` to `glitch hop` (its key stays non-empty); `indie rock`, `indie pop`, `progressive house` and other longer names are never touched) is applied last by `genre_filter.canonical`, so it reaches every write, load, suggestion (`filter_tags`), the Genres map (`user_genres`) and the startup migration (`migrate_tags`, same backup, idempotent; a song that already carries the target ends with one tag). One per-song rule: `progressive` becomes `progressive house` when another `genre:` value of the same song is electronic (`genre_filter.is_electronic`: the Electronic family in `server/data/genre_families.json`, bare or "<value> music", or the plain set `ELECTRONIC_CONTEXT`: electronic, dance, electronic dance, edm, club, electronica), else `progressive rock` (`club` stays in `ELECTRONIC_CONTEXT` although the tag itself is dropped: the rule reads the song's raw tags, so a song tagged progressive and club still gets progressive house); `library.clean_tags` passes the song's genre values to `clean_tag` for this. `dystopian` is a retag, not a drop, because "dystopian synthwave" is not an established genre (Wikipedia, Wikidata, RateYourMusic, Discogs, MusicBrainz and Every Noise all lack it); the accepted name for its dark, dystopia-flavoured side is darksynth (Wikidata Q60973191, subclass of synthwave). A retag target is always canonical itself (`canonical(target) == target`, tested). Status: implemented
- TAG-076 MUST (amended by TAG-077 to TAG-084, ADR-0023: the kept real subgenres are entries of `server/data/genre_extras.json` or Discogs genres; `genre_families.json` is retired): the stored canonical form of a genre is the bare label that resolves in Wikidata (the live Genres map node with a `qid`, " music" stripped as in GEN-031). Only what is not a genre is aliased (TAG-071), retagged (TAG-075) or dropped (TAG-073). Status: implemented
- TAG-074 MUST: a leading demonym or language word is a country, not a genre: `genre_filter.split_prefix` (table `PREFIXES`: word to country code and language code or None, e.g. russian to ru/ru, british to gb) turns `genre:russian pop` into `genre:pop` plus `country:ru` and `lang:ru`, `british blues` into `blues` plus `country:gb`, `dutch house` into `house` plus `country:nl`. `genre_filter.canonical` strips the word; `library.clean_tags` adds the country when the song has under 2 `country:` tags and lacks it, and the language only when the song has no `lang:` tag (existing tags always win). Status: implemented
