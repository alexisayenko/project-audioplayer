# iOS app

Code: `ios/Sources/` (SwiftUI, iOS 17, iPhone only). Same API as the web UI;
screen flow matches it (ADR-0007). Status values reflect code read on
2026-10-13; "implemented" means built into the app, not yet proven on a
device unless a line says so.

## Shell and navigation

- IOS-001 MUST: the app has three tabs, Library, Playback, Settings (web `#/library`, `#/playback`, `#/settings`); Add is not a tab: a + button in the Library header opens the AddSheet (ADR-0009). The queue length is shown on Playback ("Queue (N)"), not as a tab badge. Status: implemented
- IOS-002 MUST: a mini-player bar sits above the tab bar on the other tabs and opens the Playback tab on tap; it is hidden on Playback. Status: implemented
- IOS-003 MUST: the app runs on iPhone only, portrait only. Status: implemented

## Settings and auth

- IOS-010 MUST: Settings has the artboard's cards in order, Account (Sign in with Apple and Google; signed in: the email, the provider and Sign out; when the server answers 403 (not the owner, sign-up closed) the line under the email reads "Not allowed on this server" and the dot is red; the dot is green only after a successful authenticated request, grey before one), Downloads (Audio quality as a read-only "High · 192 kbps", the server's fixed bitrate, with the design's chevron although there is no choice yet; "Download new songs automatically" switch, default on; "Use mobile data" switch, default off), Storage (size of `Documents/audio`, song count, a bar against the phone's capacity, "Remove all downloads" after a confirmation, phone copies only), then the version line from the bundle ("· TestFlight" on TestFlight builds, "· Debug" in debug builds). There is no server or token UI: the server URL (default `https://play.isayenko.net`) and a previously saved token stay in UserDefaults, and the `-serverURL` / `-token` launch arguments still work for development. When the saved server differs from the default or a legacy token is stored, the Downloads card ends with a quiet row "Custom server: <host> · Reset" ("legacy token" when only a token is left); Reset asks for confirmation, then restores the default URL and clears the token. The row is hidden for a default connection. Status: implemented (not verified on a device)
- IOS-017 MUST: "Use mobile data" (UserDefaults `useMobileData`) governs file downloads only: with it off, `GET /files/{id}` uses a session with cellular, expensive and constrained access disabled and the Library toast says "Mobile data is off for downloads. Turn on Use mobile data in Settings." API calls are never blocked. "Download new songs automatically" (`downloadNewAutomatically`) decides whether "Add to library" also copies the song to the phone and whether songs that appear in a later catalog sync are copied on their own (IOS-035); off saves it on the server only, with the toast "Saved. Not downloaded to this iPhone", and the song is listed in Library as soon as the server has finished it. Status: implemented
- IOS-011 MUST: Settings has no API token or server token field; sign-in is Google or Apple only. A stale token saved by an older build is kept in the Keychain, never appears in a stored URL or in the library file, and Settings shows a "Custom server: legacy token" row with Reset only while one is saved. The owner's `X-API-Token` stays a server-side credential for scripts. Status: implemented
- IOS-012 MUST: Settings offers Sign in with Apple and Sign in with Google (any verified account, ADR-0012; ~~owner only, ADR-0006~~); the ID token goes as `Authorization: Bearer`, the Google refresh token is kept in the Keychain and refreshes silently. Status: implemented (not yet tested live on a device)
- IOS-013 MUST: an expired Apple token cannot refresh silently; Settings shows "Expired, sign in again" (a launch-argument API token is the only fallback). Status: implemented
- IOS-016 MUST: the app's Google client id is a separate OAuth client from the web one; the server accepts both (API-007). Status: implemented
- IOS-014 MUST: signing in is never required to play downloaded songs. Status: implemented
- IOS-015 MUST: client IDs come from the git-ignored `ios/Config/Secrets.xcconfig`; none is in the repo. Status: implemented

## Add

- IOS-020 MUST: Add is a sheet (AddSheet) over Library, opened from the + in the Library header. It pastes a YouTube or SoundCloud link, cleans it to the canonical form, and calls `POST /preview`. After Fetch the edit form opens directly under the song card, with the link field, Fetch and the search link hidden (Cancel closes the sheet) and the two Add buttons pinned at the bottom. Closing the sheet by any route (Cancel, swipe down, save) clears the whole form and cancels running lookups; the next + opens the initial screen. Status: implemented
- IOS-061 MUST: Add accepts SoundCloud track links (ADD-060..066): the URL port in `TagLogic.swift` (`classifySoundcloud`, `cleanUrl`, `cleanPasted`) matches `urlclean.py`, `Preview.source` and `Track.source` (derived from the id) feed a source label in the preview line; server errors (`unsupported`, `preview_only`, `not_found`, `private`) arrive as `detail` text and are shown in the sheet unchanged, including "Preview only — SoundCloud Go+ track, can't be downloaded in full.". A source tag in Library rows and Playback is left to the design system. Status: implemented (URL port checked with a swiftc script; live SoundCloud add not tested on a device)
- IOS-062 MUST: `libraryMatch` (`TagLogic.swift`) finds the library song for a pasted link offline (YouTube by video id, SoundCloud by canonical URL) so the Add sheet shows "Already in your library" and disables Fetch. Status: implemented
- IOS-063 MUST: the Add form and the song sheet have an optional field "Remix & additional production" after Album, saved as `remixer` (POST/PATCH /songs; empty is sent as null; the song sheet shows a "Remix: …" line under the cover facts only when set; list rows are unchanged). In the Add flow it is prefilled from `preview.remixer` when the preview loads (the server already cut that bracket out of the title), is editable and clearable, and is cleared with the flow state and on a new Fetch. There is no "Original track" field and no remix hint row; an `original` key in an old local library.json is ignored. Status: implemented
- IOS-021 MUST: the preview is editable (title, artist, album, year, BPM) with the tag editor and suggested tags, including `decade:` tags (ADD, TAG specs); The Wikipedia links are kept in state, filled by the preview and "Get metadata", saved with the song and sent to `POST /metadata` as `wiki_song`/`wiki_artist`, but the two link fields are not shown in the Add form for now (the Add form has no separate fill button). "Get metadata" (after Title and Artist) calls `POST /metadata` and fills only empty Album and Year and adds suggested `genre:`/`country:` tags within the caps (12 genres as a UI ceiling, the server already limits to 8 plus the song's own Wikipedia genres; 1 country); a differing `suggest` artist/title from the response shows a tappable "Wikipedia says: artist / title" hint under Artist (applied only on tap, never auto-filled; gone once the fields match or on a new fetch); it shows a spinner, then "Couldn't load metadata", "Already up to date" (only values already present came back) or "Nothing found" inline and never blocks Add. Beside the button a row of four service icons (YouTube, SoundCloud, Wikipedia, Spotify, vector shapes in `ServiceIcons.swift`, brand colours from `DS.Color.brand*`) shows the result of `services` in the response: grey and not tappable by default and for services that returned nothing; YouTube, SoundCloud and Wikipedia pulse together while the call runs (static dimmed with Reduce Motion); a service with `found: true` turns brand-coloured and opens its `url` when tapped (coloured but not tappable if `url` is null); a missing `services` field leaves all grey; Spotify stays grey always. Genres and Countries are chip fields over the `genre:` and `country:` tags (countries shown as names, saved as `country:<code>`); a comma or a slash in typed or pasted text splits it (`rock/pop, jazz` gives three chips) into separate chips (the text after the last separator stays as the unfinished remainder; the rest is committed on return, on focus loss and on tapping Add, so unfinished text is never lost); the generic tag editor hides them and `lang:` tags (existing `lang:` tags stay in the data). Status: implemented
- IOS-022 MUST: "Add to library" (primary, + glyph) calls `POST /songs`; with "Download new songs automatically" on it also hands the download to `ServerLink` (polls `GET /songs/{id}/status`, then fetches `GET /files/{id}`) so it outlives the sheet, and the song's Library row shows "Downloading NN%". "Add and download to iPhone" (text button under it) always downloads. "Download to iPhone" and "Play now" are offered for a song already saved. The old "Save and play when ready" is gone with the new artboard. Link errors show a one-line message with a red circle icon under a red-ringed field and a disabled "Add to library": Unsupported link / Private track / Track not found; "preview_only" shows the Preview only notice (the server sends no metadata with it, so the artboard's preview card is not shown). Return dismisses the keyboard on Fetch. Status: implemented (not yet tested live on a device)
- IOS-023 SHOULD: text search (`GET /search`) stays secondary: the link "Search YouTube by title" in the AddSheet pushes the search screen; tapping a result opens the same preview, and the row's download button uses the legacy `POST /download` (file only, no library record, no tags). The search field is a bottom bar on an opaque surface with a line ring and shadow, a clear X inside it (only with text) and no Cancel button; back is the "<" button at the top left. The search screen never fails silently: it searches after a 0.6 s pause in typing or on submit, shows a spinner meanwhile, "No results" for an empty list (the opening prompt shows only before the first search), and on failure an inline message that replaces the list: 401 "Not signed in. Sign in in Settings"; 403 from an account the server refuses (codes `forbidden`, `signup_closed`, `unverified_email`, `no_email`) "This account isn't allowed on this server. Sign out and use another account." without Retry; connection refused, offline or timeout "Can't reach the server" with Retry; other errors the server's `detail` or `error`, or "Server error N", with Retry. Status: implemented

## Library

- IOS-030 MUST (ADR-0010 supersedes ADR-0009's phone-only Library): Library lists the whole catalog, every song with or without audio, from the cached catalog (IOS-035); no Phone / Server switch. A row shows cover, title, artist with the quiet source mark ("· YouTube", "· SoundCloud", "· Spotify"), then the audio state, binary on the phone as in the design: on the iPhone (duration, tap plays), not on the iPhone (an outline "Download" button in `accent-ink`, "Downloading NN%" while the file arrives; a tap on the row downloads and then plays), or no audio anywhere ("No audio yet", row dimmed, not tappable; getting audio for it is task-0009). The server's own state is never shown. The server status LED stays in the AddSheet header and Settings. Status: implemented (verified in the simulator against a stub server; not on a device)
- IOS-031 MUST (supersedes the old "no Download all"): a "Downloaded N" toggle beside the sort control narrows the list to songs on the phone. There is no bulk "Download all" because the design shows none; the way to fetch many is "Download new songs automatically" (IOS-035). Status: implemented
- IOS-032 MUST: Library filters with four category chips in one row (Tags, Genres, Years, Countries; plain, `genre:`, `decade:`, `country:`; other keys fold into Tags; `lang:` tags are not shown or filterable), now over the whole catalog. A chip opens a bottom filter sheet with that category's values and counts, multi-select (any of within a category, all across categories), Clear, and a button "Show N songs"; a chip with a selection shows the selected count. Search and sort (recently added by the server's `added_at`, title, artist, year) as in LIB specs; the "Downloaded" toggle combines with all of them. Status: implemented
- IOS-033 MUST: a row's ⋯ menu offers Edit (opens the song sheet); for a song on the phone Play next, Add to queue and Remove from iPhone (frees the audio, keeps the catalog entry; hidden for a song the server no longer lists); for a song not on the phone Download; and Delete from library (after a confirmation: `DELETE /songs/{id}` on the server, then the phone entry and file; offline it fails with a toast and removes nothing). Status: implemented
- IOS-034 MUST: the song sheet (a content-height bottom sheet: Cancel, "Song", Save) shows the cover, duration · BPM · size · format and the added date, edits title, artist, album, year and BPM, Genres and Countries chip fields like the Add form (same separators and caps, unfinished text committed on Save; `lang:` tags stay in the data), tags (removable pills, without `genre:`/`country:`/`lang:` and a + that opens the tag editor) and links (Wikipedia and YouTube pills; "Edit links" reveals the Wikipedia fields, "Fill from Wikipedia" and "Detect BPM"). Save calls `PATCH /songs/{id}`. "Remove from iPhone" deletes the phone copy only, after a confirmation; the song stays in the catalog. "Change cover" from the design is not built (the server has no cover upload). Status: implemented (not yet tested live on a device)

## Playback and offline

- IOS-040 MUST: playback uses local files only, with `AVPlayer`, background audio and lock-screen controls (`MPNowPlayingInfoCenter`, `MPRemoteCommandCenter`). Status: implemented
- IOS-041 MUST: Playback leads with the cover (title and artist on it; no deck, platter, tonearm or LED), a seek bar, a transport tray (shuffle, previous, play/pause, next, repeat off/all/one), position and an Up next card (no volume row: the device buttons set the volume; no status line); the full queue (jump, remove, clear) and add-by-tag open from the Queue link and the ⋯ menu, which also holds Song details (opens the song sheet), back and forward 5 seconds, and Clear queue. Status: implemented (not verified on a device)
- IOS-035 MUST: catalog sync (CAT-005, CAT-006): on launch, when the app becomes active and on pull-to-refresh the app calls `GET /catalog` with `If-None-Match` (the ETag is stored in `library.json`; 304 changes nothing) and merges it into `Documents/library.json`, which holds the whole catalog plus the ETag (the old array format is still read). Phone state is never stored: a song is on the phone when `Documents/audio/<id>.m4a` exists. A song missing from `ids` is dropped only when it has no phone audio; otherwise it stays as local-only (plays, cannot be re-downloaded, no "Remove from iPhone"). Errors are quiet (the server LED goes off, the cached catalog stays); signed out, Library says "Sign in in Settings to load your library."; a 403 (`ServerLink.forbidden`, cleared by the next successful sync or check, or Sign out) makes Library, the Add sheet, search and downloads say "This account isn't allowed on this server. Sign out and use another account.", and never touches the cached catalog or downloaded songs The first sync only sets the baseline; songs that appear in later syncs and have server audio download by themselves when "Download new songs automatically" is on (on Wi-Fi, or on mobile data when "Use mobile data" is on), else they are only listed. Status: implemented (verified against a stub server)
- IOS-042 MUST: downloaded songs live in `Documents/audio/` and `Documents/library.json` (the catalog, IOS-035); cover tokens are never persisted, the auth header is added at request time and stored values are scrubbed on load. Status: implemented
- IOS-043 SHOULD: server covers show offline. Status: planned (covers are fetched on demand and held only in a memory cache, so they are blank offline after a relaunch)
