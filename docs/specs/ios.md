# iOS app

Code: `ios/Sources/` (SwiftUI, iOS 17, iPhone only). Same API as the web UI;
screen flow matches it (ADR-0007). Status values reflect code read on
2026-10-13; "implemented" means built into the app, not yet proven on a
device unless a line says so.

## Shell and navigation

- IOS-001 MUST: the app has three tabs, Library, Playback, Settings (web `#/library`, `#/playback`, `#/settings`); Add is not a tab: a + button in the Library header opens the AddSheet (ADR-0009). The queue length is shown on Playback ("Queue (N)"), not as a tab badge. Status: implemented
- IOS-002 MUST: a mini-player bar sits above the tab bar on the other tabs and opens the Playback tab on tap; it is hidden on Playback. Status: implemented
- IOS-003 MUST: the app runs on iPhone only, portrait only. Status: implemented

## Settings and auth

- IOS-010 MUST: Settings has the artboard's cards in order, Account (Sign in with Apple and Google; signed in: the email, the provider and Sign out; when the server answers 403 (not the owner, sign-up closed) the line under the email reads "Not allowed on this server" and the dot is red; the dot is green only after a successful authenticated request, grey before one), Downloads (Audio quality as a read-only "High · 192 kbps", the server's fixed bitrate, with the design's chevron although there is no choice yet; "Download new songs automatically" switch, default on; "Use mobile data" switch, default off), Storage (size of `Documents/audio`, song count, a bar against the phone's capacity, "Remove all downloads" after a confirmation, phone copies only), then the version line from the bundle ("· TestFlight" on TestFlight builds, "· Debug" in debug builds). There is no server or token UI: the server URL (default `https://electrophone.cc`) and a previously saved token stay in UserDefaults, and the `-serverURL` / `-token` launch arguments still work for development. When the saved server differs from the default or a legacy token is stored, the Downloads card ends with a quiet row "Custom server: <host> · Reset" ("legacy token" when only a token is left); Reset asks for confirmation, then restores the default URL and clears the token. The row is hidden for a default connection. Status: implemented (not verified on a device)
- IOS-017 MUST: "Use mobile data" (UserDefaults `useMobileData`) governs file downloads only: with it off, `GET /files/{id}` uses a session with cellular, expensive and constrained access disabled and the Library toast says "Mobile data is off for downloads. Turn on Use mobile data in Settings." API calls are never blocked. "Download new songs automatically" (`downloadNewAutomatically`) decides whether "Add to library" also copies the song to the phone and whether songs that appear in a later catalog sync are copied on their own (IOS-035); off saves it on the server only, with the toast "Saved. Not downloaded to this iPhone", and the song is listed in Library as soon as the server has finished it. Status: implemented
- IOS-011 MUST: Settings has no API token or server token field; sign-in is Google or Apple only. A stale token saved by an older build stays in UserDefaults (`token`, never in a stored URL or in the library file; the API client still sends it as `X-API-Token` when no sign-in exists) and Settings shows a "Custom server: legacy token" row with Reset only while one is saved. The owner's `X-API-Token` stays a server-side credential for scripts. Status: implemented
- IOS-012 MUST: Settings offers Sign in with Apple and Sign in with Google (any verified account, ADR-0012; ~~owner only, ADR-0006~~); the ID token goes as `Authorization: Bearer`, the Google refresh token is kept in the Keychain and refreshes silently. Status: implemented (not yet tested live on a device)
- IOS-013 MUST: an expired Apple token cannot refresh silently; Settings shows "Expired, sign in again" (a launch-argument API token is the only fallback). Status: implemented
- IOS-016 MUST: the app's Google client id is a separate OAuth client from the web one; the server accepts both (API-007). Status: implemented
- IOS-014 MUST: signing in is never required to play downloaded songs. Status: implemented
- IOS-015 MUST: client IDs come from the git-ignored `ios/Config/Secrets.xcconfig`; none is in the repo. Status: implemented

## Add

- IOS-020 MUST: Add is a sheet (AddSheet) over Library, opened from the + in the Library header. It pastes a YouTube or SoundCloud link, cleans it to the canonical form, and calls `POST /preview`. After Fetch the edit form opens directly under the song card, with the link field, Fetch and the search link hidden (Cancel closes the sheet) and the two Add buttons pinned at the bottom. Closing the sheet by any route (Cancel, swipe down, save) clears the whole form and cancels running lookups; the next + opens the initial screen. A preview the server reports as already saved (`in_library`) shows "This song is already in your library" with Play now or Download to iPhone and disables both Add buttons. Status: implemented
- IOS-061 MUST: Add accepts SoundCloud track links (ADD-060..066): the URL port in `TagLogic.swift` (`classifySoundcloud`, `cleanUrl`, `cleanPasted`) matches `urlclean.py`, `Preview.source` and `Track.source` (derived from the id) feed a source label in the preview line; server errors (`unsupported`, `preview_only`, `not_found`, `private`) arrive as `detail` text and are shown in the sheet unchanged, while `preview_only` shows the app's own "Preview only" notice above the form. A source tag in Library rows and Playback is left to the design system. Status: implemented (URL port checked with a swiftc script; live SoundCloud add not tested on a device)
- IOS-062 MUST: `libraryMatch` (`TagLogic.swift`) finds the library song for a pasted link offline (YouTube by video id, SoundCloud by canonical URL; the link field also accepts a bare 11-character YouTube video id, cleaned to the watch URL) so the Add sheet shows "Already in your library" and disables Fetch. Its checks (`linkInputSelfCheck()`, `#if DEBUG`) are not called anywhere, and there is no XCTest target or automated iOS test run. Status: implemented
- IOS-063 MUST: the Add form and the song sheet have an optional field "Remix & additional production" directly under Artist, saved as `remixer` (POST/PATCH /songs; empty is sent as null; the song sheet shows a "Remix: …" line under the cover facts only when set; list rows are unchanged). In the Add flow it is prefilled from `preview.remixer` when the preview loads (the server already cut that bracket out of the title), is editable and clearable, and is cleared with the flow state and on a new Fetch. There is no "Original track" field and no remix hint row; an `original` key in an old local library.json is ignored. Status: implemented
- IOS-064 (superseded for Title, Artist and Remix by IOS-065): only the Title, Artist and Remix & additional production fields of the Add form and the song sheet (not Album, Year, BPM, Wikipedia links, chip, tag or link/Fetch fields) show a clear button (`xmark.circle.fill`, `inkFaint`, 44pt hit area, label "Clear <field>") at its trailing edge whenever the field has text (focused or not); a tap empties the field and keeps focus; text never runs under it. One shared `DSTextField` in `Components.swift`. Status: superseded for those three fields (no other field has a clear button; `DSTextField.clearable` was removed)
- IOS-065 MUST: in the Add form and the song sheet, Title, Artist and Remix & additional production are `TokenField`s (`TokenField.swift`) over the one plain string binding, following ADD-071, ADD-072 and WEB-028: wrapped pills [pencil] text [xmark] in the DS tint, then a trailing entry. The pencil is a menu ("Edit text", "Move to <other two fields>", "Remove"); Edit text turns the pill into a prefilled text field (return or losing focus commits via `replaceToken`); xmark removes via `removeToken`; typing a separator commits pills (`commitTyped`), a trailing separator is dropped on blur; unfinished entry text counts in the bound value; programmatic sets (Fetch, preview remixer, Get metadata, flow reset) re-render the pills. Labels "Edit <text>", "Remove <text>", "Move to Artist". The tokenizer is `Tokens.swift`, a port of `web/js/tokens.js` with the `tokens.test.mjs` cases in `tokensSelfCheck()` (`#if DEBUG`, not called anywhere; no XCTest target or automated iOS test run). Status: implemented (builds; not exercised on a device)
- IOS-066 MUST: pills in the Add form and the song sheet move by drag and drop (ADD-074, WEB-029): each pill in `TokenField.swift` is `.draggable` with a `TokenDrag` payload (field kind + token index, private type `com.alexisayenko.audioplayer.token-pill` exported in `project.yml`, so only this app's fields accept it) and a lifted pill preview; dropping on a pill inserts before it (accent insertion line on its leading edge while targeted), dropping on the field's free area or entry appends (accent border while targeted); works across Title, Artist and Remix and within one field; the same position is a no-op. The logic is `Tokens.insertToken` and `Tokens.moveTokenTo` (ports of `tokens.js`, cases in `tokensSelfCheck()`); the destination field writes the source field's binding, as "Move to ..." does, and that pencil menu stays the VoiceOver alternative. The trailing entry shares the line with the last pill when at least 80pt remain (`FlowLayout` `flowFill`). Status: implemented (builds; not exercised on a device) Decision 2026-10-13: the standard system drag (lift after the system hold time) is kept on purpose; a custom shorter-hold gesture was considered and rejected, and the pencil menu "Move to ..." is the fast and VoiceOver path.
- IOS-067 MUST: the Genres field in the Add form and the song sheet shows up to 6 genre suggestions as tappable chips under the field as soon as one character follows the last separator (WEB-030): prefix matches first, then word-start, then anywhere, genres already chosen excluded, case and accent ignored (`suggestGenres`, `GenreSuggest.swift`); a tap adds the genre and keeps focus. The list comes from `GET /genres`, fetched once per session and again when the library size changes, and falls back to the genres of the loaded library songs when the call fails or is empty. Status: implemented
- IOS-068 MUST: the "Wikipedia: song" and "Wikipedia: band" fields in the song sheet show the article name instead of the `https://en.wikipedia.org/wiki/` prefix (`WikiLinkField`, `wikiDisplay` and `wikiNormalize` in `WikiLink.swift`, cases in `wikiLinkSelfCheck()`, `#if DEBUG`, not called anywhere; no XCTest target or automated iOS test run): the stored value stays the full URL, a typed title or pasted link is normalised on return or focus loss, other links (wikidata, non-English) show unchanged. Status: implemented (builds; not exercised on a device)
- IOS-021 MUST: the preview is editable (title, artist, album, year; BPM is not editable: a muted line says it is detected after saving, IOS-069) with the tag editor and suggested tags, including `decade:` tags (ADD, TAG specs); The two Wikipedia link fields ("Wikipedia: song", "Wikipedia: band") are visible in the Add form, filled by the preview and "Get metadata", saved with the song and sent to `POST /metadata` as `wiki_song`/`wiki_artist` (the form has no separate fill button). "Get metadata" (after Title and Artist) calls `POST /metadata` and fills only empty Album and Year and adds suggested `genre:`/`country:` tags within the caps (12 genres as a UI ceiling, the server already limits to 8 plus the song's own Wikipedia genres; 1 country); a differing `suggest` artist/title from the response shows a tappable "Wikipedia says: artist / title" hint under Artist (applied only on tap, never auto-filled; gone once the fields match or on a new fetch); it shows a spinner, then "Couldn't load metadata", "Already up to date" (only values already present came back) or "Nothing found" inline and never blocks Add. Beside the button a row of six service icons (YouTube, SoundCloud, Wikipedia, MusicBrainz, Spotify, Discogs, vector shapes in `ServiceIcons.swift`, brand colours from `DS.Color.brand*`) shows the result of `services` in the response: grey and not tappable by default and for services that returned nothing; YouTube, SoundCloud and Wikipedia pulse together while the call runs (static dimmed with Reduce Motion); a service with `found: true` turns brand-coloured and opens its `url` when tapped (coloured but not tappable if `url` is null); a missing `services` field leaves all grey; MusicBrainz lights up when matched (`DS.Color.brandMusicbrainz`, as in IOS-034); only Spotify and Discogs stay grey always (no lookup yet, no brand colour). Genres and Countries are chip fields over the `genre:` and `country:` tags (countries shown as names, saved as `country:<code>`); a comma or a slash in typed or pasted text splits it (`rock/pop, jazz` gives three chips) into separate chips (the text after the last separator stays as the unfinished remainder; the rest is committed on return, on focus loss and on tapping Add, so unfinished text is never lost); the generic tag editor hides them and `lang:` tags (existing `lang:` tags stay in the data). Status: implemented
- IOS-022 MUST: "Add to library" (primary, + glyph) calls `POST /songs`; with "Download new songs automatically" on it also hands the download to `ServerLink` (polls `GET /songs/{id}/status`, then fetches `GET /files/{id}`) so it outlives the sheet, and the song's Library row shows "Downloading NN%". "Add and download to iPhone" (text button under it) always downloads. "Download to iPhone" and "Play now" are offered for a song already saved. The old "Save and play when ready" is gone with the new artboard. Link errors show a one-line message with a red circle icon under a red-ringed field and a disabled "Add to library": Unsupported link / Private track / Track not found; "preview_only" shows the Preview only notice (the server sends no metadata with it, so the artboard's preview card is not shown). Return dismisses the keyboard on Fetch. Status: implemented (not yet tested live on a device)
- IOS-023 SHOULD: text search (`GET /search`) stays secondary: the link "Search YouTube by title" in the AddSheet pushes the search screen; tapping a result opens the same preview, and the row's download button uses the legacy `POST /download` (file only, no library record, no tags). The search field is a bottom bar on an opaque surface with a line ring and shadow, a clear X inside it (only with text) and no Cancel button; back is the "<" button at the top left. The search screen never fails silently: it searches after a 0.6 s pause in typing or on submit, shows a spinner meanwhile, "No results" for an empty list (the opening prompt shows only before the first search), and on failure an inline message that replaces the list: 401 "Not signed in. Sign in in Settings"; 403 from an account the server refuses (codes `forbidden`, `not_allowed`, `signup_closed`, `unverified_email`, `no_email`) "This account isn't allowed on this server. Sign out and use another account." without Retry; connection refused, offline or timeout "Can't reach the server" with Retry; other errors the server's `detail` or `error`, or "Server error N", with Retry. Status: implemented

## Library

- IOS-030 MUST (ADR-0010 supersedes ADR-0009's phone-only Library): Library lists the whole catalog, every song with or without audio, from the cached catalog (IOS-035); no Phone / Server switch. A row shows cover, title, artist with the quiet source mark ("· YouTube", "· SoundCloud", "· Spotify"), then the audio state, binary on the phone as in the design: on the iPhone (duration, tap plays), not on the iPhone (an outline "Download" button in `accent-ink`, "Downloading NN%" while the file arrives; a tap on the row downloads and then plays), or no audio anywhere ("No audio yet", row dimmed, a tap only shows that toast; the ⋯ menu offers Get audio, IOS-033, and while the server fetches and the copy follows the row is not dimmed and shows "Downloading NN%"). The server's own state is never shown. The server status LED stays in Settings (Account) and shows in the Add sheet header only while the server is not known to be reachable. Status: implemented (verified in the simulator against a stub server; not on a device)
- IOS-031 MUST (supersedes the old "no Download all"): a "Downloaded N" toggle beside the sort control narrows the list to songs on the phone. There is no bulk "Download all" because the design shows none; the way to fetch many is "Download new songs automatically" (IOS-035). Status: implemented
- IOS-032 MUST: Library filters with four category chips in one row (Tags, Genres, Years, Countries; plain, `genre:`, `decade:`, `country:`; other keys fold into Tags; `lang:` tags are not shown or filterable), now over the whole catalog. A chip opens a bottom filter sheet with that category's values and counts, multi-select (any of within a category, all across categories), Clear, and a button "Show N songs"; a chip with a selection shows the selected count. Search and sort (recently added by the server's `added_at`, title, artist, year) as in LIB specs; the "Downloaded" toggle combines with all of them. Status: implemented
- IOS-033 MUST: a row's ⋯ menu offers Edit (opens the song sheet); for a song on the phone Play next, Add to queue and Remove from iPhone (frees the audio, keeps the catalog entry; hidden for a song the server no longer lists); for a song with audio on the server but not on the phone Download; for a song with no audio anywhere Get audio (`POST /songs/{id}/audio`, API-060: the server fetches it from the song's YouTube or SoundCloud link, the row shows "Downloading NN%" for the fetch (first 80%) and the copy to the phone, the same Use mobile data rule and error toasts as Download; a failed fetch shows the server's error toast); and Delete from library (after a confirmation: `DELETE /songs/{id}` on the server, then the phone entry and file; offline it fails with a toast and removes nothing). Status: implemented
- IOS-070 MUST: the Add form and the song sheet are one control, `SongFormView` (`SongFormView.swift`) over one `SongFormState` (`SongFormState.swift`; `AddFlow` extends it): Title, Artist, Remix & additional production, the "Wikipedia says" hint, Get metadata (button left, service icons right) with its note, Album and Year side by side, a BPM row, Genres, Countries, Tags and the two Wikipedia link fields side by side (stacked on the narrowest widths), in that order, in both. Only the BPM row (Add: muted "BPM is detected after saving"; song sheet: read-only label plus "Detect BPM") and Get metadata's source URL (Add: the preview's; song sheet: the song's) differ. Get metadata fills only empty fields in both and is new in the song sheet. Status: implemented (builds; not exercised on a device)
- IOS-069 MUST: BPM is never typed on iOS. The Add form shows only the muted line "BPM is detected after saving" and sends no `bpm`; the song sheet shows a read-only "BPM" row ("128 BPM" rounded, or "Not detected yet") that updates after "Detect BPM"; `PATCH /songs/{id}` never carries `bpm`. Status: implemented
- IOS-034 MUST: the song sheet (a content-height bottom sheet: Cancel, "Song", Save) shows the cover, duration · BPM · size · format and the added date, shows the source-link icons (YouTube, SoundCloud, Spotify, Wikipedia, MusicBrainz, Discogs; Spotify and Discogs inert unless a link exists; MusicBrainz is lit and opens the matched recording after "Get metadata" in the song sheet, in the `brand-musicbrainz` colour token) and edits the fields through the same shared form as Add (IOS-070), with a read-only BPM row (IOS-069) and "Detect BPM"; unfinished Genres, Countries and tag text is committed on Save; `lang:` tags stay in the data. The old "Fill from Wikipedia" button is removed (`POST /lookup/wikipedia` stays on the server). Save calls `PATCH /songs/{id}`. "Remove from iPhone" deletes the phone copy only, after a confirmation; the song stays in the catalog. "Change cover" from the design is not built in the app; the server and the web UI can change a cover (API-097, LIB-133), the app only shows it (the cover URL is unchanged; it may add `?v=<cover_v>` later). Status: implemented (not yet tested live on a device)

## Playback and offline

- IOS-040 MUST: playback uses local files only, with `AVPlayer`, background audio and lock-screen controls (`MPNowPlayingInfoCenter`, `MPRemoteCommandCenter`). Status: implemented
- IOS-041 MUST: Playback leads with the cover (title and artist on it; no deck, platter, tonearm or LED), a seek bar, a transport tray (shuffle, previous, play/pause, next, repeat off/all/one), position and an Up next card (no volume row: the device buttons set the volume; no status line); the full queue (jump, remove, clear) and add-by-tag open from the Queue link and the ⋯ menu, which also holds Song details (opens the song sheet), Share link (SHARE-019: outbound link sheet; opening links in the app is not built), back and forward 5 seconds, and Clear queue. Status: implemented (not verified on a device)
- IOS-035 MUST: catalog sync (CAT-005, CAT-006): on launch, when the app becomes active and on pull-to-refresh the app calls `GET /catalog` with `If-None-Match` (the ETag is stored in `library.json`; 304 changes nothing) and merges it into `Documents/library.json`, which holds the whole catalog plus the ETag (the old array format is still read). Phone state is never stored: a song is on the phone when `Documents/audio/<id>.m4a` exists. A song missing from `ids` is dropped only when it has no phone audio; otherwise it stays as local-only (plays, cannot be re-downloaded, no "Remove from iPhone"). Errors are quiet (the server LED goes off, the cached catalog stays); signed out, Library says "Sign in in Settings to load your library."; a 403 (`ServerLink.forbidden`, cleared by the next successful sync or check, or Sign out) makes Library, the Add sheet, search and downloads say "This account isn't allowed on this server. Sign out and use another account.", and never touches the cached catalog or downloaded songs The first sync only sets the baseline; songs that appear in later syncs and have server audio download by themselves when "Download new songs automatically" is on (on Wi-Fi, or on mobile data when "Use mobile data" is on), else they are only listed. Status: implemented (verified against a stub server)
- IOS-042 MUST: downloaded songs live in `Documents/audio/` and `Documents/library.json` (the catalog, IOS-035); cover tokens are never persisted, the auth header is added at request time and stored values are scrubbed on load. Status: implemented
- IOS-043 SHOULD: server covers show offline. Status: planned (covers are fetched on demand and held only in a memory cache, so they are blank offline after a relaunch)

## Look

- IOS-050 MUST: the UI follows the Electrophone design system (ADR-0009, [`../ui-ux/style-guide.md`](../ui-ux/style-guide.md)); all colours, sizes and radii come from `DS.*` in the generated `DesignTokens.swift`, components are in `Components.swift`, no hex or literal colour in other files; day and night follow the system appearance. Status: partially implemented. - IOS-051 MUST: the app icon is the record on the platter from the design system (cyan label with teal stripes on a vinyl disc, paper frame, copper rim), 1024 x 1024 without alpha. Status: implemented

## Per-user storage (ADR-0012)

The server is open to any signed-in user and every user has their own library. Implemented in the client: Google and Apple sign-in for any verified account (IOS-012), the 403 "not allowed" texts (IOS-010, IOS-023, IOS-035). Still open in [task-0016](../tasks/task-0016.md): the `queued` job status and its "Waiting..." display, so an iOS user may still see raw error texts for refused jobs.
- IOS-071 MAY: web-added links (`spotify_url`, edited `sources[]` via `youtube_url` / `soundcloud_url`, DATA-072, DATA-073) are not decoded or edited by the app yet: `Track` ignores `spotify_url` (the Spotify icon stays inert) and the song sheet shows the YouTube and SoundCloud links from `sources[]` as before; unknown fields are ignored on decode, so nothing breaks. Status: planned

## Credits and versions (ADR-0024)

- IOS-072 MUST: the app edits the legacy keys (`title`, `artist`, `remixer`, `year`, `album`) and keeps the structured ones read-only: `ServerSong` and `Track` carry `version {type, name, artists, releaseYear, originalArtists}`, `mainArtists`, `featuredArtists`, `withArtists`, `releaseYear`, `albums`, `genres`, `remix_year`, `rawTitle`, `wikipedia_album` and `discogs_url` as optionals, pinned in `ios_contract.json`. A catalog song that fails to decode is logged (`NSLog`) and skipped, not silently dropped. Status: implemented
- IOS-073 MUST: an Edit sends only the credit keys the person changed (`artist`, `album`, `remixer`, `year`), so the structure (version, `withArtists`, `remix_year`, albums) survives a save; changing the artist text replaces `mainArtists` with its pills and clears `featuredArtists` and `withArtists`; clearing the remixer of a remix removes the version. A version whose type is not remix or other (cover, live, ...) is shown read-only and its Remix text is not sent. Status: implemented
- IOS-074 MAY: the edit form shows the version in words and the featured artists read-only; the decade tag follows the displayed year (the version's `releaseYear` when it has one, else the release year, as the server computes it). Editing featured artists, version type and `withArtists` on the phone is a later iOS task. Status: partly implemented
