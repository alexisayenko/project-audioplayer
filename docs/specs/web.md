# Web UI sign-in

Code: `web/js/settings.js`, `web/js/api.js`, `web/js/app.js`; server side in
[api.md](api.md) (API-020..024) and ADR-0006. Status values reflect code read
on 2026-10-13 (the web is a catalog UI: it saves song entries, it never downloads); none has been tried live with Google or Apple yet.

- WEB-001 MUST: a signed-out visitor (no session) sees only Settings; Library, Playback and the player bar are hidden and routed away. Status: implemented
- WEB-002 MUST: Settings offers "Sign in with Google" (Google Identity Services, `accounts.google.com/gsi/client`) and "Sign in with Apple" (Apple JS SDK, popup mode), each shown only when its client id is returned by `GET /auth/config`; the SDK scripts load on Settings only. Status: implemented (not yet tested live)
- WEB-003 MUST: the ID token goes once to `POST /auth/session` and is never stored by the page or put in a URL; afterwards the HttpOnly session cookie authenticates, and audio and cover URLs carry no token. Status: implemented (not yet tested live)
- WEB-004 MUST: when signed in Settings shows the email and a Sign out button (`POST /auth/logout`, clears the in-memory library and stops playback). Status: implemented
- WEB-005 MUST: the web authenticates with the session cookie only. It has no API token field, no Server URL field, and never reads or sends `X-API-Token` or `?token=`; on load it deletes any `audioplayer.token` left in `localStorage`. The owner's API token remains for iOS and scripts. Status: implemented
- WEB-006 MUST: every web request sends `X-Requested-With: audioplayer` (CSRF, API-009). Status: implemented
- WEB-007 MUST: a 401 on a signed-in session returns the UI to the sign-in screen. Status: implemented
- WEB-008 MUST: no service worker or cache stores authenticated data (NFR-041, API-024). Status: implemented
- WEB-009 SHOULD: checks for the URL rules live in `web/js/api.test.mjs` (`node web/js/api.test.mjs`) and for quota messages in `web/js/limits.test.mjs`; the sign-in flow itself is manual. Status: implemented
- WEB-010 MUST: the web UI is styled only from `web/tokens.css` (generated, ADR-0009) and `web/style.css`; no hex or rgb literal appears in `web/style.css`, `web/js` or `index.html`. Day and night follow `prefers-color-scheme`. Status: implemented
- WEB-011 MUST: Library offers four category chips (Tags, Genres, Years, Countries; plain, `genre:`, `decade:`, `country:`; other keys fold into Tags; `lang:` tags are hidden) that open a filter sheet with multi-select values and counts, Clear, and a "Show N songs" button; values in one category are OR, categories are AND; Escape or the scrim closes without applying. Status: implemented
- WEB-012 MUST: navigation is three destinations (Library, Playback, Settings; same order as the iOS tab bar) as a 220px rail (>= 720px), 64px icon rail (480-719px) or floating tab bar (< 480px); the layout works from 360px up; every control has a visible focus ring, a 44px target (chips 36px) and an accessible name. Status: implemented
- WEB-013 SHOULD: every text/ground pair holds 4.5:1 in both themes (see the style guide for the deviations from the system's own pairs). Status: implemented (checked by computation, not by an automated test)
- WEB-014 MUST: the screens follow the "Electrophone Screens" web artboards (Web Library, Web Library Add dialog, Web Playback, Web Settings, version 1791839754-4134, 2026-10-13) and the Electrophone design system components (Sidebar, TableRow, PlayerBar, Chip, FilterSheet, AddSheet, Transport, Button). Status: implemented
- WEB-015 MUST: adding a song is an action on Library ("Add song" opens the Add dialog; `#/add` opens Library with the dialog); "Save to library" on the web saves a catalog entry only (`POST /songs` with `audio:false`, no download, no status polling), toast "Saved to library"; the web never starts a server download (2026-10-13). Status: implemented
- WEB-018 MUST: the Add dialog has one link input (placeholder "YouTube or SoundCloud link, or a YouTube video id") that accepts YouTube and SoundCloud links and a bare 11-character YouTube video id, which becomes the watch link (`web/js/url-clean.js` `classifySoundcloud`, `cleanUrl`, `cleanPasted`, with tests), shows a source chip in the preview card, and shows server errors (`unsupported`, `preview_only`, `not_found`, `private`) as text; `ApiError.code` carries the server's `error` value. Status: implemented (live SoundCloud add not tested)
- WEB-033 MUST: the Add dialog and the Edit song dialog share ONE form (`web/js/song-form.js`, `songForm({mode: 'add'|'edit', song, source, onChange})` returning `{node, values(), setValues(partial), focus(), reset(), destroy()}`), rendering in this order: Title, Artist, Remix & additional production (token pills), the "Wikipedia says" hint, the "Get metadata" button with service icons and status note, Album, Year, the BPM row, Genres, Countries, the generic Tags editor, and the two Wikipedia inputs (visible in both). The only differences are parameters: the source link(s) sent to `POST /metadata` (Add: the fetched preview's source URL; Edit: the song's `sources` and `source_url`), the BPM row (Add: muted line "BPM is detected after saving"; Edit: read-only label with Re-detect), and the preview data (Add only). Payload building is pure and tested (`web/js/song-payload.js`, `song-payload.test.mjs`). Add keeps only the link input and Fetch, the in-library line, the preview header, the sticky Save footer and dialog state clearing; Edit keeps only the song header, Save, Cancel and Delete. Status: implemented (not checked in a browser)
- WEB-022 MUST: the Add dialog mirrors the iOS Add flow (IOS-020, IOS-021): after Fetch the full form opens directly (link field hidden, sticky footer with Save), "Get metadata" (the shared form, WEB-033; also in the Edit dialog, where it sends the song's current title, artist, links and sources) calls `POST /metadata` (`web/js/metadata-apply.js`, tested) and fills only empty Album and Year and adds `genre:`/`country:` tags within the caps (12, 1), six service icons (YouTube, SoundCloud, Wikipedia, Spotify, MusicBrainz, Discogs; grey, pulsing while running, brand-coloured links when found; MusicBrainz lights up when the lookup matched a recording and links to it, in the Wikipedia colour token until a `brand-musicbrainz` token exists; Spotify and Discogs always grey and inert until a lookup exists), a "Wikipedia says: artist / title" hint applied only on click, separate Genres and Countries chip fields (the tag editor hides `genre:`, `country:`, `lang:`; in these two fields `,` and `/` both separate chips, typed or pasted, and pending text is split the same way on Save: `web/js/chip-split.js`, tested), and every way of closing the dialog (Cancel, Escape, backdrop, Save) clears its state, empties the dialog and aborts running requests, so the next open starts at the empty link field. Overlap: WEB-033 defines the form, WEB-022 the Add flow around it; neither restates the other's field rules. Status: implemented (not checked in a browser)
- WEB-024 MUST: the shared song form (WEB-033) has separate Genres and Countries chip fields in both the Add and Edit dialogs (`web/js/chip-field.js`, caps 12 and 1, `,` and `/` separators, pending text committed on Enter, blur and Save); its Tags editor hides `genre:`, `country:`, `lang:` and saves stored `lang:` tags back unchanged. Status: implemented (not checked in a browser)
- WEB-025 MUST: the Add dialog checks the link input against the already loaded library on every input, before Fetch, with no network call; a bare video id counts as its watch link (`web/js/library-match.js`: YouTube id, or the canonical SoundCloud URL against each song's id and sources); a match shows "Already in your library: title · artist" with a check icon and a "Show in library" action (closes the dialog, scrolls to and outlines the song) and disables Fetch until the link is edited. Test: `web/js/library-match.test.mjs`. Status: implemented (not checked in a browser)
- WEB-016 MUST: Playback shows the cover with title and artist on it (a vinyl square with an accent disc when there is no art), seek bar with elapsed and remaining time, the transport tray (shuffle, previous, play/pause, next, repeat), a volume slider (saved in `localStorage`) and the queue card (Add by tag, Clear, row menu: move up, move down, remove). Status: implemented
- WEB-017 MUST: every web asset is served under a versioned path so a deploy never waits for a browser or CDN cache. `GET /` and `GET /index.html` return `index.html` with `tokens.css`, `style.css`, `favicon.svg` and `js/app.js` rewritten to `_v/<version>/...` (`Cache-Control: no-cache`, `ETag` = version, 304 on `If-None-Match`); `GET /_v/<version>/<path>` serves the file with `public, max-age=31536000, immutable` when `<version>` is current and `no-cache` otherwise; relative imports inside `js/` therefore resolve under the same versioned path. `<version>` is a hash of the names, sizes and mtimes of all files in `web/` (`web_version()` in `server/app/main.py`). Direct paths such as `/style.css` stay `no-cache` (revalidate by ETag). Test: `test_web_assets_are_versioned_and_revalidated`. Status: implemented
- WEB-020 MUST: any Google or Apple account may sign in (ADR-0012); a refused sign-in shows the server's message (403 `signup_closed`: "Sign-up is closed on this server."), not "not the owner". Settings shows the signed-in email and the storage meter from `GET /me/usage` (`web/js/limits.js` `usageText`). Status: implemented
- WEB-021 MUST: coded errors (API-041..045) show as readable sentences through `web/js/limits.js` `friendly`; a 503 with a code is not reported as a missing API token. Status: implemented

- WEB-023 MUST: songs without server audio (`audio_state` `none`, `file` null) stay in the Library list (greyed title, no "Not on the server" label, WEB-031) with the service logo (YouTube / SoundCloud, brand colour, neutral external-link glyph for others; aria-label and tooltip "Open on YouTube" / "Open on SoundCloud") as a link in the Time column, next to the menu (the first `sources` entry with an http(s) URL, new tab, `rel=noopener`) instead of a play action; the title is plain text, the cover is dimmed and the row menu offers only "Edit song" (rows with audio offer Play now, Add to playlist, Edit song); they never enter the web queue, and Add all, tag adds, Next, Previous and shuffle skip them (`web/js/playable.js`, tested). Songs that already have server audio play as before; any song is deleted from its Edit dialog; the web has no embed and no control that starts a download. Status: implemented (not checked in a browser)
- WEB-026 MUST: the shared song form (WEB-033, Add and Edit) has an optional "Remix & additional production" (`remixer`) field directly under Artist (before Album and Year), sent in addSong metadata and PATCH; in the Add dialog it is prefilled from `preview.remixer` (the server already cut that bracket out of the title), editable and clearable, and reset on a new Fetch; Playback shows "Remix: ..." in the subtitle under the title when set. Status: implemented (not checked in a browser)
- WEB-027 (superseded by WEB-028): the plain-input clear (X) button on Title, Artist and Remix was removed; `clearable` no longer exists. Status: superseded
- WEB-028 MUST: in the Add and Edit dialogs Title, Artist and Remix & additional production are token-pill fields inside a field-styled container (`web/js/token-field.js`, rules in ADD-071, ADD-072): each pill is [pencil button "Edit <text>"] text [X button "Remove <text>"]; the pencil opens a small menu (Edit text, Move to the other two fields, Remove); Edit text turns the pill into an input (Enter or blur commits, Escape cancels); pills wrap and the field grows; the container exposes `.value` (get/set, includes unfinished typed text) and bubbles an `input` event after every change, so the library-match hint, preview header and save read it as before; the Edit dialog refuses to save an empty Title. Status: implemented (not checked in a browser)
- WEB-029 MUST: token pills (WEB-028) are draggable between Title, Artist and Remix & additional production and within one field, with the semantics of ADD-074 (`web/js/token-field.js`): HTML5 drag and drop with a custom MIME type carrying source field and token index; the dragged pill is dimmed; over a pill a thin accent line on its left edge shows the insertion point, over the free area or entry the field border turns accent (append); after a drop both fields fire a bubbling `input` event, a no-op drop fires none. On touch (no HTML5 DnD) a 250 ms long-press on a pill starts a pointer-events drag with a floating clone, the target is found with `elementFromPoint`, and the same drop function runs. Status: implemented (not checked in a browser)
- WEB-030 MUST: the Genres chip field (Add and Edit dialogs) suggests genres while typing: from the first character after the last separator it lists up to 6 buttons under the field (prefix matches first, then word-start, then anywhere, in server order, chosen genres excluded, case and accent insensitive, matching part bold; `web/js/genre-suggest.js`, tested); click or tap adds the chip (cap 12); ArrowUp/ArrowDown highlight (listbox, `aria-activedescendant`), Enter or Tab accepts the highlighted one (Enter with none highlighted commits the typed text), Escape or blur closes it. The list comes from `GET /genres` (`api.genres()`), fetched once and cached until the library changes, falling back to the genres of the loaded songs. Status: implemented (not checked in a browser)
- WEB-031 MUST: the Library list is a table with columns cover / Track / Genres / Time, with no row-number column (the Track cell shows the title with a smaller muted line "Artist · Year" below it, missing parts and the dot omitted, one ellipsised line at every width, `web/js/track-sub.js`, tested; the Add and Edit dialogs keep the field label "Title"; Genres from 900px, hidden below; below 720px the phone row keeps cover, Track, Time/logo and menu); Genres (a wider column directly after Track: Track 1fr, Genres 1.5fr) shows the song's `genre:` values joined by ", " on up to two lines, ellipsis after the second, with the full list as tooltip, empty when none (`web/js/genre-cell.js`, tested); there is no Album column (album stays in Edit and search). Rows without server audio show no "Not on the server" line, only the greyed title and the service logo link (WEB-023). Status: implemented (not checked in a browser)
- WEB-032 MUST: the "Wikipedia: song" and "Wikipedia: band" inputs (Add and Edit dialogs, `web/js/wiki-links.js`) hide the prefix `https://en.wikipedia.org/wiki/`: `wikiDisplay(url)` shows the decoded article title with underscores as spaces (also for `en.m.` and `m.en.` hosts; query and fragment are not shown), any other value (Wikidata, other-language Wikipedia) is shown unchanged. `wikiNormalize(text)` turns typed text into the stored value: empty stays empty, an http(s) link is kept, anything else is an article title and becomes `https://en.wikipedia.org/wiki/<Title_with_underscores>` (escaped). The stored value is what is saved and validated (red outline as in ADD-050); it is unchanged while the field is untouched, and a pasted link or typed title is re-rendered as the article name on blur or Enter. Placeholder "Article name or link". Status: implemented (not checked in a browser)
