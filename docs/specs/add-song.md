# Add song

Code: `web/js/add.js`, `server/app/routes/lookup.py` (`preview`), `server/app/routes/songs.py` (`create_song`), `server/app/downloads.py` (`run_download`), `server/app/extractor.py`, `server/app/titles.py`, `server/app/metadata.py`, `server/app/bpm.py`.

## Flow

1. Paste a YouTube URL, press Preview (`POST /preview`).
2. Edit fields and tags in the preview card.
3. Web: "Save to library" saves metadata only (`POST /songs` with `audio:false`, 201, no download, no polling); toast "Saved to library". Audio reaches the server only through the iOS download flow (2026-10-13). The steps below describe the iOS/server download path (`audio` omitted: 202, poll `GET /songs/{id}/status`).

## BPM

- ADD-020 MUST: BPM is optional; empty means auto-detect after download (web: no BPM input, a muted line "BPM is detected after saving"; iOS: a muted line "BPM is detected after saving"); a supplied value (20..300, whole number, fractions rounded) is kept and skips detection. Status: implemented
- ADD-021 MUST: detection decodes the saved file with `ffmpeg` to mono 44.1 kHz float PCM (120 s timeout), runs aubio tempo, takes the median of per-beat estimates (needs >= 4 beats), folds into 70..180 and rounds to a whole number. Status: implemented
- ADD-022 MUST: any detection failure (no ffmpeg, no aubio, too few beats) is logged and stored as `bpm: null`; it never fails the download. Status: implemented
- ADD-023 MUST: BPM is a heuristic and may be off by half or double; the UI says so and lets the user edit it or re-detect from the Edit dialog (`POST /songs/{id}/bpm/detect`). Status: implemented
- ADD-110 MUST: songs added before detection existed (or whose detection failed) can be filled in bulk with Settings > BPM detection > Detect missing BPM (API-110..112); it uses the same detector, rounding and octave heuristic as the download path (ADD-022, ADD-023). Status: implemented
- ADD-024 SHOULD: detection run off the request path for slow files. Status: implemented (the job runs in a background task; re-detect runs in a thread pool)

- ADD-070 MUST: the remix cut (`titles.split_title(artist, title)`, pure, no network, no AI, never MusicBrainz) runs before the artist/title split: the first bracket `(...)` or `[...]` whose text contains the whole word "remix" or "mashup" or the whole phrase "mixed by" (case-insensitive) is removed from the title (double spaces collapsed, trailing separators trimmed) and its inner text, trimmed with its capitalisation kept, becomes `remixer` ("Delerium - Innocente (Sadrican 2026 Remix)" gives title "Delerium - Innocente", remixer "Sadrican 2026 Remix"; "Song (Mixed By DJ Gvozd)" gives title "Song", remixer "Mixed By DJ Gvozd"; "Song [DJ X Mashup]" gives title "Song", remixer "DJ X Mashup"; the artist is never invented; see Reference examples). - ADD-071 MUST: Title, Artist and Remix & additional production are shown as token pills (web; WEB-039) (a view of the one plain string, saved unchanged; web `web/js/tokens.js`, `token-field.js`, tested in `tokens.test.mjs`; the iOS side ports `tokens.js`). Tokenization: `tokenize(text)` returns `[{text, sep}]`, `sep` being the separator that followed the token (empty for the last); `compose` concatenates `text+sep`, so `compose(tokenize(s)) == s` for ANY string. Whitespace adjacent to a separator belongs to `sep`; tokens are shown trimmed; a blank token (only at the start or end, never between) is not shown. Separators (one list, shared by Title, Artist and Remix & additional production; web `web/js/tokens.js`): a dash `-`, `–` or `—`, a pipe `|` or `｜`, a slash `/` or `／` or a doubled slash `//`, each ONLY with whitespace on both sides (' - ', ' – ', ' — ', ' | ', ' / ', ' // ' and the fullwidth variants). A comma, semicolon, `&`, `feat.`, a dot, a colon, a bullet, or any slash, pipe or dash without surrounding spaces NEVER separates ('Tyler, The Creator', 'Earth, Wind & Fire', 'AC/DC', '24/7', 'Jean-Michel Jarre', 'A-ha', 'Лондон, гуд бай' are one pill each; 'AC/DC - Back In Black' gives two; 'A - B / C | D' gives four). Pills are also created by pressing Enter in the entry. Whitespace adjacent to a separator belongs to `sep`; tokens are shown trimmed; a blank token (only at the start or end, never between) is not shown. Adjacent separators fold into one `sep`. Brackets get no special treatment: `(Sadrican Remix)` stays inside its token. Pure helpers: `splitTokens(text)` (the shown, trimmed pills) and `joinTokens(parts)` (joined with ' - ', the one serialisation). The stored string is never changed by opening and saving: the raw value is kept until a pill is edited, added or removed, and an edit keeps the separators of the untouched pills ('Artist | Title' shows two pills and saves back unchanged; a NEW pill is joined with ' - '). Older data with a comma ('A, B') now shows as ONE pill 'A, B' until the user splits it; server-side lookups treat both ' - ' and the legacy ', ' as artist separators locally (ADD-079). The TAG editor (genres, countries, other tags) keeps its own comma rules, unchanged. iOS gap: `TokenField.swift` still ports the old separator rules (comma, `;`, `:`, bullets, periods) and is not changed here; it keeps splitting on them until it ports the new `tokens.js`. Status: implemented on the web (not browser-verified); iOS not ported

- ADD-077 MUST: promo noise is removed from a title when a song is added, by ONE function with identical rules on the server (`server/app/titleclean.py`, authoritative) and the web (`web/js/title-clean.js`), driven by the shared table `server/tests/fixtures/title_clean_cases.json` (135 cases, both test suites read it). A bracketed group `(...)`, `[...]`, `{...}` or `【...】` (innermost first, nested ones repeat) or a trailing segment after ' | ', ' / ', ' // ' (and fullwidth) or ' - ' / ' – ' / ' — ' is removed only when its WHOLE content, case-, trim- and punctuation-insensitive, is in the noise list: free download, free dl, free d/l, download, free, free track, free release, premiere(d), exclusive, out now, out soon, available now, buy (now), hd, hq, 4k, 1080p, 720p, 60fps, official, official video / music video / audio / lyric video / visualizer / video clip, lyrics, lyric video, with lyrics, video, audio, visualizer, music video, mv, clip, video clip, full song, full version, high quality, hq audio, original mix, original version, original; a combined content split on `/`, `,`, `&`, `+` counts when ALL parts are noise ('[Free Download / Premiere]'). After ' - ' only the promo group (free download, free dl, free d/l, out now, premiere) is removed when just one segment would remain ('Artist - Free Download' gives 'Artist'); with two or more left the whole list applies ('A - B - Official Video'). Meaningful tags are never removed: remix, mix, extended, radio edit, edit, club mix, dub, instrumental, acoustic, live, version, remaster(ed), cover, bootleg, mashup, feat./ft./featuring, vip, rework, demo ('Rover (Extended Mix)', 'Song (2019 Remastered)' stay). 'Original Mix', 'Original Version' and 'Original' are noise only as a whole segment ('Rover (Original Mix)' gives 'Rover', 'Track [Free Download] (Original Mix)' gives 'Track', 'Song (Original Mix) (Extended Mix)' gives 'Song (Extended Mix)', 'Artist - Title - Original Mix' gives 'Artist - Title', 'Artist - Original Mix' stays); any other word or a name blocks it ('(Tiësto Original Mix)', '(Original Mix Extended)', '(Original Mix Remix)' stay); a group that is not wholly noise stays whole. A content also counts as noise word by word: when EVERY word (split on whitespace and punctuation, case-insensitive) is in the unambiguous promo/quality vocabulary (free, download, dl, premiere(d), exclusive, hd, hq, 4k, 1080p, 720p, 480p, 360p, 60fps, official, lyric(s), visualizer, mv, audio, video, music, clip, with, out, now, soon, available, buy, new, full, song, high, quality, the) AND at least one word is a strong one (free, download, dl, premiere(d), exclusive, hd, hq, 4k, the resolutions, 60fps, official, lyric(s), visualizer, mv, video, audio, clip), '[HD 1080p]' and '(Official Music Video HD)' go, but '(The New Song)', '(Music)', '(Official Remix)' and '(HD Extended Mix)' stay (any other word, such as remix, mix, live, version or a year, blocks removal); the word rule is not used for the lone segment after ' - ' (promo group only). Whitespace is collapsed, separators left at an end are trimmed, Unicode (Cyrillic) is untouched, the result is never empty (an empty result keeps the original) and the function is idempotent.
