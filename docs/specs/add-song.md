# Add song

Code: `web/js/add.js`, `server/app/main.py` (`preview`, `create_song`,
`_run_download`), `server/app/extractor.py`, `server/app/bpm.py`.

## Flow

1. Paste a YouTube URL, press Preview (`POST /preview`).
2. Edit fields and tags in the preview card.
3. Web: "Save to library" saves metadata only (`POST /songs` with `audio:false`, 201, no download, no polling); toast "Saved to library". Audio reaches the server only through the iOS download flow (2026-10-13). The steps below describe the iOS/server download path (`audio` omitted: 202, poll `GET /songs/{id}/status`).

## Requirements

- ADD-001 MUST (Add becomes "add to catalog" when ADR-0010 is accepted, see CAT-011): the Add screen accepts a YouTube URL and shows a preview card with cover (YouTube thumbnail), title, duration, and editable Title, Artist, Album, Year, BPM and Tags. Status: implemented
- ADD-002 MUST: preview prefills `title` from yt-dlp `track` else `title` (for YouTube, cut by `server/app/titles.py` `split_artist_title`: when the channel name starts the video title it is the artist, separators " - " and " ●● ", and noise such as "(Official Video)" or "(Remastered 2009)" is stripped, but version info such as "(Live from the Royal Albert Hall)" or "(Acoustic)" stays, see ADD-073; "feat."/"ft."/"featuring" credits are kept in the saved title and artist and stripped only for lookups, see ADD-075; applied in search, preview and download); `artist` from `artist`, `creator`, `uploader`; `year` from `release_year`, else `release_date`/`upload_date`; `tags` per [tags.md](tags.md) (genre and country suggestions; no language tag is suggested). Status: implemented
- ADD-003 MUST: preview downloads nothing and writes nothing. Status: implemented
- ADD-004 MUST: the user may edit every field and tag before saving using the shared tag editor (LIB-055): current tags as removable chips, a "Suggested" row with the preview's tags (toggle), all library tags as toggle chips, a text input (Enter or comma adds, accepts `key:value`). Status: implemented
- ADD-005 MUST: on iOS ("Add and download to iPhone"; the web saves metadata only, ADD-053), Save starts a background download of the best m4a audio (`bestaudio[ext=m4a]/140`) to the user's audio directory (`<music_root>/users/<uid>/`) as `<id>.m4a`, one video only (no playlists). Status: implemented
- ADD-006 MUST: after the audio is saved the server fetches the cover from `https://i.ytimg.com/vi/<id>/hqdefault.jpg` to `covers/<id>.jpg`; a failed fetch leaves `cover: null` and does not fail the add. Status: implemented
- ADD-007 MUST: on success the song record is appended and committed (`audioplayer: <uid8> add <id>`); `added_at` is the UTC completion time. Status: implemented
- ADD-008 MUST: progress is 0..1 from yt-dlp byte counts, rounded to 3 decimals; it may stay at 0 when the size is unknown. Status: implemented
- ADD-009 MUST: on any failure the partial `<id>.m4a` is deleted and the job becomes `error` with a short message; the UI shows "Download failed: <message>" and re-enables Save. Status: implemented

- ADD-050 MUST: the web preview card has two optional URL inputs (the iOS Add form keeps and saves the links but does not show them for now), "Wikipedia: song" and "Wikipedia: band", pre-filled from `preview.wikipedia_song` / `wikipedia_artist` (MusicBrainz url-rels, see [tags.md](tags.md) TAG-040); they are saved with the song (`metadata.wikipedia_song`, `wikipedia_artist`); an input that is not a Wikipedia/Wikidata link is outlined red and dropped by the server. Status: implemented
- ADD-051 MUST: the Add form has no "Fill from Wikipedia links" button; the two link inputs feed "Get metadata" (`POST /metadata`; a differing `suggest` artist/title is offered as a tappable hint, never auto-filled); `POST /lookup/wikipedia` remains for the song edit sheet. In the iOS form the two link inputs are not shown for now (the links are still kept, saved and sent); four service icons beside the button reflect `services` from the response (inactive, pulsing, found and tappable; Spotify always inactive), see IOS-021. Status: implemented
- ADD-053 MUST: the web Add dialog has the same "Get metadata" button, service icons, "Wikipedia says" hint and Genres/Countries chip fields as iOS (WEB-022), and shows the full edit form straight after Fetch. Status: implemented

## BPM

- ADD-020 MUST: BPM is optional; empty means auto-detect after download (placeholder "Detected after saving"); a typed value (20..300, whole number, fractions rounded) is kept and skips detection. Status: implemented
- ADD-021 MUST: detection decodes the saved file with `ffmpeg` to mono 44.1 kHz float PCM (120 s timeout), runs aubio tempo, takes the median of per-beat estimates (needs >= 4 beats), folds into 70..180 and rounds to a whole number. Status: implemented
- ADD-022 MUST: any detection failure (no ffmpeg, no aubio, too few beats) is logged and stored as `bpm: null`; it never fails the download. Status: implemented
- ADD-023 MUST: BPM is a heuristic and may be off by half or double; the UI says so and lets the user edit it or re-detect from the Edit dialog (`POST /songs/{id}/bpm/detect`). Status: implemented
- ADD-024 SHOULD: detection run off the request path for slow files. Status: implemented (the job runs in a background task; re-detect runs in a thread pool)

## Duplicates

- ADD-030 MUST: preview returns `in_library: true` when the id is already stored; the UI shows "This song is already in your library." and disables Save. Status: implemented
- ADD-068 MUST: the iOS Add sheet checks the pasted link against the on-device library before Fetch (no network): "Already in your library: <title> · <artist>" with a Play action, and Fetch is disabled until the link changes. Status: implemented
- ADD-031 MUST: `POST /songs` returns 409 `already in library` or `already downloading` (checked under the lock). Status: implemented
- ADD-032 MUST: the identity of a song is its id (YouTube video id or `soundcloud-<track id>`); two URLs for the same video or track are the same song. Status: implemented
- ADD-033 MUST: pasted links are cleaned before use: YouTube forms (`youtu.be/<id>`, `watch?v=`, `m.` and `music.` hosts, `shorts/`, `embed/`, `live/`) become `https://www.youtube.com/watch?v=<id>`, dropping `si`, `t`, `list` and every other parameter; other http(s) links lose only `si`, `feature`, `pp`, `fbclid`, `gclid` and `utm_*`. The web cleans on paste, drop, bulk input (paste/drop/replacement input events or multi-character insertions; single keystrokes are left alone), blur and submit, moves the caret to the end, extracts the first YouTube or http(s) link from surrounding text (otherwise the first line) and shows the result in the field (`cleanPasted` in `web/js/url-clean.js`); the server applies the same rules (`server/app/urlclean.py`) and tolerates clean input. Status: implemented

## SoundCloud

- ADD-060 MUST: Add also accepts a SoundCloud track link (no search): `soundcloud.com/<artist>/<track>` with `www.`/`m.` hosts, an optional private `/s-<secret>` segment, and `on.soundcloud.com/<code>` short links. Cleaning (web `cleanPasted`, iOS port, server `urlclean.py`) gives `https://soundcloud.com/<artist>/<track>[/s-<secret>]`, dropping the query and fragment; the server resolves a short link by following its redirect once (https only, host `soundcloud.com`/`www.`/`m.`). Status: implemented (live SoundCloud download not verified)
- ADD-061 MUST: playlists, sets, albums, likes and profile links are refused with 422 `{"error":"unsupported"}` and the message "Only single tracks are supported". Status: implemented
- ADD-062 MUST: the song id is `soundcloud-<numeric track id>` (known only after the server resolves the link, so preview returns it); the record gets `source: "soundcloud"`; YouTube ids and records are unchanged ([ADR-0011](../tech/decisions.md)). Status: implemented
- ADD-063 MUST: SoundCloud preview uses yt-dlp metadata without downloading: `title` (`track`, else `title`), `artist` from `artists`/`artist`/`creator`, else the uploader (which may be a label, see [concerns](../concerns.md)), `thumbnail` the artwork upgraded to `-t500x500`, `duration`, `genres` as suggested `genre:` tags, `year` only from `release_year`/`release_date`. Status: implemented
- ADD-064 MUST: save downloads the best audio and re-encodes it to `<id>.m4a` (ffmpeg `FFmpegExtractAudio` m4a), then fetches the artwork (https `*.sndcdn.com` only) to `covers/<id>.jpg`; a cover failure does not fail the add. Status: implemented (live download not verified)
- ADD-065 MUST: SoundCloud Go+ tracks that only offer the 30 s preview are refused with 422 `{"error":"preview_only","detail":"Preview only — SoundCloud Go+ track, can't be downloaded in full."}` at `POST /preview` and `POST /songs`; detection is a yt-dlp format id containing `preview` with no full format, or at download time a chosen preview format or a file under 35 s while the page duration exceeds it by over 60 s (partial file deleted, job `error` with `code: "preview_only"`). Clients show "Preview only — SoundCloud Go+ track, can't be downloaded in full." Status: implemented
- ADD-066 MUST: the preview card shows a small source tag ("YouTube" / "SoundCloud"). Status: implemented
- ADD-067 MUST: the web Add dialog says at once, before Fetch, when the pasted link is already in the loaded library and disables Fetch for it (WEB-025); the disabled Save after a preview whose `in_library` is true stays as the fallback. Status: implemented (web, not checked in a browser)

## Limits (ADR-0012)

- ADD-054 MUST: the server checks the user's quotas before it resolves or downloads the link (API-041); the Add dialog shows a readable message for each refusal and keeps the form: 429 "Hourly limit reached. Try again in N minutes.", 403 `library_full_songs` "Your library is full. Delete some songs to add more.", 403 `library_full_bytes` "Your storage is full. Delete some songs to free space.", 503 `server_full` "The server is out of storage right now. Try again later." (`web/js/limits.js` `friendly`, tested). Status: implemented
- ADD-055 MUST: there is no "Fill from Wikipedia links" button on the web; the song and band Wikipedia link inputs stay and are saved with the song. Status: implemented
- ADD-052 MUST: a sign-in refused because signup is closed shows "Sign-up is closed on this server." on Settings (403 `signup_closed`). Status: implemented
- ADD-069 MUST: a song carries an optional `remixer` text; `/preview` returns the title already cut of the remix bracket (ADD-070) plus `remixer`, which the web Add dialog prefills (WEB-026). Status: implemented on web
- ADD-070 MUST: the remix cut (`titles.split_title(artist, title)`, pure, no network, no AI, never MusicBrainz) runs before the artist/title split: the first bracket `(...)` or `[...]` whose text contains the whole word "remix" (case-insensitive) is removed from the title (double spaces collapsed, trailing separators trimmed) and its inner text, trimmed with its capitalisation kept, becomes `remixer` ("Delerium - Innocente (Sadrican 2026 Remix)" gives title "Delerium - Innocente", remixer "Sadrican 2026 Remix"; the artist is never invented; see Reference examples). Other bracket words (Extended Mix, Radio Edit, Club Mix, Bootleg, Rework, Remastered, Official Video) and a bare unbracketed "Remix" do not trigger it. When no bracket matched, the first segment after the first one, split by the spaced separators " | ", " - ", " – ", " — ", whose text contains the whole word "remix" is cut verbatim (trimmed) into `remixer` together with the separator before it ("A - B | X Remix" gives title "A - B", remixer "X Remix"); the first segment is never cut, and the segment cut applies only when at least two segments remain after it, so with two segments in total nothing is cut ("Daft Punk - Around The World Remix" keeps its remix word in the title; the user fixes it with the pills); noise stripping then runs on the remaining title. Applied by preview, download and the SoundCloud probe, not by search (result rows keep the full title). Status: implemented
- ADD-071 MUST: Title, Artist and Remix & additional production are shown as token pills (a view of the one plain string, saved unchanged; web `web/js/tokens.js`, `token-field.js`, tested in `tokens.test.mjs`; the iOS side ports `tokens.js`). Tokenization: `tokenize(text)` returns `[{text, sep}]`, `sep` being the separator that followed the token (empty for the last); `compose` concatenates `text+sep`, so `compose(tokenize(s)) == s` for ANY string. Whitespace adjacent to a separator belongs to `sep`; tokens are shown trimmed; a blank token (only at the start or end, never between) is not shown. Separators: `|`; `,` and `;` when a whitespace or the string end touches them; `:` when followed by whitespace or the end and not preceded by whitespace; `/`, `-`, `–`, `—` only with whitespace on both sides (never inside Hip-Hop, Jean-Michel, AC/DC); a run of `●` or `•` with whitespace on both sides; `.` only when followed by whitespace, then a character that is not lower-case, and preceded by a word of at least 3 letters that is not one of feat, featuring, vol, vs, ft, pt, mr, mrs, ms, dr, jr, sr, st, inc, ltd, ver, prod (so Q., initials, decimals and ellipses stay whole). Adjacent separators fold into one `sep`. Brackets get no special treatment: `(Sadrican Remix)` stays inside its token.
- ADD-072 MUST: pill operations on strings. `removeToken(text, i)`: drop token i with the separator that followed it (when i is the last token, drop the separator that followed token i-1 instead), then trim. `replaceToken(text, i, new)`: keeps the separator, trims `new`, empty `new` removes the token; separators inside `new` re-tokenize naturally. `appendToken(text, token, defaultSep)`: trimmed token; nothing for a blank token; the token alone for blank text; directly after a trailing separator (adding a space when that separator ends without whitespace); otherwise after the trimmed text with `defaultSep`. Default separators: Artist `", "`, Title `" - "`, Remix `" "`. `moveToken(src, i, dst, dstDefaultSep)` returns `{src: removeToken(src, i), dst: appendToken(dst, token, dstDefaultSep)}` and does nothing for a blank token; a pill can be moved to either of the other two fields. Typing a separator in the free-text entry commits the finished parts as pills (`commitTyped`), the unfinished remainder stays typed and counts in the field value; a trailing separator left by typing is dropped on blur (`stripEdges`). Status: implemented on the web (not checked in a browser) and on iOS (IOS-065)
- ADD-074 MUST: pills move by drag and drop between the three fields and within one field (the pencil menu's "Move to ..." stays as the keyboard alternative). `insertToken(text, index, token, defaultSep)`: like `appendToken` but puts the trimmed token BEFORE token `index` of `tokenize(text)`; the new token's separator is `defaultSep`, the previous token's separator is kept; blank token: nothing; blank text: the token alone; `index` at or past the end (or before a trailing blank token) is `appendToken`; index 0 on a leading blank token inserts after that blank. `moveTokenTo(src, i, dst, dstIndex, dstDefaultSep)` returns `{src, dst}`: `removeToken(src, i)` then `insertToken` into `dst` (the default separator is the destination field's); within one field (`src == dst`) the index is adjusted for the removal, `src == dst` in the result, and dropping on the pill itself or on the gap right after it is a no-op (text unchanged, no events). Dropping on a pill inserts before it; dropping on the free area or entry of a field appends. Status: implemented on the web (not checked in a browser); iOS implemented (IOS-066, not exercised on a device)
- ADD-073 MUST: version info (live, acoustic, unplugged, session, "at <venue>") stays in the saved and shown title ("Cold Heart (Live from the Royal Albert Hall)"); only noise words (Official, Video, Audio, Lyrics, Visualizer, Remastered, HD, HQ, 4k, Clip, MV) are stripped, so "(Official Live Video)" is still removed. For external lookups (MusicBrainz, Wikidata, Wikipedia) `titles.lookup_title` additionally drops those version brackets and a trailing "- Live ..." or "Live at ..." segment; the visible title is never changed by it, and there is no Version field. Status: implemented
- ADD-075 MUST: feat credits are kept in the saved title and artist ("Song (feat. X)" and "Artist feat. X" stay), with the keyword normalised by `titles.normalize_feat` to exactly "feat." (whole words Feat., FEAT, ft, Ft., FT., featuring, Featuring all become "feat."; "Kato Feat. Jon" gives "Kato feat. Jon", "Song (Ft. X)" gives "Song (feat. X)"; names and "Defeat" untouched; not rewritten right after a number ("5 ft tall" stays, ft = feet), and the bare forms ft/feat without a period only when the next word starts with a capital or digit ("Kato ft Jon" changes, "Kato ft jon" stays; "ft.", "feat." and "featuring" always change); the cue below still reads the raw text; see Reference examples); only lookups (MusicBrainz, Wikipedia) strip them (`titles.lookup_title`, `titles.lookup_artist`; a credit ends at its own separator or closing bracket), so queries use "Kato" and "Turn The Lights Off". Deterministic split cue in `split_title`: when no channel-prefix split happened and the text before the first spaced " - ", " – " or " — " contains a feat keyword that normalize_feat would rewrite (whole word feat, feat., ft, ft. or featuring, case-insensitive), that left part is the artist (credit included) and the rest after the dash is the title, later pipe segments included ("Kato Feat. Jon - Turn The Lights Off | Jon Hamm Club Dance Scene | DEEPO Remix Long Version" gives artist "Kato feat. Jon", title "Turn The Lights Off | Jon Hamm Club Dance Scene", remixer "DEEPO Remix Long Version"). Without the cue ("Warriors Dance - The Prodigy") nothing is split. Status: implemented
