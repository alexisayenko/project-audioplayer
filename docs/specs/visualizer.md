# Visualizer

Analyser-driven 2D canvas visualizer on the web Playback screen ([task-0023](../tasks/task-0023.md) phase 1; the iOS app is unchanged). Decisions: [ADR-0016](../tech/decisions.md) sub-note. Status "not browser-verified" means unit-tested with fakes only: no real audio analysis, iOS Safari, CPU or look check yet. Term names and aliases (now line, relief, parts, camera): [terminology.md](terminology.md).

## Audio graph

- VIZ-001 MUST: the Web Audio graph (`web/js/audio-graph.js`) is created lazily: nothing is created at app start or by merely loading a page; the first user gesture that enables the visualizer (the Visualizer button, key `V`, or the Settings switch; with the switch already on, the first pointer or key gesture) builds `AudioContext` -> `createMediaElementSource(audio)` -> `GainNode` (unity, reserved for [task-0020](../tasks/task-0020.md)) -> `AnalyserNode` (`fftSize` 8192, `smoothingTimeConstant` 0.5) -> destination. Status: implemented (not browser-verified)
- VIZ-002 MUST: the graph is idempotent (one graph per page; concurrent and repeated `enable` calls return the same graph) because `createMediaElementSource` cannot be undone. Status: implemented (not browser-verified)
- VIZ-003 MUST: the audio element is routed through the graph only after the context is confirmed `running` (resumed inside the gesture, 1.5 s timeout); a context that stays suspended (blocked, iOS lock) is closed and the element is never routed, so plain playback is untouched; the source node is created last so a failure leaves the element unrouted; any failure shows the static idle frame. The graph resumes on every `play` and when the tab becomes visible. Status: implemented (not browser-verified)
- VIZ-004 MUST: the module exposes `getAnalyser()` (only while the context is `running`), `getGain()`, `isSupported()`, `getState()` and `onState(cb)` (`off`, `running`, `suspended`, `interrupted`, `blocked`, `failed`, `unsupported`). Status: implemented
- VIZ-005 MUST: audio is same origin (session cookie or the guest stream), so the analyser is not silenced by CORS; the visualizer works in guest mode. Status: implemented (not browser-verified)

## Look (reference match)

- VIZ-010 MUST: bar geometry is proportional and matches the reference (thicker bars that nearly merge with their glow): `barCount(width) = clamp(round(width / 4), 96, 480)` (300 bars at 1200 px, 475 at 1900 px; the count and pitch depend only on the canvas width, never on the governor level, so the density cannot drift while playing), bar width `max(2 css px, round(0.6 * pitch * dpr))` device pixels, one constant integer width for every bar, with a gap of at least 1 css px; bars are drawn in device pixels (identity transform) and each bar's left edge is `round(i * pitch * dpr)` and its right edge left + width, so both edges sit on whole device pixels in the main, mirrored and glow-source draws (no moire stripes from fractional edges), low frequencies on the left (log scale 20 Hz to 16 kHz, analyser bins read nearest/max-pooled per bar so single spikes survive, no spatial smoothing), per-bar attack/release smoothing only. Levels are not read against a fixed dB window (that saturated every loud bar into one constant shape): each bar's max-pooled dB gets a +3 dB/octave tilt about 1 kHz, then maps through a 50 dB window whose top is a slow global reference (the loudest bar, rising over about 0.5 s, falling 2 dB/s, never below -70 dB, plus 3 dB headroom), so loud passages do not clip and the shape follows the real spectrum, beat and dynamics; the same levels feed the Ring and Terrain (VIZ-042, VIZ-043) and the bass pulse. Status: implemented (not browser-verified)
- VIZ-015 MUST: jagged silhouette: each bar height is `v^0.85` times `1 + 0.18 * noise(bar, floor(t / 60 ms))` (deterministic hash, so it shimmers like the reference clip), then the soft knee of VIZ-011. Status: implemented (not browser-verified)
- VIZ-011 MUST: the Mirrored spectrum mirrors about a bright horizon line (`--viz-line` #fff: a 3 px core with a flare that is brightest in the centre, plus halos at alpha 0.5 (+-3 px) and 0.2 (+-10 px); no `shadowBlur`). The lower half is the SAME bar draw flipped (`scale(1, -1)` about the horizon) at alpha 0.35 (a faint, dimmer reflection): no second series, no silhouette or envelope fill, no reflection scrim, no second tier. Bar height is `0.8 * (1 - exp(-2v)) / (1 - exp(-2))` of the half height multiplied by the height scale (VIZ-041). Status: implemented (not browser-verified)
- VIZ-012 MUST: colour is one horizontal gradient with 4 stops (`--viz-s0` #ff1f8e at 0, `--viz-s1` #ff3d73 at 25%, `--viz-s2` #ff6a52 at 60%, `--viz-s3` #ff9a3a at 100%; `--viz-a` and `--viz-b` alias s0 and s3); bars are uniformly that colour from base to tip: no white or whitened tips and no tip layer; bars fade only over the outer 4% of the width. Status: implemented (not browser-verified)
- VIZ-013 MUST: no `shadowBlur` anywhere in the 2D renderers. Per frame the main canvas receives, in order: `clearRect`, the backdrop image (VIZ-016, full-screen only), the upper bars (one fill per edge-fade band, 8 bands), the flipped lower bars (same bands), the horizon (3 `fillRect`), then the glow composites with `lighter`. Glow is a blurred copy of the already drawn sharp bars (both halves and the horizon together, so every line gets a halo in its own colour that bleeds into the gaps): a half-resolution layer blurred 2 px (alpha 0.65) and, at level 0, a second quarter-resolution layer blurred again from the first (wider body, alpha 0.5); layers are cleared and reset to `source-over` every frame. There is no polygon envelope. At most 24 fills per frame at 700 bars. Governor: level 0 both glows and backdrop, level 1 tight glow and backdrop, level 2 cheap quarter-resolution glow blurred 1 px, level 3 none. The governor never changes the bar count or pitch, only glow and backdrop; a browser whose 2D context has no `filter` (blur) draws no glow at all, because an unblurred downscaled copy composited with `lighter` shows as extra lighter ghost bars (VIZ-017). Status: implemented (not browser-verified)
- VIZ-017 MUST: bar density is constant and only one aligned set of bars is visible: no governor level, resize or DPR change alters bar count or pitch for a given canvas width, and the glow is always a blurred copy (never sharp). Status: implemented (not browser-verified)
- VIZ-016 MUST: in full-screen bars mode (levels 0-1) a faint decorative ring backdrop (radius 0.28 of the height, 160 spokes, alpha 0.25 pulsing with the bass) is drawn from an offscreen canvas rendered once per resize; never in the Playback background (transparent over the CSS scrim). The full-screen background is a radial gradient `--viz-bg-center` #1b0a33 to `--viz-bg-edge` #07030f. The sparkle dots of the earlier plan are not built (they would add draw passes). Status: implemented (not browser-verified)
- VIZ-014 MUST: all colours come from `web/viz.css` (`--viz-a`, `--viz-b`, `--viz-line`, `--viz-bg-top` #1a0b33, `--viz-bg-mid` #3b1470; the same in light and dark). The canvas is transparent; the violet gradient is CSS: a translucent layer at 35% opacity behind Playback (text stays readable on both themes; contrast to be measured), the full gradient in full-screen mode. The Ring visualizer (VIZ-042) is a radial ring (spokes mirrored about the vertical axis around a dark disc, halo, three fading dot rings rotating slowly, radius pulsing with the bass energy below 150 Hz); it is never drawn together with the bars. Status: implemented (not browser-verified)

- VIZ-074 MUST: Terrain camera flight (`viz-flight.js`; owner request 2026-10-15: "camera moving slowly on eye and yaw ... like a spaceship"). The drift is an OFFSET added in the frame on top of the base camera (defaults or the debug panel); the stored base values are never touched. Each channel is a sum of three sines (weights 0.55 / 0.3 / 0.15, irrational period ratios, random phases per session from a seeded `mulberry32`, independent seeds per channel): eye periods 90 / 55.6 / 40.2 s, amplitude `min(0.35 x base eye, base - 0.2, 10 - base)` so the eye never leaves [0.2, 10]; yaw periods 60 / 37.1 / 26.8 s, amplitude `min(14 deg, yawCoverDeg(aspect) - |base yaw|)` (`yawCoverDeg` = `YAW_COVER_MAX_DEG` minus the half horizontal field of view, about 21 deg at 16:9) so the grid stays covered, shrinking to 0 for a large base yaw; pitch gets `-1.5 deg x (eye offset / eye amplitude)` (rising looks down a little); no roll. Time is dt-based (timestamp driven, each frame step clamped to 0.1 s) so 30, 60 and 120 fps give the same trajectory, and it advances ONLY while audio plays (paused: the view holds still). Toggling on eases the offset in over 3 s, off over 2 s (smoothstep, no snap; the ease runs on frames, so if frames stop while paused it finishes on the next frame). The LOD tier widths use the worst-case yaw `|base yaw| + flight yaw amplitude` (5 degree steps, `yawStepOf`) while flight is on or easing out, never the instantaneous yaw, so no grid rebuild happens while drifting (only at the toggle). `vizdebug=1`: the Camera panel readouts and copy line stay the BASE values and a read-only line `flight offset: eye +0.4 yaw -6.2deg` shows while flying. Share links carry `fl=1` (SHARE-017). Status: implemented (unit-tested with a fake clock; checked in the built-in browser with a synthetic timeline, not on real playback)

## Performance, motion and safety

- VIZ-030 MUST: `requestAnimationFrame` runs only while the visualizer is enabled AND audio is playing (or bars are still decaying) AND the document is visible AND the canvas is on screen (`IntersectionObserver`); otherwise the loop stops and an idle frame (or a clear) is drawn; pause decays to idle, no frozen frame. Status: implemented
- VIZ-031 MUST: 30 fps for the Mirrored spectrum and the Ring (Terrain draws at `TERRAIN_TARGET_FPS` 60, VIZ-061; `makePacer` takes its rate per frame via `set(fps)` and a refresh-aware slack); the canvas DPR is capped at 1.5 (2 only in full-screen on a non-touch device); the frame governor starts at level 1 (cheap quarter-resolution glow), raises quality to level 0 after 60 consecutive frames under 10 ms, and lowers it one level when the 30-frame average work time exceeds half the frame interval (halo, fewer bars, no glow); in Terrain mode governor levels 0 / 1 / 2 / 3 select Terrain quality 2 / 1 / 1 / 0 (`GOV_TO_TERRAIN`); colours are read once per resize (re-read every 5 s), typed arrays are reused. With `vizdebug=1` in the URL query or hash a small text in the canvas corner shows the average frame time, bar count and governor level. Frame pacing (VIZ-061): the rAF-to-rAF interval is measured and feeds a Terrain quality ladder next to the JS-time criterion. Status: implemented
- VIZ-032 MUST: reduced motion (`prefers-reduced-motion: reduce`) turns the animation off: one static idle frame, no loop, the button tooltip reads "Reduced motion is on"; playback is unaffected. Status: implemented
- VIZ-033 MUST: flash safety (WCAG 2.3.1): the bass pulse that drives ring radius and halo is rate limited (slew 4 units/s) and may reverse direction at most every 1/6 s, so at most 3 flashes in any second; bar heights follow release 0.15 smoothing; covered by a test with a full-scale alternating beat. Status: implemented
- VIZ-034 SHOULD: CPU below 8% of one mid-range phone core at 30 fps. Measurement plan: browser Performance panel, 60 s of playback per placement (background, full-screen), record mean frame time and dropped frames on one phone and one desktop. Status: planned
- VIZ-035 MUST: the canvases are `aria-hidden`; the overlay has `role="dialog"` and an accessible name; the Visualizer button and the exit button have accessible names. Status: implemented
- VIZ-036 MUST: the visualizer never invents motion: with no analyser, or an analyser that reads silence (every bin `-Infinity`, NaN or below -110 dB), the bars are all zero (Mirrored spectrum shows only the horizon line, Ring only the idle ring) and a one-line status names the cause (`viz-signal.js` `diagnose`): browser without Web Audio, context blocked, context `suspended` or `interrupted`, audio not routed yet, or analyser silent for 90 frames (about 3 s). The Web Audio graph is created only synchronously inside a user gesture (`audio-graph.js` `unlock`: `AudioContext`, source -> gain -> analyser -> destination wired first, then `resume()`), never on track end or auto-advance, and only when Visualizer background is on or the overlay is open: `V`, the Visualizer button and the setting call it directly, and while no graph is running a capturing listener on `pointerdown`, `pointerup`, `touchend`, `mousedown`, `click` and `keydown` (so every Play, Pause, Next, Previous and track click) calls it too and is removed once the context runs. A `blocked` state is not sticky: the next gesture retries `resume()`. The media element source is created once per page. In full-screen the status line is moved inside the overlay at the top left, under the `vizdebug` line. With `vizdebug=1` in the URL query or hash a fixed text box at the bottom left lists: state code, playing/paused, graph state, `AudioContext.state`, analyser `fftSize`, last frame max and mean dB and byte max, whether the frame is all-zero, frame counts (total, non-zero, silent run), audio origin vs page origin and same-origin yes/no, `audio.crossOrigin` and the user agent family. Status: implemented (not browser-verified)

Status: implemented (not browser-verified)

Status: implemented (not browser-verified)
Concept of Terrain in plain language (for designers): [terrain-concept.md](terrain-concept.md).

- VIZ-043 MUST: Terrain uses `viz-terrain-math.js` and `viz-terrain-gl.js`. Geometry: a rigid landscape of relief that travels toward the camera at a constant world speed (`WORLD_SPEED` 5.5 units/s). Rows are uniformly spaced in world z over a 40-unit depth (`rowZ`), the grid has a CONSTANT world width (`gridHalfWidth = WIDTH_PER_ASPECT x clamp(aspect, 0.4, 3.6)`, no flare; `WIDTH_PER_ASPECT = tan(32.5 deg) x 0.9 x GRID_DEPTH x 1.1` = 25.4, derived from the frustum half-angle at 90% of the depth with a 10% margin) so the outer columns lie beyond both screen edges at every visible depth from the bottom edge to the far fade (no dark sides, aspects 0.46 to 3.5, pinned by a test) while real perspective still makes the long depth lines converge toward the horizon and fan out toward the bottom edge; columns are uniformly spaced in x (`columnX` is linear, `COL_SHAPE` 1; owner request 2026-10-14, reference 14.webp) and the column spacing equals the row spacing in world units, so every grid cell is a square in world space at every height (a screen-space square only to the extent perspective allows; the nearest screen width holds about 25 / 44 / 74 cells at levels 0 / 1 / 2 at 16:9, see the level-of-detail tiers below); the far fade depends only on depth, never on x; and each vertex row holds one fixed data row that only slides in z (a continuous sub-row scroll `frac`; data rows are sampled at times aligned to the row spacing, so a ridge keeps its shape, no vertical smearing, no temporal aliasing, no per-row height damping near the camera, no swell). Heights: each row's amplitude is baked from that row's own spectrum when the row is sampled (`AMP_BASE + AMP_GAIN x energy of the row`, then a constant `u_amp`), so a row never re-scales with the live beat; the palette energy, glow and horizon are slow (1.2 s) followers and only the now slice (VIZ-047) pulses with the beat; peak height in world units is unchanged from the 2026-10-14 release. Camera: eye 3.31, pitch -13.5 degrees (owner-picked 2026-10-14; the baseline had 2.0 / -10), FOV 62, near plane 0.3, no drift. Bass camera shake and FOV breathing are kept in `cameraAt` but disabled (`SHAKE_ENABLED = false`); when enabled they move only the camera, never row heights. The data lattice (`QUALITY.spacing` 1.0 / 0.6 / 0.4 world units at level 0/1/2; `gridDims(level, aspect)`: rows = 40 / spacing + 1, cols = 2 x halfWidth / spacing + 1, both spacings widened together by 6% steps while rows x cols exceeds `GRID_MAX_VERTICES` 30000) holds the baked heights, landmarks, beat peaks and light factor exactly as before (the tag `terrain-liked-1` keeps the old 40x128, 64x144, 88x208 non-uniform grid). What is drawn is a level-of-detail mesh of square cells (owner request 2026-10-14, "cells too big"): `lodTiers(level, aspect, nowZ)` returns depth tiers whose cell size doubles with distance, `QUALITY.cell` x 2^k with `cell` = 0.35 / 0.2 / 0.12 world units at level 0/1/2 (about 74 cells across the screen at the bottom edge at 16:9, level 2, was about 10); tier k ends at `sqrt(spacing x LOD_ROW_PX 900)` world units (so a row line stays at least about 3 px apart on screen and the far grid does not alias into moire), tiers beyond spacing `LOD_MAX_SPACING` 1.4 or past 90% of the depth run to the far end; level 2 at 16:9 is 0.12 (0-10.4 units), 0.24 (to 14.7), 0.48 (to 20.8), 0.96 (to 40), level 1 is 0.2 / 0.4 / 0.8, level 0 is 0.35 / 0.7 / 1.4. Tiers cross-fade instead of switching: tier k's mesh reaches `LOD_BLEND_CELLS` (3) coarse cells beyond its nominal range on both sides (`zA`, `zB`, `fade`), its lines fade in over `z0 +- 3 x spacing` and out over `z1 +- 3 x next spacing` in the vertex shader (`u_tf`), the column grids are nested (odd counts, multiples of the spacing from x = 0, spacings double) so the shared lines stay at full strength while the in-between lines fade out, bead noise is hashed from the world column so a shared line has the same look in both tiers, and a line's alpha also fades smoothly to 0 as its on-screen column pitch falls from 3 px to 1 px (`u_cell`, `u_focal`); relief flattens to ground over the last 20% of the depth (`FAR_FLAT_START` 0.8, vertex shader) so the far edge fades into the horizon without a comb. Each tier is its own mesh of exact squares (dx = dz = spacing, odd column count, symmetric) and only as wide as the camera footprint at its far end (`tierHalfWidth` = min(`gridHalfWidth`, tan 32.5 deg x aspect x 1.1 x (zEnd + 2)), a trapezoid made of steps; pinned by a test for every tier); neighbouring tiers overlap by at most two rows (no gaps). Tier rows hold fixed absolute times (`jz0`, `baseT`, `fracT`, so a ridge slides rigidly and the bead noise stays on its row) and their heights and light factors are resampled from the lattice on the CPU each frame with a separable Catmull-Rom kernel (`resampleTier`, about 0.3 M multiply-adds, clamped to [0, 1] and [-1, 1]), so the per-frame height and beat-peak cost stays that of the lattice. Vertex budget at 16:9: level 2 about 31000 grid vertices in 4 meshes (62000 ribbon vertices, 16-bit indices because every mesh stays below 32767 vertices; no `OES_element_index_uint` needed), level 1 about 19000, level 0 about 10000; each mesh is capped at `GRID_MAX_VERTICES` (a very wide aspect widens that tier's cells by 6% steps); about 2 ms of JS per frame at level 2 in a desktop browser; the meshes are rebuilt when the aspect changes the counts, heights are smoothed with two [1,2,1] passes, columns map monotonically from low (left) to high (right) frequency, no mirror. Lines: level 0 draws crisp 1 px lines; levels 1 and 2 draw soft ribbons (screen-space quads, gaussian-ish alpha across the line, beaded brightness noise per line and per vertex tied to the data row so it travels with the relief, a depth-of-field widening and dimming toward the near and far ends; level 2 adds the half-resolution bloom). Cells versus long lines: depth lines are drawn at every height, cross lines only above about half a world unit (`crossAlpha`, smoothstep `CROSS_H0` 0.4 to `CROSS_H1` 0.6 on the displayed world height), so flat ground reads as long ribbons and raised ground as a square grid.
