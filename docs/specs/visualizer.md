# Visualizer

Analyser-driven 2D canvas visualizer on the web Playback screen ([task-0023](../tasks/task-0023.md) phase 1; the iOS app is unchanged). Decisions: [ADR-0016](../tech/decisions.md) sub-note. Status "not browser-verified" means unit-tested with fakes only: no real audio analysis, iOS Safari, CPU or look check yet.

## Audio graph

- VIZ-001 MUST: the Web Audio graph (`web/js/audio-graph.js`) is created lazily: nothing is created at app start or by merely loading a page; the first user gesture that enables the visualizer (the Visualizer button, key `V`, or the Settings switch; with the switch already on, the first pointer or key gesture) builds `AudioContext` -> `createMediaElementSource(audio)` -> `GainNode` (unity, reserved for [task-0020](../tasks/task-0020.md)) -> `AnalyserNode` (`fftSize` 8192, `smoothingTimeConstant` 0.5) -> destination. Status: implemented (not browser-verified)
- VIZ-002 MUST: the graph is idempotent (one graph per page; concurrent and repeated `enable` calls return the same graph) because `createMediaElementSource` cannot be undone. Status: implemented (not browser-verified)
- VIZ-003 MUST: the audio element is routed through the graph only after the context is confirmed `running` (resumed inside the gesture, 1.5 s timeout); a context that stays suspended (blocked, iOS lock) is closed and the element is never routed, so plain playback is untouched; the source node is created last so a failure leaves the element unrouted; any failure shows the static idle frame. The graph resumes on every `play` and when the tab becomes visible. Status: implemented (not browser-verified)
- VIZ-004 MUST: the module exposes `getAnalyser()` (only while the context is `running`), `getGain()`, `isSupported()`, `getState()` and `onState(cb)` (`off`, `running`, `suspended`, `interrupted`, `blocked`, `failed`, `unsupported`). Status: implemented
- VIZ-005 MUST: audio is same origin (session cookie or the guest stream), so the analyser is not silenced by CORS; the visualizer works in guest mode. Status: implemented (not browser-verified)

## Look (reference match)

- VIZ-010 MUST: bar geometry is proportional and matches the reference (thicker bars that nearly merge with their glow): `barCount(width) = clamp(round(width / 4), 96, 480)` (300 bars at 1200 px, 475 at 1900 px; the count and pitch depend only on the canvas width, never on the governor level, so the density cannot drift while playing), bar width `max(2 css px, round(0.6 * pitch * dpr))` device pixels, one constant integer width for every bar, with a gap of at least 1 css px; bars are drawn in device pixels (identity transform) and each bar's left edge is `round(i * pitch * dpr)` and its right edge left + width, so both edges sit on whole device pixels in the main, mirrored and glow-source draws (no moire stripes from fractional edges), low frequencies on the left (log scale 20 Hz to 16 kHz, analyser bins read nearest/max-pooled per bar so single spikes survive, no spatial smoothing), per-bar attack/release smoothing only. Levels are not read against a fixed dB window (that saturated every loud bar into one constant shape): each bar's max-pooled dB gets a +3 dB/octave tilt about 1 kHz, then maps through a 50 dB window whose top is a slow global reference (the loudest bar, rising over about 0.5 s, falling 2 dB/s, never below -70 dB, plus 3 dB headroom), so loud passages do not clip and the shape follows the real spectrum, beat and dynamics; the same levels feed the Ring and Terrain (VIZ-042, VIZ-043) and the bass pulse. Status: implemented (not browser-verified)
- VIZ-015 MUST: jagged silhouette: each bar height is `v^0.85` times `1 + 0.18 * noise(bar, floor(t / 60 ms))` (deterministic hash, so it shimmers like the reference clip), then the soft knee of VIZ-011. Status: implemented (not browser-verified)
- VIZ-011 MUST: the Mirrored spectrum mirrors about a bright horizon line (`--viz-line` #fff: a 3 px core with a flare that is brightest in the centre, plus halos at alpha 0.5 (+-3 px) and 0.2 (+-10 px); no `shadowBlur`). The lower half is the SAME bar draw flipped (`scale(1, -1)` about the horizon) at alpha 0.35 (a faint, dimmer reflection): no second series, no silhouette or envelope fill, no reflection scrim, no second tier. Bar height is `0.8 * (1 - exp(-2v)) / (1 - exp(-2))` of the half height multiplied by the height scale (VIZ-041). Status: implemented (not browser-verified)
- VIZ-012 MUST: colour is one horizontal gradient with 4 stops (`--viz-s0` #ff1f8e at 0, `--viz-s1` #ff3d73 at 25%, `--viz-s2` #ff6a52 at 60%, `--viz-s3` #ff9a3a at 100%; `--viz-a` and `--viz-b` alias s0 and s3); bars are uniformly that colour from base to tip: no white or whitened tips and no tip layer; bars fade only over the outer 4% of the width. Status: implemented (not browser-verified)
- VIZ-013 MUST: no `shadowBlur` anywhere in the 2D renderers. Per frame the main canvas receives, in order: `clearRect`, the backdrop image (VIZ-016, full-screen only), the upper bars (one fill per edge-fade band, 8 bands), the flipped lower bars (same bands), the horizon (3 `fillRect`), then the glow composites with `lighter`. Glow is a blurred copy of the already drawn sharp bars (both halves and the horizon together, so every line gets a halo in its own colour that bleeds into the gaps): a half-resolution layer blurred 2 px (alpha 0.65) and, at level 0, a second quarter-resolution layer blurred again from the first (wider body, alpha 0.5); layers are cleared and reset to `source-over` every frame. There is no polygon envelope. At most 24 fills per frame at 700 bars. Governor: level 0 both glows and backdrop, level 1 tight glow and backdrop, level 2 cheap quarter-resolution glow blurred 1 px, level 3 none. The governor never changes the bar count or pitch, only glow and backdrop; a browser whose 2D context has no `filter` (blur) draws no glow at all, because an unblurred downscaled copy composited with `lighter` shows as extra lighter ghost bars (VIZ-017). Status: implemented (not browser-verified)
- VIZ-017 MUST: bar density is constant and only one aligned set of bars is visible: no governor level, resize or DPR change alters bar count or pitch for a given canvas width, and the glow is always a blurred copy (never sharp). Status: implemented (not browser-verified)
- VIZ-016 MUST: in full-screen bars mode (levels 0-1) a faint decorative ring backdrop (radius 0.28 of the height, 160 spokes, alpha 0.25 pulsing with the bass) is drawn from an offscreen canvas rendered once per resize; never in the Playback background (transparent over the CSS scrim). The full-screen background is a radial gradient `--viz-bg-center` #1b0a33 to `--viz-bg-edge` #07030f. The sparkle dots of the earlier plan are not built (they would add draw passes). Status: implemented (not browser-verified)
- VIZ-014 MUST: all colours come from `web/viz.css` (`--viz-a`, `--viz-b`, `--viz-line`, `--viz-bg-top` #1a0b33, `--viz-bg-mid` #3b1470; the same in light and dark). The canvas is transparent; the violet gradient is CSS: a translucent layer at 35% opacity behind Playback (text stays readable on both themes; contrast to be measured), the full gradient in full-screen mode. The Ring visualizer (VIZ-042) is a radial ring (spokes mirrored about the vertical axis around a dark disc, halo, three fading dot rings rotating slowly, radius pulsing with the bass energy below 150 Hz); it is never drawn together with the bars. Status: implemented (not browser-verified)

## Performance, motion and safety

- VIZ-030 MUST: `requestAnimationFrame` runs only while the visualizer is enabled AND audio is playing (or bars are still decaying) AND the document is visible AND the canvas is on screen (`IntersectionObserver`); otherwise the loop stops and an idle frame (or a clear) is drawn; pause decays to idle, no frozen frame. Status: implemented
- VIZ-031 MUST: 30 fps on all devices; the canvas DPR is capped at 1.5 (2 only in full-screen on a non-touch device); the frame governor starts at level 1 (cheap quarter-resolution glow), raises quality to level 0 after 60 consecutive frames under 10 ms, and lowers it one level when the 30-frame average work time exceeds half the frame interval (halo, fewer bars, no glow); in Terrain mode governor levels 0 / 1 / 2 / 3 select Terrain quality 2 / 1 / 1 / 0 (`GOV_TO_TERRAIN`); colours are read once per resize (re-read every 5 s), typed arrays are reused. With `vizdebug=1` in the URL query or hash a small text in the canvas corner shows the average frame time, bar count and governor level. Status: implemented
- VIZ-032 MUST: reduced motion (`prefers-reduced-motion: reduce`) turns the animation off: one static idle frame, no loop, the button tooltip reads "Reduced motion is on"; playback is unaffected. Status: implemented
- VIZ-033 MUST: flash safety (WCAG 2.3.1): the bass pulse that drives ring radius and halo is rate limited (slew 4 units/s) and may reverse direction at most every 1/6 s, so at most 3 flashes in any second; bar heights follow release 0.15 smoothing; covered by a test with a full-scale alternating beat. Status: implemented
- VIZ-034 SHOULD: CPU below 8% of one mid-range phone core at 30 fps. Measurement plan: browser Performance panel, 60 s of playback per placement (background, full-screen), record mean frame time and dropped frames on one phone and one desktop. Status: planned
- VIZ-035 MUST: the canvases are `aria-hidden`; the overlay has `role="dialog"` and an accessible name; the Visualizer button and the exit button have accessible names. Status: implemented
- VIZ-036 MUST: the visualizer never invents motion: with no analyser, or an analyser that reads silence (every bin `-Infinity`, NaN or below -110 dB), the bars are all zero (Mirrored spectrum shows only the horizon line, Ring only the idle ring) and a one-line status names the cause (`viz-signal.js` `diagnose`): browser without Web Audio, context blocked, context `suspended` or `interrupted`, audio not routed yet, or analyser silent for 90 frames (about 3 s). The Web Audio graph is created only synchronously inside a user gesture (`audio-graph.js` `unlock`: `AudioContext`, source -> gain -> analyser -> destination wired first, then `resume()`), never on track end or auto-advance, and only when Visualizer background is on or the overlay is open: `V`, the Visualizer button and the setting call it directly, and while no graph is running a capturing listener on `pointerdown`, `pointerup`, `touchend`, `mousedown`, `click` and `keydown` (so every Play, Pause, Next, Previous and track click) calls it too and is removed once the context runs. A `blocked` state is not sticky: the next gesture retries `resume()`. The media element source is created once per page. In full-screen the status line is moved inside the overlay at the top left, under the `vizdebug` line. With `vizdebug=1` in the URL query or hash a fixed text box at the bottom left lists: state code, playing/paused, graph state, `AudioContext.state`, analyser `fftSize`, last frame max and mean dB and byte max, whether the frame is all-zero, frame counts (total, non-zero, silent run), audio origin vs page origin and same-origin yes/no, `audio.crossOrigin` and the user agent family. Status: implemented (not browser-verified)

## Modes, switch and height

- VIZ-040 MUST: exactly one visualizer is shown at a time, never combined. The modes are `bars` ("Mirrored spectrum", VIZ-010 to VIZ-013), `ring` ("Ring", VIZ-042) and `terrain` ("Terrain", WebGL wireframe, VIZ-043). Only the selected visualizer has a renderer: a switch disposes the old one and the WebGL canvas exists only in `terrain` mode (created lazily, removed on switch away); switching never rebuilds the audio graph and fades the canvas in over 150 ms (no fade with reduced motion). Status: implemented (not browser-verified)
- VIZ-041 MUST: Settings > Playback has the select "Visualizer height" (Small (1/6) default, Medium (1/3), Full; `localStorage` `ap2.viz.height`, validated, unknown values fall back to Small). The visualizer is half as tall as before (the earlier Small 1/3 and Medium 2/3 are now 1/6 and 1/3); the same scale applies in full-screen mode for the bars and the ring. The scale applies to the bar half-height (the bars stay centred on the horizon) and to the ring radius in both placements, and to the terrain canvas (its height and vertical centring) in the Playback background only: in the full-screen overlay Terrain always fills the whole viewport (canvas 100% wide and tall, the heightmap and camera use the whole canvas) whatever the setting. Status: implemented (not browser-verified)
- VIZ-042 MUST: the Ring is centred (in the Playback background on the cover), radius `RING_SCALE (4) x 30% of the smaller canvas dimension x height scale` (four times the original size; 20% of the smaller side at Small, but the clamp binds at Medium and Full; spokes, halo and dot rings scale with it), clamped by `ringRadius` so that the outermost dot ring (2.1 r, at the maximum bass pulse 1.08) never leaves the canvas: `r <= min(distance from the centre to the nearest canvas edge) / (2.1 x 1.08)`, which also holds when the cover anchor is off-centre; with the halo, dot rings and spokes; no bars. Status: implemented (not browser-verified)
Concept of Terrain in plain language (for designers): [terrain-concept.md](terrain-concept.md).

- VIZ-043 MUST: Terrain uses `viz-terrain-math.js` and `viz-terrain-gl.js`. Geometry: a rigid landscape of relief that travels toward the camera at a constant world speed (`WORLD_SPEED` 5.5 units/s). Rows are uniformly spaced in world z over a 40-unit depth (`rowZ`), the grid has a CONSTANT world width (`gridHalfWidth = WIDTH_PER_ASPECT x clamp(aspect, 0.4, 3.6)`, no flare; `WIDTH_PER_ASPECT = tan(32.5 deg) x 0.9 x GRID_DEPTH x 1.1` = 25.4, derived from the frustum half-angle at 90% of the depth with a 10% margin) so the outer columns lie beyond both screen edges at every visible depth from the bottom edge to the far fade (no dark sides, aspects 0.46 to 3.5, pinned by a test) while real perspective still makes the long depth lines converge toward the horizon and fan out toward the bottom edge; columns are uniformly spaced in x (`columnX` is linear, `COL_SHAPE` 1; owner request 2026-10-14, reference 14.webp) and the column spacing equals the row spacing in world units, so every grid cell is a square in world space at every height (a screen-space square only to the extent perspective allows; the nearest screen width holds about 25 / 44 / 74 cells at levels 0 / 1 / 2 at 16:9, see the level-of-detail tiers below); the far fade depends only on depth, never on x; and each vertex row holds one fixed data row that only slides in z (a continuous sub-row scroll `frac`; data rows are sampled at times aligned to the row spacing, so a ridge keeps its shape, no vertical smearing, no temporal aliasing, no per-row height damping near the camera, no swell). Heights: each row's amplitude is baked from that row's own spectrum when the row is sampled (`AMP_BASE + AMP_GAIN x energy of the row`, then a constant `u_amp`), so a row never re-scales with the live beat; the palette energy, glow and horizon are slow (1.2 s) followers and only the now slice (VIZ-047) pulses with the beat; peak height in world units is unchanged from the 2026-10-14 release. Camera: eye 3.31, pitch -13.5 degrees (owner-picked 2026-10-14; the baseline had 2.0 / -10), FOV 62, near plane 0.3, no drift. Bass camera shake and FOV breathing are kept in `cameraAt` but disabled (`SHAKE_ENABLED = false`); when enabled they move only the camera, never row heights. The data lattice (`QUALITY.spacing` 1.0 / 0.6 / 0.4 world units at level 0/1/2; `gridDims(level, aspect)`: rows = 40 / spacing + 1, cols = 2 x halfWidth / spacing + 1, both spacings widened together by 6% steps while rows x cols exceeds `GRID_MAX_VERTICES` 30000) holds the baked heights, landmarks, beat peaks and light factor exactly as before (the tag `terrain-liked-1` keeps the old 40x128, 64x144, 88x208 non-uniform grid). What is drawn is a level-of-detail mesh of square cells (owner request 2026-10-14, "cells too big"): `lodTiers(level, aspect, nowZ)` returns depth tiers whose cell size doubles with distance, `QUALITY.cell` x 2^k with `cell` = 0.35 / 0.2 / 0.12 world units at level 0/1/2 (about 74 cells across the screen at the bottom edge at 16:9, level 2, was about 10); tier k ends at `sqrt(spacing x LOD_ROW_PX 900)` world units (so a row line stays at least about 3 px apart on screen and the far grid does not alias into moire), tiers beyond spacing `LOD_MAX_SPACING` 1.4 or past 90% of the depth run to the far end; level 2 at 16:9 is 0.12 (0-10.4 units), 0.24 (to 14.7), 0.48 (to 20.8), 0.96 (to 40), level 1 is 0.2 / 0.4 / 0.8, level 0 is 0.35 / 0.7 / 1.4. Tiers cross-fade instead of switching: tier k's mesh reaches `LOD_BLEND_CELLS` (3) coarse cells beyond its nominal range on both sides (`zA`, `zB`, `fade`), its lines fade in over `z0 +- 3 x spacing` and out over `z1 +- 3 x next spacing` in the vertex shader (`u_tf`), the column grids are nested (odd counts, multiples of the spacing from x = 0, spacings double) so the shared lines stay at full strength while the in-between lines fade out, bead noise is hashed from the world column so a shared line has the same look in both tiers, and a line's alpha also fades smoothly to 0 as its on-screen column pitch falls from 3 px to 1 px (`u_cell`, `u_focal`); relief flattens to ground over the last 20% of the depth (`FAR_FLAT_START` 0.8, vertex shader) so the far edge fades into the horizon without a comb. Each tier is its own mesh of exact squares (dx = dz = spacing, odd column count, symmetric) and only as wide as the camera footprint at its far end (`tierHalfWidth` = min(`gridHalfWidth`, tan 32.5 deg x aspect x 1.1 x (zEnd + 2)), a trapezoid made of steps; pinned by a test for every tier); neighbouring tiers overlap by at most two rows (no gaps). Tier rows hold fixed absolute times (`jz0`, `baseT`, `fracT`, so a ridge slides rigidly and the bead noise stays on its row) and their heights and light factors are resampled from the lattice on the CPU each frame with a separable Catmull-Rom kernel (`resampleTier`, about 0.3 M multiply-adds, clamped to [0, 1] and [-1, 1]), so the per-frame height and beat-peak cost stays that of the lattice. Vertex budget at 16:9: level 2 about 31000 grid vertices in 4 meshes (62000 ribbon vertices, 16-bit indices because every mesh stays below 32767 vertices; no `OES_element_index_uint` needed), level 1 about 19000, level 0 about 10000; each mesh is capped at `GRID_MAX_VERTICES` (a very wide aspect widens that tier's cells by 6% steps); about 2 ms of JS per frame at level 2 in a desktop browser; the meshes are rebuilt when the aspect changes the counts, heights are smoothed with two [1,2,1] passes, columns map monotonically from low (left) to high (right) frequency, no mirror. Lines: level 0 draws crisp 1 px lines; levels 1 and 2 draw soft ribbons (screen-space quads, gaussian-ish alpha across the line, beaded brightness noise per line and per vertex tied to the data row so it travels with the relief, a depth-of-field widening and dimming toward the near and far ends; level 2 adds the half-resolution bloom). Cells versus long lines: depth lines are drawn at every height, cross lines only above about half a world unit (`crossAlpha`, smoothstep `CROSS_H0` 0.4 to `CROSS_H1` 0.6 on the displayed world height), so flat ground reads as long ribbons and raised ground as a square grid. Look (post-baseline, reference image 13.webp): intersections are brighter than the segments (dots `u_pt` 3 px, `NODE_GAIN` 1.6, soft round glow, lines slightly dimmer; drawn at every quality level); directional light from the upper right slightly behind the viewing direction (`LIGHT_DIR`, `LIGHT_GAIN` 1.6): `fillLight` computes a per-vertex signed light factor from the displayed heights (slope across columns over a +-2 column span with a minimum 0.5 unit baseline, and across rows; flat ground is 0, faces toward the light up to +1, faces away down to -1; `lightFactor`), the shader brightens lit faces with a `pow(l, 1.5)` falloff plus a blue tint and dims faces turned away by 0.4 x l; the factor depends on row data only, so it is rigid and does not pulse; height fog (`fogDensity(depthFrac, worldHeight)`: smoothstep `FOG_NEAR` 0.15 to `FOG_FAR` 0.95 of the depth, `FOG_LOW_MIN` 0.35 floor rising to 1 in valleys below `FOG_H0` 0.3 to `FOG_H1` 2.2 world units) pulls far and low lines toward the fog colour and dims them; a translucent dark-blue mist pass over the terrain (`QUALITY.mist` 0/1/2 octaves: off at level 0, one octave at level 1, two at level 2) drifts slowly (time only, slow energy follower, never the beat) in a band below and just above the horizon, denser toward the horizon (approximation: it is a screen-space band, valleys are veiled only by the per-vertex height fog); calm sky and ground are darker navy (near-black at calm). Also: bright dots at intersections, a dark navy calm state brightening with the slow energy, a background shader with sky, horizon halo and smoke, stars 40/90/150, only when WebGL is available (`detectCaps`), a failing `createTerrain` falls back to the Mirrored spectrum, context loss and restore are handled in the renderer, the vertex shader declares `precision mediump float;` like the fragment shader. Status: implemented (browser-checked with a synthetic timeline; not on real playback)

For a song whose audio is on the server (the player's same-origin `/files/<id>` URL) Terrain precomputes a spectrum timeline and shows the planned relief: the now row sits at a fixed depth about 30% of the way to the horizon (screen middle, `NOW_Z` = depth - 5 s x speed), the past comes toward the camera and the future (about 5 s, `LOOK_S`) recedes toward the horizon; beyond the end of the track and before its start the relief is flat. Orientation is the same as the live view (new relief appears at the horizon and flows toward the camera). The timeline is built by `viz-timeline.js`: fetch and `decodeAudioData` (on an `OfflineAudioContext` at the live context's sample rate), mono downmix, then per row at `ROWS_PER_SECOND` (16) a Blackman-windowed 8192-point FFT of the samples ending at the row time (the analyser's window), magnitudes smoothed 0.5 like `smoothingTimeConstant`, the SAME band mapping (`barsDb`, count = the live `barCount`, 20 Hz to 16 kHz log, max-pooled, +3 dB/oct tilt), the SAME 50 dB window with the slow global reference (`makeReference`), the SAME attack 0.6 and release 0.15 smoothing (`smoothBars`), then resampled to 64 bins and stored as bytes (about 1 KB per second of audio, so a 10 minute track is under 0.7 MB). Status: implemented (browser-checked on a generated tone with a real worker; not on a real song)

- VIZ-050 MUST: Terrain landmark ridges (post-baseline, not part of `terrain-liked-1`). The relief stays continuous; in addition one tall ridge appears every `LANDMARK_PERIOD_S` (5 s) on the loudest moment of each window. Windows are consecutive and anchored at song time 0 (window k = [5k, 5k+5)), so the landmarks depend only on absolute time and a seek shows the same ones. With the lookahead timeline (`timelineLandmarks`, cached per timeline and extended only for windows that are completely built, so a partial build never changes a result) the landmark of a window is its row with the highest `energyOf` (the same measure as the row amplitude; earliest row wins ties); a window whose best energy is not above `LANDMARK_MIN_ENERGY` (0.15) gets none (silence stays flat). A window whose chosen row has no clear peak (smoothed maximum column / mean column below `LANDMARK_MIN_PEAKINESS` 1.6, `rowPeak`; a flat spectrum) also gets none. A smooth neighbourhood of `LANDMARK_SPREAD_S` (0.25 s) each side gets a gaussian-ish weight w (1 at the landmark, 0 at the edge, `landmarkWeight`). The boost is baked into the row at height-fill time from the row's own time only (`frame.boost`, applied after smoothing in `fillHeights` with `bakeAmp`): the row's heights are multiplied by `1 + (LANDMARK_GAIN - 1) w` (`LANDMARK_GAIN` 1.8) plus `LANDMARK_BONUS` (0.4 world units) x w, then scaled so the row's tallest point never exceeds `LANDMARK_MAX` (4.5 world units; normal relief is 0..2.9); a row already above that is left alone. The boost is a PEAK, not a wall: it is multiplied across the row by a gaussian in x (`landmarkShape`, sigma `LANDMARK_SIGMA_X` 0.08 of the width, centred on the row's strongest smoothed column, clipped to 0 beyond 3 sigma), so columns far from the peak keep their normal height. rows stay independent and rigid while they scroll, and nothing pulses with the live beat. Live fallback (no timeline): the future is unknown, so a row gets its boost when it is created (`createSeries.push`): w = clamp01((e / m - 0.9) / 0.1) with e the row energy and m the running maximum of the current 5 s window (including the row), zero below `LANDMARK_MIN_ENERGY` and for a row without a clear peak (same peakiness test); so only rows within 10% of the window maximum so far are raised (approximation: a steadily rising passage raises several rows, the real peak is not looked for, and a window's landmark may sit before its true peak). When the timeline blends in, the boost blends with the heights. No debug controls. Status: implemented (unit-tested; not browser-verified)

- VIZ-052 MUST: beat detection (`viz-beats.js`), causal and deterministic. Per row: flux = mean over the lowest `BEAT_BINS` (32 of 64, about 20 Hz to 600 Hz) of the positive level increase against the previous row; a row is a beat when its flux exceeds `max(BEAT_MIN_FLUX 0.03, median + BEAT_MAD_K 3 x MAD)` of the previous `BEAT_WINDOW_ROWS` (16 = 1 s) fluxes, is a local maximum (decided one row later), and is at least `BEAT_MIN_GAP_S` (0.18 s) after the previous beat. Strength = `clamp01(flux / BEAT_FLUX_FULL 0.22)`; the beat keeps the elementwise max of its row and the next row as its spectrum. With the lookahead timeline `timelineBeats` extends a cached list over fully built rows only (same result for any build progress, seek, or replay); without it a live detector (`createLiveBeats`) runs on the pushed live rows and the two lists blend with the timeline blend (1 s). Status: implemented (unit-tested)
- VIZ-053 MUST: beat heights (`fillBeatHeights`), per frame for the visible rows, no baking: for row time T and now time t, `h(row, column) = min(cap, sum over beats b of A_b x S_b(column) x w(T - b.t) x env(t - b.t) x ahead(T))`. `env(a)` is 0 for a <= 0, a smoothstep rise to 1 over `BEAT_RISE_S` (0.15 s), then `(1 - x)^2` with x running 0 to 1 until `BEAT_DECAY_S` (5 s), 0 after; `w` is a gaussian time spread across rows (support `BEAT_SPREAD_S` 0.4 s); `ahead` fades rows beyond now (T > t) to flat over `BEAT_AHEAD_FADE_S` 0.1 s (the future stays ground). Height `A_b = BEAT_AMP_MIN 1 + (BEAT_AMP_MAX - 1) x strength^1.5` world units with `BEAT_AMP_MAX` = `LANDMARK_MAX` 4.5 (a typical beat of strength 0.6 is about 2.6; the sum is capped at 4.5); heights depend on (row time, now time) only through the age, so nothing pulses as a whole and a seek shows the same field. Cost: only beats within the last 5.4 s and the rows they touch, located by binary search. The now row is 12.5 units from the camera, so a peak is on screen for about 2.3 s (env is then still about 0.3). Status: implemented
