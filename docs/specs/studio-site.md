# Studio site

The Analyze and Synthesize tools as a public static site at https://studio.electrophone.cc ([ADR-0049](../tech/decisions.md), owner decision GR1, 2026-10-24, [task-0114](../tasks/task-0114.md)). The site is live (2026-10-24, task-0114 phases 1 and 2): Pages project `electrophone-studio`, custom domain `studio.electrophone.cc` with a proxied CNAME; the main app links and redirects to it and no longer has the two tabs (STU-016, phase 3, owner decision GU1, 2026-10-24). The tools themselves are specified in [web.md](web.md) (WEB-150 to WEB-202) and ADR-0048; this file says only what changes by moving them. Modify (the former Track tab) stays in the main app.

## Site and build

- STU-001 MUST: the site is static files (one HTML page, one hashed JS file, one hashed CSS file under `assets/`, the favicons, `_headers`, `robots.txt`) served by Cloudflare Pages (Direct Upload, project `electrophone-studio`) at `https://studio.electrophone.cc`; no server code, no API call, no sign-in, no cookie, no analytics, no third-party request. Status: deployed 2026-10-24
- STU-002 MUST: no module is copied. The entry (`studio/main.js`) imports the tool modules from `web/js`; `scripts/build-studio.mjs` bundles them with the esbuild version pinned for `build-web.mjs` (shared in `scripts/build-lib.mjs`) and writes `studio/dist/` (git-ignored, deployed from the PC by `scripts/deploy-studio.sh`). Status: deployed 2026-10-24
- STU-003 MUST: the look comes from the design system only: the stylesheet is `web/tokens.css` (generated from `docs/brand/tokens.json`), `web/style.css`, `web/studio.css` and `studio/site.css` (sidebar and layout, tokens only, no invented colour, size or radius), concatenated in that order; the page follows the system light or dark scheme and sets `<body data-route="studio">`. Status: deployed 2026-10-24
- STU-004 MUST: `index.html` has `noindex,nofollow`, `viewport-fit=cover`, a title "Electrophone Studio" (the tab name is added after it at run time) and the favicons of the main app (copied at build time from `web/`, not committed twice); `robots.txt` disallows everything. Status: deployed 2026-10-24

## Listen page

- STU-018 MUST (owner decision GX1, 2026-10-24, [task-0108](../tasks/task-0108.md), [task-0111](../tasks/task-0111.md)): `#/analyze/listen` ("Listen", the first Analyze item and the target of the `#/analyze` alias) is one `section.card` with a Start/Stop button for the microphone (no Source switch: the Player source is not offered, STU-009), a status line (`role="status"`, "Tap Start to listen" idle) and these blocks in order: Level (STU-019), Waveform (oscilloscope with a time-window selector: 40 ms, or 1, 2 or 4 cycles of the loudest tone, falling back to 40 ms while no tone is found), Spectrum (Linear|Log axis, the 2, 5 and 10 kHz range when linear, and the peak readout "Peak: 220 Hz (A3 +0 cents)" under it), Spectrogram (10 s) and Beat bands (Sub, Bass, Mids, Highs). Status: built; deployment noted in the changelog
- STU-019 MUST: the Level block is a dBFS meter: a big readout "xx.x dBFS" (RMS of the last 100 ms, "< -90 dBFS" at the floor), an RMS bar and a Peak bar over -90 to 0 dBFS (a scale line below), a "Peak hold" button whose text is "Peak hold: xx.x dBFS" and which resets the hold when clicked (the hold marks the loudest sample peak since Start or the last reset), and the line "dBFS is the digital level: 0 is the loudest the device can record; it is not dB SPL (room loudness), which needs a calibrated microphone." RMS follows the AES17 convention (a full-scale sine reads 0 dBFS, so a sine of amplitude 0.1 reads -20.0 dBFS on both bars); bars fall at 40 dB per second, rise at once. No dB SPL and no dB(A) is shown (task-0111). Status: built; deployment noted in the changelog
- STU-020 MUST: Listen takes the microphone as the lab did (WEB-190): `getUserMedia({ audio: { echoCancellation: false, noiseSuppression: false, autoGainControl: false } })` after the Start tap; one analyser (FFT 16384) behind a muted sink, so nothing is played back; it stops, and releases the tracks and closes the context, on Stop, on a route change (dispose), when the page is hidden, after 10 minutes and when the stream ends or the devices change, each with its own status message. Status: built; deployment noted in the changelog
- STU-021 MUST (single source of truth): the drawing and the stateful view builders are in one module, `web/js/listen-views.js` (waveform, spectrum with the peak readout, spectrogram, beat bands, the axis control, the level meter, the dBFS conversion and the feeder of analyser buffers), used by both `web/js/listen.js` (Listen) and `web/js/harmonics.js` (the lab uses the axis control, spectrogram and beat bands builders and the drawing helpers for its synth signal); `harmonics.js` re-exports the helpers it used to define, so the tests still import them from there. The microphone input (`createMicInput`) and the dormant Player input stay in `web/js/harmonics-input.js`. Status: built; deployment noted in the changelog
- STU-022 MUST: Listen keeps no state: no storage, no network, nothing recorded or uploaded ("Listens in this browser only. Nothing is recorded, uploaded or played back."); at 375 px there is no horizontal scroll. Status: checked locally at 375 px; deployment noted in the changelog
- STU-023 MUST (owner request 2026-10-25, "live bpm cant detect moby thousand", task-0073): the Live BPM card has a collapsed "Details" row (`details.mt-details`) between the badge row and the level meter; opened, it shows the microphone level in dBFS (RMS of the last block), the window length the engine used in seconds, and the top 3 BPM candidates with their score from 0 to 1 (`createLiveBpm().details()`, refreshed every 0.5 s only while open; "none" when silent or without a candidate). It changes nothing else: the badge, the meter and the state line are as before, and nothing is stored or sent. Code: `mic-tool.js`, `mic-bpm.js` (`details()`), `live-bpm.js`. Status: implemented, checked in the Browser pane with a fake 1000 BPM microphone
- STU-027 MUST (owner request 2026-10-25, [WEB-203](web.md)): the Spectrum on Listen and on Chordophones has a hover readout: a thin vertical line (the ink token colour) at the pointer and a small label with the frequency, the nearest note with cents and the level in dB (Chordophones snaps to a harmonic bar within 8 px: "H3 · 660 Hz"). It follows the current axis (Linear 0 to 2, 5 or 10 kHz, or Log 20 Hz to 20 kHz) through the shared `freqAt`, `specFreq` and `specX` in `web/js/listen-views.js`, redraws on every live frame and on `pointermove` when the view is static, and goes away on `pointerleave`, `pointercancel` and a touch `pointerup`. The canvas has `touch-action: pan-y` (in `studio/site.css`) so a vertical swipe still scrolls the page. No storage, no network, no animation. Code: `listen-views.js` (`specHover`, `drawSpecHover`, `trackHover`), `harmonics.js` (`drawSpectrumView`). Tests: `listen-views.test.mjs` (not run). Status: deployed 2026-10-25 (`d0e5b27`); checked in the Browser pane, 375 px included, with a fake 220 Hz microphone
- STU-028 MUST (owner request 2026-10-25, [WEB-205](web.md)): the Spectrum on Listen and on Chordophones has a "Trails" checkbox (default off, in memory only, no storage) in its header next to the Linear | Log switch. On, the spectrum keeps a fading ghost of recent peaks like a phosphor screen: a per-bin (Listen) or per-harmonic-bar (Chordophones) peak-hold buffer falling 40 dB over the trail length, drawn in the same colour at low alpha behind the live curve; the Linear and Log switch and a resize keep it aligned because it is stored in frequency space and mapped through the shared `freqAt` and `specX`. It is cleared when the source starts or stops, when the harmonic set changes and on every click of the checkbox. The caption gains one sentence while it is on. While it is on, a "Trail length" counter (the `stepper` helper; 0.5 to 10 s, step 0.5, default 2 s, applied live, kept in memory only) sits next to the switch; it is hidden when Trails is off. The glossary has "Trails (afterglow)" (see also Spectrum; "You can set how long the glow lasts."). No storage, no network. Code: `listen-views.js`, `harmonics.js`, `glossary-terms.js`. Tests: `listen-views.test.mjs` (not run). Status: deployed 2026-10-25 (`cb8a9b6`); checked in the Browser pane with a faked analyser, 375 px included
- STU-029 MUST (owner decision HB1 2026-10-25, [WEB-206](web.md), task-0107): the Spectrum on Listen only (not Chordophones, whose spectrum already labels H1 to Hn) has a "Mark harmonics" checkbox (default off, in memory only, no storage) in its header between Trails and the axis control. On, the page estimates the pitch of the microphone or player signal about 14 times per second (`detectPitch` in `web/js/pitch-detect.js`: YIN on the analyser time-domain buffer, 60 Hz to 2 kHz, a confidence from 0 to 1, nothing below -55 dBFS) and, at confidence 0.8 or more, draws small ticks with labels "H1", "H2", ... above the Spectrum at n times the pitch, for the harmonics inside the axis range (at most 16). A tick is solid when a real spectral peak (at least 6 dB above the bins around it and above -70 dBFS) lies within 3 percent of n times the pitch and hollow when it does not (a missing harmonic: a missing fundamental or an odd-only sound shows at once). Design tokens only (ink, muted), not the data colour; labels are skipped when markers are closer than 22 px, ticks stay. A readout under the Spectrum reads "Pitch: 220 Hz (A3 +0 cents), harmonics found: 1,2,3,5,6", "No single pitch (polyphonic or noisy sound)" or "Pitch outside the visible range"; it is hidden while the switch is off. The pitch is the median of the last 3 estimates; the markers fade out over about 300 ms when the pitch is lost. The hover crosshair snaps to a marker within 8 px ("H3 · 660 Hz"); Trails, Linear (2, 5, 10 kHz) and Log work through the shared `freqAt` and `specX`. The glossary has "Harmonic markers" and "Pitch detection (YIN)". No storage, no network. Code: `pitch-detect.js`, `listen-views.js` (`drawHarmonicMarks`, `harmonicBars`, `pitchText`, `createMarkControl`, `createLiveSpectrum`), `glossary-terms.js`. Tests: `pitch-detect.test.mjs`, `listen-views.test.mjs` (not run). Status: deployed 2026-10-25 (`8177b33`); checked in the Browser pane with a fake 220 Hz sawtooth microphone, 375 px included

## Glossary page

- STU-025 MUST (owner decision GY, 2026-10-25, [task-0114](../tasks/task-0114.md)): `#/glossary` ("Glossary", the only item of the menu group "Reference", below Analyze) is one `section.card` (`studio/glossary.js`, `mountGlossary`) titled "Glossary": a one-line intro, a filter box (`type="search"`, `aria-label` and placeholder "Filter terms…"; live: every typed word must occur in the term or its text, case-insensitive; a "Clear" button appears when it holds text and empties it), a `role="status"` line ("40 terms", "n of 40 terms", "No terms match.") and an alphabetical `dl` of terms (`div.gl-item` with `dt`, a definition `dd`, and a second `dd` with "See also" links to related terms and, where a page demonstrates the term, a link "<page> page →", e.g. Harmonic 1 to Chordophones). `#/glossary/<term-id>` opens the page, clears a filter that hides the term, scrolls the term to the top, focuses it and marks it (tinted background) until the next filter edit or another term; a click on a "See also" link does the same, also when the hash does not change. The Primitive page lost its two blocks "What do these mean?" and "Sound, tone, note: what is what?" and ends with the link "Terms: see the Glossary →" (`#/glossary`); the Chordophones lab keeps "What are harmonics?" and adds "More terms in the Glossary →" inside it. The captions under the views stay. Status: built; deployment noted in the changelog
