# Cut a time range when importing a track from YouTube or SoundCloud

> Alex: "when importing track from youtube/soundcloud - allow to cut a certain time", example https://youtu.be/HdR7uf2l7Ac (a long video of which only a part is wanted).

## Why

A link often points to a long video (a stream, a conversation, a mix, a live set) of which only one part is the song. Today the whole thing is a library entry with the full duration and the full audio.

## Proposed behaviour

- Add (and Edit) get an optional **Start** and **End** (`mm:ss` or `h:mm:ss`; empty = from the beginning / to the end). A link that carries a start time (`?t=85`, `&t=1m25s`, SoundCloud `#t=1:25`) pre-fills Start.
- The song keeps its source link and its original duration; a `clip` object `{start, end}` (seconds) is stored with the song (data model v2: next to `sources`/`audio`; legacy responses add nothing iOS must decode).
- Duration shown everywhere (Library, card, dock, stats) is the clip length when a clip is set.
- The Add dialog shows the cut as a small range control with a preview play button that plays only the cut from the original link (embed/seek) and the resulting length.

## Open questions (lettered for Alex)

- A. How is the cut applied to the audio? 1. Non-destructive: store the clip, keep the full audio on the server, players seek to start and stop at end (simple, reversible, wastes space). 2. Destructive: the iOS/server download trims with ffmpeg (`-ss`/`-to`, re-encode or stream copy) so only the cut is stored (saves space, no player changes, not reversible without re-downloading). 3. Both: trim on download, keep the clip range in metadata.
- B. Web playback of audio already on the server: honour the clip (start/stop, progress bar relative to the clip)? Default yes.
- C. Editing the clip after the audio was downloaded: allowed only with option A1 or A3 (re-trim from the source on the next download).
- D. Where do the iOS app and the server meet: `POST /songs` and `POST /download` accept `clip`; old clients that send none get the whole track.

## Acceptance (to refine when built)

- Parse and validate start/end (start < end <= source duration; `?t=` forms); clear error messages.
- Spec ids in docs/specs/add-song.md (form), data-model.md (`clip`), playback.md (honouring the clip), api.md; tests on both parsers.
- iOS contract unchanged for songs without a clip.

## Not in scope

- Several cuts from one video (one entry per cut for now; a later task could split a link into several songs).
- Fades and any editing other than start/end.
