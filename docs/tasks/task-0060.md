# YouTube video with time codes imports like a playlist

> Alex: create task md: when importing a YouTube video with time codes - act the same as when importing a playlist

Depends on: task-0058, task-0059. [task-0058](task-0058.md) gives the playlists, [task-0059](task-0059.md) the "create or extend a playlist" step, and the import table it reuses is specified in [add-song.md](../specs/add-song.md) ADD-150 to ADD-159.

## Today

Pasting a YouTube video link into the Add dialog opens the single-song form. A DJ mix, a full album upload or a compilation is one long video, so it becomes one song of an hour or more. The track list that its author wrote down as time codes (`00:00 Artist - Title`) is ignored.

## Proposed behaviour

- When the video has a **track list** (at least two time codes, see below), the Add dialog treats it like a YouTube playlist (ADD-150 to ADD-159): the time codes become entries in the same import table, and "Add N songs" saves the songs and a playlist.
- **Where the time codes come from**, first source that yields at least two entries wins:
  1. yt-dlp `chapters` metadata (the author's chapters; title and start/end are already structured).
  2. The description: one entry per line that starts with, ends with, or is wrapped in a time code. Accepted shapes: `00:00 Artist - Title`, `1:02:30 Artist - Title`, `[00:00] Artist - Title`, `(00:00) Artist - Title`, `00:00 - Title`, `1. 00:00 Artist - Title`, `Artist - Title 00:00`. Minutes may be one or two digits, hours optional, `:` the only separator.
  3. The top pinned comment of the video, parsed with the same line rules (many mixes keep the list there).
- **Trigger:** at least two time codes, in ascending order. One time code, or a description that mentions a time only inside a sentence, does not trigger.
- **Entries** (`start`, `end`, `title`, `artist`):
  - `start` is the time code in seconds; `end` is the next entry's start, the last entry ends at the video duration.
  - Artist and title go through the same parsers as the playlist import ([ADD-154](../specs/add-song.md)): `titles.split_title`, the version and bracket handling (ADD-159), the clean-up (ADD-077, ADD-179) and the credit split (`feat.`, `vs`, `x`, ADD-165). The video's channel is the fallback artist when a line has no "Artist - Title" (open question C).
  - Lines that are not a time code (intro text, links, "Tracklist:") are ignored; a time-coded line that cannot be read into a title is kept as a flagged row (ADD-158 style, "Could not read this line") so the owner can fix or untick it.
- **Import table:** the same table as the playlist import (ADD-151 to ADD-153): one row per entry, with a time range column ("12:34 to 15:50") next to the duration, ticks by default for rows that are not duplicates and not longer than 5 minutes (ADD-152; the rule uses the entry length, not the video length), "In library" for duplicates, flags for unparsed lines. Select all, Select none, the counter and "Add N songs" behave as in ADD-151.
- **Playlist:** adding creates or extends a saved playlist exactly as in [task-0059](task-0059.md): named after the video title, songs in time order, `source: {type: "youtube", id: <video id>, url}`. Re-importing the same video appends only the missing entries; the "Save as playlist" option and the editable name stay.
- **How an entry plays** (phase 1 and 2): the catalog entry of each song points to the same video with a start offset, `https://www.youtube.com/watch?v=<id>&t=<SECONDS>`. The song stores `source: {type: "youtube", id, start, end}`; no audio is cut. Where the web plays audio that is already on the server, an entry without its own audio plays from the original link at that offset and stops at `end` (open question A). Phase 3 adds a real segment for the iOS download.
- **Keep the single-video Add intact:** a video link with a track list shows a choice above the form, "This video has a track list: import N tracks" (primary) and "Add the whole video as one song". The second one opens the existing single-song form with no change. A video without a track list opens the form at once, as today, with no extra step and no delay beyond the details lookup the form already does.
- **Duplicates** are decided by video id plus start offset (the same video imported twice gives "In library" rows), then by the normalised title + artists + version match of ADD-153. A whole-video song and a track of the same video do not count as duplicates of each other.
- **Limits:** 200 entries per import (ADD-156), the playlist and quota caps of task-0058/0059. Guests and the public read-only view are unaffected (no import, ADR-0018). iOS later.

## Open questions

- A. How an entry plays: a catalog entry that points to the same video with `&t=SECONDS` and an end time, with no audio cutting in phases 1 and 2. **Recommended.** Alternative: cut the audio on the server with ffmpeg at import time (needs the whole audio first and the iOS download flow; large for a 2-hour mix). Which one?
- B. Where the time codes come from: chapters first, then the description, then the top pinned comment, first source with at least two entries wins, no merging between sources. **Recommended.** Alternative: also scan all comments (noisy, rate-limited, rejected).
- C. A line without "Artist - Title" (`00:00 Sunset`): title only, the artist is the video's channel, the row is flagged "Artist is the channel" so the owner can fix it before adding. **Recommended.** Alternative: leave the artist empty.
- D. Minimum number of time codes that triggers the track list: two. **Recommended.** Alternative: three, to avoid a false trigger on a video that mentions a start time and an end time.
- E. The whole-video option: always offered, as the second button of the choice. **Recommended.** Alternative: remember the choice per video id so a re-paste does not ask again.
- F. Duplicates by video id + start offset, not by the video id alone. **Recommended**, since the video id alone would block every later track of the same mix.
- G. Time codes that overlap or go backwards: keep the ascending prefix, flag the first out-of-order line and drop the rest of the list from the table. **Recommended.**

## Phases

1. **Parser and preview** (after task-0058 phase 1): a pure server module for the time-code lines (chapters, description, pinned comment) with a fixture file like `credit_title_cases.json`, the entries with `start`/`end`, and `POST /preview` (or a sibling endpoint) returning `trackList: {source, entries}` next to the usual preview so the Add dialog can offer the choice. Spec ids next to ADD-150 and in the API spec.
2. **Import table reuse and playlist creation** (after task-0059 phase 2): the choice "import N tracks / add the whole video as one song", the playlist-import view fed by the time-code entries (time range column, flagged lines), the songs saved as catalog entries with `source {type: "youtube", id, start, end}` and the `&t=` link, duplicates by id + offset, the playlist step of task-0059, playback from the original link at the offset in the web.
3. **Segment audio extraction for the iOS download**: the download of a track fetches only its time range (yt-dlp `--download-sections` or ffmpeg `-ss/-to`), so the phone holds a real file per song and plays offline (the key principle). The web stays catalog-only (ADD-053).
4. iOS and Mac import view later (needs Alex's permission to edit `ios/`).

## Acceptance (to refine when built)

- Spec ids in add-song.md (next to ADD-159) and api.md; server tests for the line shapes (`00:00 A - B`, `1:02:30 ...`, `[00:00] ...`, `00:00 - Title`, trailing time), the minimum of two, source priority (chapters, description, pinned comment), `end` of the last entry, ascending order and out-of-order lines, lines without an artist, and the single-video Add unchanged when there is no track list; web tests for the choice, the time range column and the duplicate rule by id + offset.
