# Auto-skip silence at the start and end of tracks (toggle)

Type: analysis first. No code until Alex answers the open questions.

## Context

Alex wants a toggle that skips silence at the beginning and end of tracks, so songs follow each other without dead air.

What exists today:

- One `<audio>` element plays every song from `GET /files/{id}` (PLY-003). When a song ends, `audio` `ended` calls `player.next(true)` in `web/js/player.js` (PLY-026). There is no gapless or crossfade logic.
- The Web Audio graph (`web/js/audio-graph.js`, used by the visualizer) already has an `AnalyserNode`, but only after the user starts it, so the player cannot rely on it.
- The server already analyses audio once per song: `server/app/bpm.py` decodes with ffmpeg to mono 44.1 kHz float PCM and aubio detects BPM. BPM is stored on the song, re-detectable per song (`POST /songs/{id}/bpm/detect`) and backfilled for the whole library (`/me/backfill/bpm`, WEB-070, `web/js/backfill-card.js`). Metadata has a second backfill (WEB-081).
- Audio state and `audio: {file, format, size, duration}` are derived at read time, not stored (DATA-030, DATA-031). Catalog metadata lives in the git store (DATA-032).
- iOS plays local files with `AVPlayer` and lock-screen info (IOS-040). `ios/` is read-only for this ticket.
- There is no play history or play-count feature in the specs, so "history and stats" below only needs to stay correct if one is added.

## Behaviour

When the toggle is on and the current song has analysis data:

- Start: on load, if `skip_start_s` > 0, seek to it before the first audible sample (no audible jump; set `currentTime` before `play()`).
- End: when `currentTime` reaches `duration - skip_end_s`, treat it as a natural end, i.e. call `player.next(true)` (same rules as PLY-026, including repeat one and the end of the queue). Repeat "one song" loops from `skip_start_s`.
- Never skip when the user seeks manually: a seek into the leading or trailing region plays from where the user put it; the end-skip only fires on natural playback progress, and only once per play.
- Previous restarts at `skip_start_s` (PLY-023 "restart" case).
- Do not cut a fade-in or fade-out: only digital silence or near-silence below the threshold counts, and a safety margin stays.
- Minimum track length: skip nothing from tracks shorter than 20 s; never trim more than 25% of the duration per side.
- Intentionally quiet or ambient tracks: the level is absolute (dBFS), not relative to the loudest part, so a quiet track is not trimmed unless it is truly silent; a track whose whole body is below the threshold gets no skip values.

Thresholds (defaults, server constants, tunable later):

| Parameter | Default |
|---|---|
| Silence level | -55 dBFS |
| Minimum silence length | 0.5 s |
| Safety margin kept | 0.15 s |

Only the first silent region touching the start and the last one touching the end count. Internal silence is never skipped.

## Options

### (a) Server-side analysis (recommended)

On download and upload the server runs one pass (ffmpeg `silencedetect` with `-af silencedetect=n=-55dB:d=0.5`, parsing `silence_start` / `silence_end` from stderr; or the same decode as `bpm.py` and a numpy RMS scan over 10 ms windows, which also gives the all-silent and ambient checks cheaply). Result is stored on the song as `skip_start_s` and `skip_end_s` (margin already applied). The player only seeks.

- Same behaviour on web and iOS, no runtime cost, works offline once the catalog carries the values (iOS caches the catalog).
- Editable and re-analysable per song, backfillable like BPM.
- Cost: one more decode per song (reuse the BPM decode so the file is read once), a new backfill job.

### (b) Client-side live detection (AnalyserNode)

Watch the level at the start and end of playback. Rejected: web only, the audio graph exists only after the visualizer starts, the end needs look-ahead buffering to know the rest is silent (flaky), no iOS parity, repeated work on every play.

Recommendation: (a). Reuse the BPM decode pass so the analysis adds near-zero I/O.

## Toggle

- Settings card "Playback", switch "Skip silence at the start and end of songs", per device (`localStorage` key `ap2.skipSilence`, `1`/`0`), default off. Not stored on the server, so guests can use it too.
- Quick toggle in the Now playing "..." / player menu if cheap (same key, same state; `aria-pressed`).
- Guests: allowed. It is a client setting; the analysis values come from the owner's catalog song objects, read-only.
- Songs without analysis (`skip_start_s` and `skip_end_s` absent) play normally. No error, no toast.

## Semantics

- Gapless: with the toggle on, the next song starts at its own `skip_start_s`, so the gap is the load time only. No crossfade is added.
- Shuffle and repeat: unchanged; the end-skip is just an earlier natural end. Repeat "one song" restarts at `skip_start_s`.
- Scrubber and durations: keep the real duration and real positions everywhere (seek bar, queue rows, song card). The seek bar may show a thin muted marker for each trimmed region while the toggle is on; if that costs more than a small CSS gradient, skip it (open question below).
- iOS lock screen (later parity): elapsed time stays the real `currentTime`; `MPNowPlayingInfoCenter` keeps the real duration.
- History and stats: count played time as actually played (skipped regions are not played). No history feature exists yet.
- Share links: a shared link opens the song; a timestamp in a link (if any) is honoured and never skipped; otherwise the start-skip applies for the recipient's own toggle.
- Toggle changed mid-song: takes effect on the next song; the current one is left alone.

## Data model

On the song's `audio` object (derived at read time like `size` and `duration`, DATA-031) or, because the analysis must survive and be editable, in catalog metadata beside `bpm` (decision for the implementer after reading DATA-030..031; the API shape is the same):

- `audio.skip_start_s` (float seconds, 0 or absent = none)
- `audio.skip_end_s` (float seconds of trailing silence to drop, 0 or absent = none)
- `audio.silence_analysis`: `{version: 1, at: <ISO date>, level_db: -55, min_s: 0.5, margin_s: 0.15}`

Rules: values are clamped to the per-side 25% limit; a re-download of different audio clears them; `PATCH /songs/{id}` accepts `skip_start_s` and `skip_end_s` (0 to 30, `null` clears) so Alex can fix a song by hand; a manual edit sets `version: "manual"` so a backfill never overwrites it. iOS contract fixture (API-133) gains the new optional keys on purpose.

## API and backfill

- `POST /songs/{id}/silence/detect`: re-analyse one song; 200 the updated song; 404 `unknown song` / `not downloaded`; 503 music root not configured (mirrors `/bpm/detect`).
- `GET|POST|DELETE /me/backfill/silence`: same states and error codes as `/me/backfill/bpm` (API-110..112); candidates are songs with server audio and no `silence_analysis`.
- Download and upload paths run the analysis after BPM; failure is logged and stored as no values, and never fails the download (as ADD-022).
- Settings card "Silence detection" under "BPM detection" (signed in, not guests): "N songs have audio but no silence analysis", button "Analyse missing songs", progressbar with a polite status line, Cancel, final message and library refresh; a new `web/js/backfill-card.js` instance, no new UI pattern.

## Accessibility

- The switch is a real checkbox/`role="switch"` with a visible label and 44px target; state announced; visible focus ring.
- Skipping is silent to the eye by default; a polite live-region message is not needed. If the seek-bar marker exists it is decorative (`aria-hidden`) and the real values stay in the song card.
- `prefers-reduced-motion`: no animation involved.

## Tests

Server (ffmpeg-generated fixtures, 44.1 kHz, a few seconds each):

- leading silence only; trailing silence only; both
- internal silence only (must give 0 and 0)
- all-silent file (no values, no crash)
- very short file (below the minimum length: no values)
- quiet ambient track above the threshold (no values); fade-in and fade-out tails (margin keeps them)
- manual edit survives a backfill; re-download clears values
- API: detect endpoint 404/503/200, backfill state machine, `PATCH` ranges, iOS contract fixture

Web (node tests): skip-start seek on load, end-skip calls `next(true)` once, manual seek into the regions is respected, Previous restarts at `skip_start_s`, repeat one, toggle off and missing analysis fall back to normal playback, guest playback honours the toggle.

## Risks

- Reverb tails and slow fades cut: level is absolute -55 dBFS plus a 0.15 s margin; the user can edit or clear per song.
- Live albums with applause: not silence, never skipped (fine).
- Hidden tracks after long silence at the end: the trailing skip would drop them; only the end silence counts and a hidden track makes it not "trailing" if audio follows. The risky case is a hidden track inside 25% of the end; the limit and the per-song clear cover it.
- DJ mixes and continuous albums: usually no silence, so no change; very long tracks (over 20 min) could have large silent gaps at the end, which skip handles.
- Wrong silence values causing lost music: mitigated by the margin, the 25% cap, manual edit, and the toggle defaulting off.
