# Genre history timeline: what came out of what

Alex's request: show a history timeline of music genres, what came out of what (rock from rock and roll, psytrance from goa trance). He asked whether this differs from the current genres map or is 90% the same. This task is analysis and a proposal only; no code until Alex approves. Related: [genres.md](../specs/genres.md), [genre-levels.md](../tech/genre-levels.md), [task-0035](task-0035.md), [task-0037](task-0037.md).

## Answer: not 90% the same

The Genres map (`genre-graph.js`, `genre-view.js`) and the rework map (`genre-radial*.js`, `genres-rework.js`) answer a CLASSIFICATION question: what is this genre a kind of, where does it sit (an is-a / belongs-to tree or graph, no time). The timeline answers a LINEAGE question: where did it come from and what did it give rise to (derived from, fusion of, revival of), on a TIME AXIS. Different data, different layout, different questions.

Classification and lineage disagree often:

| Genre | Classification (our taxonomy) | Lineage |
|---|---|---|
| psytrance | level 2, sibling of trance (GEN-056) | from goa trance (and trance, psychedelia) |
| rock | Discogs genre Rock | from rock and roll, rhythm and blues, blues, country |
| house | umbrella under Electronic | from disco, post-disco, Chicago scene |
| drum and bass | style under Electronic | from jungle, breakbeat hardcore |

Honest estimate: about 40-50% shared CODE, little shared DATA.

- Reused: Wikidata fetch, cache and rate limiter (`genre_graph.py`), graph loading and node selection, the owner's songs overlay and counts (GEN-053), search, ancestor highlight (GEN-043/044), names and display rules from `genre_levels.json`, design tokens, tooltip and panel plumbing.
- New: lineage data (`genre_lineage.json` and a source merge), origin years, the time-axis layout and lanes, curved lineage edges, timeline pan/zoom, the accessible list.
- Partly shared edges: Wikidata P279 (subclass of) covers some derivations but is mostly classification, and sometimes points the wrong way for lineage (see feasibility).

## Feasibility check (live APIs, 2026-10-16)

Five samples, Wikidata `wbgetentities` and Wikipedia raw wikitext (official APIs only).

- Wikidata P571 (inception) exists for all five, year precision only: rock and roll Q7749 1949 and 1950 (two values), rock Q11399 1948, goa trance Q835131 1991, psytrance Q622871 1992, house Q20502 1982. Good enough for a decade axis; the two-value case must be handled.
- Wikidata P279 is classification and often inverted for lineage: rock and roll -> rock (the older genre points to its descendant), goa trance -> psytrance, psytrance -> trance (Q170435), house -> Q851213, rock -> Q373342. Using P279 as "derived from" would draw rock and roll AFTER rock. It cannot be the lineage source.
- Wikidata P737 (influenced by) is empty on all five; P495 (country of origin) is present on all five (place usable). No stylistic-origins property was found on these items.
- Wikipedia genre infoboxes are the real lineage source: `stylistic_origins`, `derivatives`, `fusiongenres` and `cultural_origins` (decade and place) are filled for rock and roll (origin: rhythm and blues; derivative: rock), rock (origins: rock and roll, rockabilly, blues, electric blues, folk, country, R&B, jazz), goa trance (origins: trance, EBM, psychedelic rock, acid house, new beat, Indian classical; derivatives: psytrance, nitzhonot) and psytrance (origins: trance, psychedelia, goa trance). House has `stylistic_origins` EMPTY (a comment only), so disco, post-disco and Chicago scene need the curated file. Infobox values are wikitext with templates (`hlist`, refs), so parsing needs care; the text is CC BY-SA (attribute).
- Not checked: MusicBrainz genre relations (believed flat; verify in phase 1). Discogs has no lineage (known).

Result: the data exists, but only Wikipedia infoboxes carry lineage; Wikidata gives year and place; gaps (house, many electronic styles) need a curated file.

## Data model

Per genre node: `id` (GEN id, as the current graph), `label` (Discogs-authoritative name, display rules from the levels data), `year` with `year_precision` (year or decade), `place?`, `group` (the Discogs genre, for lane and colour), `year_source`.

Edge: `{from, to, type, source, confidence}`.

- `type`: `derived_from` (stylistic origin), `fusion_of`, `revival_of`, `influenced_by`. Direction is always older -> newer.
- `source`: `wikipedia-infobox:<page>`, `wikidata:<Pnnn>`, or `curated` (curated by Alex, per the no-invented-history rule).
- `confidence`: `sourced` or `curated`; conflicting sources are listed, not merged silently.

Source trust order: curated file `server/data/genre_lineage.json` (reviewed in git, like `genre_levels.json`; overrides and fills gaps), Wikipedia infobox, Wikidata P571/P495 for year and place. Wikidata P279 is not used for lineage. No scraping beyond official APIs; fetched through the existing cache and limiter.

## API sketch

`GET /genres/lineage` (guest-readable, like the vocabulary): `{nodes, edges, generated_at}` with a long cache. "Only my genres and their ancestors" is a client filter using the owner's `genre:<name>` tags (GEN-053). Alternative: add `lineage` to the vocabulary payload (heavier for every client; not preferred).

## UI sketch

- Horizontal timeline by decade, 1900s to now; lanes or colour by group (Discogs genre); genres are nodes at their origin year.
- Curved arrows for lineage; hover or select highlights ancestors and descendants (reuse GEN-043 selection logic); the rest is dimmed.
- Filter "only my genres and their ancestors" (default), plus search and song counts.
- Zoom and pan (reuse the radial map pan/zoom); same design system tokens, no new colours.
- Accessible alternative: a list grouped by decade with "from" and "led to" links, keyboard navigable; the SVG is not the only way in.
- Page location: see open question D.

## Test cases

- Server: infobox parser (hlist, bullets, refs, pipes, empty comment-only field, redirects); year parsing (two values, decade, circa); curated file validator (unknown keys, cycles, edge to a later year, missing source); merge precedence; no edge without a source or `curated`.
- Contract: every edge endpoint is a node; every node has a group; Discogs names win over Wikipedia names.
- Web: layout puts a node in its decade column; ancestor and descendant highlight on select; "my genres" filter keeps ancestors; nodes with no year go to an "undated" strip; list view equals the graph's edges.
- Sample fixtures: rock and roll -> rock, goa trance -> psytrance, jungle -> drum and bass, disco -> house.
