# Featured artists as credits and the Credit display setting

> Alex: featured artists are stored as credits (a separate Featuring / With role, never part of the stored title); a per-user Settings option chooses how titles are displayed: Apple / YouTube (default) or Spotify / MusicBrainz.

Rules: [credits.md](../specs/credits.md) (CRD-001 to CRD-054), WEB-104, DATA-162, DATA-163, API-148. Decision: [ADR-0036](../tech/decisions.md). Builds on [task-0043](task-0043.md) (data model v2, built, not deployed): the credit-title migration must run after `migrate_model2`, so this ships after task-0043 is deployed.

## Phases

1. **Parser and tests.** Extend `server/app/credits_split.py` and its twin `web/js/credits-split.js` (and the preview split in `titles.py`) to the forms of CRD-012 to CRD-015; write the shared case table `server/tests/fixtures/credit_title_cases.json` first (feat. / ft. / featuring, `&`, `x`, `vs.`, `,`, `with`, reversed title-first, remix with feat inside, noise, empty-title guard, "Defeat" and "5 ft tall"); both suites read it. Change ADD-075 and the Add form so the title is saved clean and Featuring is pre-filled. Built (not deployed, ADD-165): `server/app/credit_title.py` and `web/js/credit-title.js` with `credit_title_cases.json`, wired into the preview, the SoundCloud probe, the playlist import and the Add form (With pill field, combined suggestion row ADD-166); `withArtists` is stored minimally (DATA-168, API-165). Differences: "A with B" in the artist text is not read as With (CRD-011), and `credits_split.py` / `credits-split.js` were not extended.
2. **Credits storage.** `withArtists`, `version.brackets`, `legacyTitle` in the model, API, guest whitelist and form (Featuring and With pill fields, bracket kind in the Version block); derived `artist` appends With; `credits_schema` bump; contract test (`ios_contract.json`) stays green.
3. **Display function and Settings row.** `creditLine`, `titleLine`, `displayString`, `subtitleString` with the preset in `web/js/credits.js`, a table test of songs by preset (`credit_display_cases.json`); `creditDisplay` in user settings, `GET /me`, `PATCH /me/settings`; the "Credit display" row (WEB-104) with live re-render; every surface of CRD-039 (Library rows, Now playing, mini-player, song card, queue, Media Session, share pages, Stats).
4. **Migration.** `migrate_credit_titles.py` (CRD-050 to CRD-054): dry run on a copy of the live library, report, review file, backup, display-equality check; Alex verifies the review file and a sample, then `legacyTitle` is removed in a follow-up.
5. **iOS and macOS later.** Read `creditDisplay`, compose with the same cases (CRD-049); out of scope until Alex asks, and no `ios/**` change in phases 1 to 4.

## Test plan

- Parser table in both languages; idempotence (parse of a clean title is a no-op); round trip: composing the `spotify` display of a migrated song equals the normalised old display.
- Display table: every row of CRD-031 under both presets, legacy-only songs unchanged, no featured artists identical in both.
- UI: Settings choice persists across reload and signed-out viewers, all surfaces re-render, search finds a featured artist under both presets.
