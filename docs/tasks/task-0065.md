# Library filter and map highlight by genre modifier

> Alex (AY1): a Library filter and a map highlight by modifier, for example "dark" across all families, as a later task.

## Why

Modifiers (dark, progressive, deep, acid, hard, melodic, uplifting, vocal, minimal, tech, berlin, baltimore) are shared words that qualify different base genres: `dark psytrance`, `dark ambient`, `darksynth`; `progressive house`, `progressive trance`. Today they exist only in the vocabulary (`modifiers` block, kinds sound, mood and scene, ADR-0038); no genre entry carries a modifier list yet and nothing in the UI uses them. A filter by modifier would answer "all my dark songs" across families, which the genre tree alone cannot.

## Proposed behaviour

1. **Data:** attach modifiers to genres (`levels[genre].modifiers`, a list of modifier keys; the key is already served), derived from the genre name where the name contains the modifier word (progressive house -> progressive) and reviewed by hand for the rest (uncertain cases in the docs/tech/genre-levels.md 'Modifiers' section). A song's modifiers are the union of its genres' modifiers, computed on read, never stored on the song.
2. **Library filter:** a "Modifiers" chip group beside Genres, Years, Countries and Tags, grouped by kind (Sound, Mood, Scene); selecting one shows songs whose genres carry it; combines with the other filters as AND.
3. **Genres map highlight:** a Modifiers row in the filter area of the Genres map (the row exists, "Modifier", Sound, Mood and Scene groups): selecting a modifier highlights every genre that carries it across all families and dims the rest.
4. **Song card:** the modifiers of the song's genres as small muted chips under the genre pills (optional, decide when built).

## Open questions

- A. Is the genre name the source of truth (parse "dark psytrance" -> dark) or an explicit list per genre?
- B. Do mood-kind modifiers (dark, deep, uplifting) stay in the shared filter or only appear in the map?
- C. Scene modifiers (berlin, baltimore) also belong to the Tradition axis: one filter or two?

## Acceptance (to refine when built)

- Depends on the data change of the Electronic and groups work (ADR-0038 open decisions) only for names; it can start before.
