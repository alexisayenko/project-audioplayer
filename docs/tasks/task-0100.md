# Microgenre flag

> Alex (2026-10-24, CH1): yes, build the idea in phases; phase 1 is the candidate review.

A boolean `microgenre` on genres for very narrow, often internet-born styles (vaporwave, chillwave, witch house, sovietwave, darksynth, dreamwave), independent of the hierarchy level. A narrow style that Rate Your Music does not list as a genre but that is a real, distinct scene style stays visible as a flagged microgenre instead of becoming a full genre; the first candidate is `twilight psytrance`, now only a synonym of `full-on psytrance`. The flag is not a depth name, so decision AD (no "subgenre" or "microgenre" level names) is unaffected. Review and proposal: [microgenre-candidates.md](../tech/microgenre-candidates.md). Related: [genre-terminology.md](../tech/genre-terminology.md#source-policy-for-new-genres), [task-0065](task-0065.md) (modifier filter).

## Phases

1. 🔄 Candidate review: criteria, a table of 53 candidates with recommendations, and a proposal of what the flag does (documentation only; built 2026-10-24, awaiting the owner's review).
2. 🔲 After approval: data model (`microgenre` on `genre_levels.json` and `genres_v2.json`), API field, web UI (chip, map switch, picker), the source-policy clause, new names (twilight psytrance and others the owner approves), removals the owner confirms.
3. 🔲 Optional: Library filter "microgenres only / exclude".

## Open

The seven open points at the end of the review (policy exception for unattested styles, which rows get the flag, map default, names to check on Rate Your Music, dreamsynth versus dreamwave, UI label, drops).
