# Add selectable iOS color themes

Allow the user to choose a predefined app-wide color theme. Keep the current
Light/white theme as the default and add Dark/black as the initial alternative.
Structure theme resolution so more curated palettes, such as Vintage or Luxury,
can be added later without redesigning the selection and persistence model; do
not create those palettes in this task.

## Scope

- Add a theme choice in iOS Settings with clear names and a preview or swatch
  that makes each preset distinguishable.
- Persist the selected preset and restore it on launch. Existing installs keep
  the current Light/white appearance unless the user chooses another theme.
- Apply the selected theme consistently across the whole app, including sheets,
  menus, navigation, playback surfaces, and status-bar-adjacent content. The
  selected app theme takes precedence over the device's Light/Dark appearance.
- Resolve semantic design tokens through the selected theme while keeping
  components palette-independent. Avoid scattered theme conditionals in views.
- Ensure text, controls, selected states, disabled states, and focus indicators
  retain readable, accessible contrast in both presets; keep media artwork
  unchanged.
- Do not add arbitrary color picking or implement Vintage/Luxury in this task.

## Acceptance checks (not run; implementation pending)

- A fresh install and existing install without a saved choice launch in
  Light/white, matching today's default.
- Choosing Dark/black updates every screen and popup sheet immediately, survives
  app relaunch, and remains selected regardless of the device appearance.
- Switching back to Light/white restores today's appearance and remains
  selected after relaunch.
- Accessibility contrast is checked for text and interactive states in both
  presets, including VoiceOver and increased text sizes.
- Adding a future curated preset can use the same theme selection and token
  resolution architecture without view-by-view palette branching.

This task covers the iOS app only. Do not change the web UI or upload a
TestFlight build as part of the implementation unless separately requested.
