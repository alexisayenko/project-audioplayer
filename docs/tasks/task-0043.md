# Data model v2: naming, version block and artist table (one migration)

Requirements: [data-model.md, Data model v2](../specs/data-model.md#data-model-v2-final-model-approved-2026-10-16) (DATA-144 to DATA-155). Terminology: [ddex-terminology.md](../tech/ddex-terminology.md#words-adopted-in-data-model-v2). Background: [metadata-model-design.md](../tech/metadata-model-design.md).

## Context

The credits model (task-0036) shipped with names that drifted (`artists`/`featured`, `released`, `version.kind/year/by/of`, singular `album`, composite `raw`) and kept `decade:`, `lang:` and `country:` as stored tags. Alex approved one final model; this task renames, restructures and migrates in a single step so the data changes shape only once.

## The model

```
Song { id, title (base title only), mainArtists[], featuredArtists[],
       releaseYear (ORIGINAL recording; Wikipedia, MusicBrainz or Discogs only, never the upload date),
       albums[] (first = original album if known), genres[], tags[] (genre: prefixed tags only),
       version? { type: remix|cover|mashup|live|acoustic|extended|instrumental|remaster|edit|other,
                  name (credited text exactly as written),
                  artists[] (extra artists credited only on this version, e.g. a remixer; empty for covers and mashups),
                  releaseYear, originalArtists[] (one for a cover, several for a mashup) },
       sources[] { platform, url }, audio { state, bpm, ... }, rawTitle (original source title, never edited) }
Artist { name, countries[]? }   // keyed by name; no type, members or ids
```

- `decade:` tags removed: decade is computed at runtime from `releaseYear` (and `version.releaseYear` for the version).
- `lang:` tags discarded and no longer looked up. `country:` tags removed from songs, moved to the Artist table.
- Renames: artists -> mainArtists, featured -> featuredArtists, released -> releaseYear, version.kind -> version.type, version.year -> version.releaseYear, version.by -> version.artists, version.of -> version.originalArtists, album -> albums[], raw -> rawTitle.
- Derived legacy fields (not stored): `artist` (mainArtists joined + "feat." featuredArtists), `remixer` (version.name, else version.artists), `remix_year` (version.releaseYear), `year` (releaseYear), `album` (albums[0]), plus decade/country tag views while the API still exposes them.
- Rules that stay: no version means no version object; a cover's performer is a main artist; a remix keeps the original main artist and the remixer goes in `version.artists`; a mashup's makers are the main artists and the originals go in `version.originalArtists`; nothing about a source (ids, genres, albums, links, years) is applied to a version; parsing is only a suggestion (ADD-126 cover rule, mashup rule). MusicBrainz artist-credit override (DATA-142) and cover detection from the work (DATA-143) stay in task-0042.
- Deferred future direction (freeze BT1, not in this task): the nested chain/tree, separate Work and full Artist entities, full DDEX adoption and DDEX-aligned renames beyond `mainArtists`/`featuredArtists`/`version.type`. Reasoning in DATA-155.

## Migration plan

One idempotent startup migration, per user, after the credits migration, with a one-time backup like `backups-credits` (`backups-model2/<uid>/library.json`, outside the git-added tree); one git commit per user; `updated_at` untouched.

1. Input accepts old and new key names during a transition; output writes new names only.
2. Rename keys as listed; `album` string becomes `albums[0]` (empty string means `[]`); `raw` becomes `rawTitle` only after a check proves the derived legacy fields stay identical (else keep `raw` and list the song in the review file).
3. The dry-run on a copy of the live library asserts the derived legacy fields (`artist`, `remixer`, `year`, `remix_year`, `album`) are identical for every song before and after. Any difference aborts the real run.
4. Remove `decade:`, `lang:`, `country:` tags with a count report per prefix (dry-run and real run).
5. Build the Artist table from main artist names (no auto-splitting of ambiguous names). `countries` come from existing `country:` tags when the song has a single main artist; otherwise the country is listed in `backups-model2/review-artists-<uid>.json` and never applied.
6. Guest view: keeps `mainArtists`, `featuredArtists`, `releaseYear`, `albums`, `version`; drops `rawTitle`; Artist countries are public (shown on the info card).

## Impact

- API: new field names on songs; legacy derived keys still sent; new artist endpoints (read, edit countries). Old names accepted on input during the transition.
- iOS: reads only derived legacy fields. `ServerSong` (`ios/Sources/ServerLink.swift`) decodes `id, title, artist, album, remixer, year, duration, cover, tags, bpm, source_url, wikipedia_song, wikipedia_artist, musicbrainz_url, added_at, audio_state, sources`; `Track.swift` mirrors them. Note `album` and `tags` are decoded, so `album` stays a derived key and the tag views must keep working. No code change expected; verify with the contract test (`server/tests/fixtures/ios_contract.json`, `always_present`).
- Readers of decade/lang/country tags today (grep of web/js and server/app, non-test files; Library filters, stats, search chips, forms, Edit dialog, tag cloud, share links and the genres map go through them; re-check each at implementation):
  - web/js: `chip-field.js`, `countries.js`, `countries-data.js`, `genre-data.js`, `identify-plan.js`, `library-data.js`, `metadata-apply.js`, `song-card.js`, `song-form.js`, `stats-data.js`, `stats-table.js`, `tag-editor.js`, `tagname.js`.
  - server/app: `countrycodes.py`, `langcodes.py`, `discogs_lookup.py`, `downloads.py`, `genre_filter.py`, `genre_lookup.py`, `genres.py`, `identify.py`, `library.py`, `metadata.py`, `metafill.py`, `migrate_tags.py`, `wiki_lookup.py`.
- Specs to update: data-model.md, api.md, library.md, add-song.md, playback.md, tags.md, share.md, screens.md, metadata-model-design.md, ddex-terminology.md, CHANGELOG.

## Test plan

- Migration dry-run on a copy of the live library: zero legacy-field diffs, tag removal counts, review files.
- Contract test (`ios_contract.json`) and server API tests for old-input/new-output.
- Property tests: round trip old -> new -> derived legacy equals old; idempotence; tokens parity (Python vs JS).
- UI tests: Library filters and decade chips, stats, search chips, form and Edit dialog, info card countries, share links, genres map.

## Rollback

Old code cannot read the migrated file. Keep `backups-model2` until the release is verified; recovery is a forward fix (or restoring the backup and redeploying the old build, losing later edits).

## Implementation order

4. Display (card, info card, stats).
