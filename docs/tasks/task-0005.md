# Migrate the iOS app and web UI to the Electrophone design system

ADR-0009 makes the Design System artifact the single source of truth and
lands `DesignTokens.swift` + `web/tokens.css` as generated consumers. Nothing
uses them yet.

iOS (done, build verified on the simulator in light and dark; TestFlight upload not done):
- Replace `Theme.swift` tokens with `DS.Color` / `DS.Font` / `DS.Space` /
  `DS.Radius`; delete the walnut, chrome and piano-key code once no view
  references it.
- Rebuild `Components.swift` from the system's component READMEs:
  Transport tray, category Chip + FilterSheet, AddSheet, TabBar, SongRow,
  Button. Match the "Electrophone Screens" artboards (iOS page: Library,
  Library · Add sheet, Playback day/night, Settings, Library · Genres sheet).
- Three tabs: Library, Playback, Settings. Add is not a tab: a + button in
  the Library header opens the AddSheet (link → Fetch → preview → Save);
  the download then shows as "Downloading NN%" on the song's row.
- Library is the phone only: remove the Phone / Server switch, the server
  list view, "Download all", "Add all" and the per-row On iPhone / Download
  states (a row shows duration, or "Downloading NN%" while the file arrives).
  The server is the download pipe behind Add; its status LED lives on Add
  and Settings. `GET /library` stays for the web UI; the phone does not
  browse it.
- Library: four category chips (Tags, Genres, Years, Countries → plain,
  `genre:`, `decade:`, `country:`) opening a bottom sheet; `lang:` folds
  into Tags until a fifth chip is wanted.
- Playback leads with the cover: full-width square, title and artist ·
  album · year on a bottom gradient. No deck, platter, tonearm or LED
  (the `Turntable`/`Platter` views go).
- Day/night follow the system appearance; check 4.5:1 on every text/ground pair.
- New app icon from the system (Vega icon retired).

Web (the "Web" page of the Screens artifact: Library, Library · Add dialog,
Playback, Settings):
- Link `tokens.css` from `index.html`; rewrite `style.css` on its
  variables (`--ground`, `--surface`, `--accent-ink` …) and `.t-*` styles.
- Layout from the system's web components: Sidebar rail (Library,
  Playback, Settings; collapses to the tab bar under 480px), TableRow
  library, PlayerBar docked at the bottom of every page but Playback.
- "Add song" button in the Library header opens the AddSheet as a centred
  dialog; same category-chip filter + FilterSheet as iOS; Playback shows
  the cover with the queue beside it. The web library is the server's;
  no Phone / Server switch anywhere.

Web status (2026-10-13): done and verified in the built-in browser against a
fixture server (Library, Add, Playback, Settings; light and dark; 375px and
1280px). `tokens.css` is linked, `style.css` is rewritten on the variables, the
four-chip filter sheet replaces the tag row, and `web/favicon.svg` is a new mark
(the record on the platter, drawn by hand; the system has no vector mark yet).
Not done: live Google/Apple sign-in styling was not exercised (no credentials).

Done when no hex value remains in `ios/Sources` or `web/style.css` outside
the generated files.

Web v16 (2026-10-13): Alex judged the first web migration "an old design". The
web UI was rebuilt from the "Electrophone Screens" web artboards (version
1791839754-4134): three destinations (Library, Playback, Settings) with a 220px
rail, Add as a dialog opened from Library, a table Library with a "..." menu,
the player bar, a cover-led Playback with the queue card, and a card Settings
page. `docs/brand/tokens.json` was already identical to the design system, so
`tokens.css` and `DesignTokens.swift` did not change. Downloads continue as a
"Downloading NN%" Library row (`web/js/downloads.js`). Static assets are served
under `/_v/<version>/` (WEB-017). Contrast substitutions are in the style guide.
Not built: the artboard's favourite button, the Downloads settings card (audio
quality, format, covers, BPM; the server has no such settings) and the storage
card (the server reports no sizes; Settings shows song count, total time and
sync state instead). iOS must follow: three tabs, Add as an action on Library,
and the same substitutions.


iOS refresh (2026-10-13, artboards 1791841359-7b2e, design system 1791840724-5234):
the system's only token change is the `eyebrow` usage text (web only, never on
iOS screens), so `tokens.json` was exported and the generators re-run. The app
now follows the new artboards: no eyebrow, Playback without the status line,
tags/BPM block and volume row (a 300pt-high cover, seek bar, 56/64pt keys, Up
next with grip glyphs), a song sheet (Cancel / Song / Save) in place of the Edit
screen, Settings as Account / Storage (with "Remove all downloads") / Private
server, 36pt category chips, content-height Add, filter and song sheets (no
height jump when the keyboard opens), and the "+" wraps with the last tag pill.
Not built: the Downloads card and "Change cover" (no backing in app or server).
