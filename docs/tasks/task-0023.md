Scope decided by Alex (2026-10-14): phase 1 = mirrored spectrum bars plus radial ring, 2D canvas ("BE1"); placed both as a Playback background layer and as a full-screen mode. Details marked **(proposed)** are not decided; see [Open questions](#open-questions-for-alex). Web only; the iOS app is unchanged.

## Source analysis (reference clip)

`C:\temp\00_91c2bb18c7.mp4`: a stock 10 s audio-spectrum template, 1280x720, 24 fps, three layers:

1. Wireframe terrain (WebGL heightmap).
2. Radial spectrum ring.
3. Mirrored spectrum bars on a horizon, over a fog, star and lens-flare backdrop.

Palette: navy `#050a1a`, blue `#0a2a50`, cyan `#3a8fc0`, violet `#7a2cff`, magenta `#ff20c0` to amber `#ffb040`. Hard parts: heavy bloom, depth of field, scripted camera.

## Decision

- **Phase 1 (this task's scope):** mirrored bars (about 100-128, horizon line, mirror below the horizon, gradient) and radial ring (spokes around a disc, glow halo, concentric fading dot rings). Both on 2D canvas with additive blending and `shadowBlur` glow. Fog and stars: optional, cheap.
- **Phase 2 (later):** WebGL terrain from an FFT-history heightmap.
- **Phase 3 (later):** bloom post-process, scripted camera, colour drift by spectral centroid, per-song colour from the cover-art palette.

## Placements (both)

1. **Background layer** on the Playback screen, behind the cover and details; subtle and low contrast so text stays readable (text contrast unchanged over the layer, WCAG AA). Toggle in Settings "Visualizer background", default **off (proposed)**.
2. **Full-screen Visualizer mode**: a button in the Playback controls and the key `V` open it; `Esc` or a click on the canvas exits. A mini overlay (play/pause, next, scrubber) auto-hides after 3 s without pointer or key activity and returns on movement. Fullscreen API where available; on iOS Safari (no element fullscreen) a fixed full-viewport overlay.

## Technical design

### Audio graph (`web/js/audio-graph.js`, built once, shared)

`createMediaElementSource(audio)` -> optional `GainNode` (reserved for [task-0020](task-0020.md) volume normalisation, unity until then) -> `AnalyserNode` (`fftSize` 2048, `smoothingTimeConstant` 0.8) -> `destination`.

- The `AudioContext` is created and resumed on the first user gesture (iOS Safari); resume again on `play`.
- Audio is same-origin (`/files/{id}`, session cookie) so no CORS silence; guest mode uses the public stream, same origin, so the analyser works.
- `createMediaElementSource` cannot be undone and throws if called twice for one element: connect once, guard with a module-level singleton. The same module serves task-0020 so only one graph exists.
- Playback must keep working if the context is suspended or blocked (iOS background and lock): verify on a device; if sound dies when routed through the graph, route through it only while the visualizer or normalisation is needed and fall back to plain element output otherwise (decision after the device test; note the element cannot be un-routed, so this means the fallback is "never build the graph" on such devices).
- No Web Audio, or context blocked: the player plays as today and the visualizer shows a static idle frame.

### Modules

| Module | Role |
|---|---|
| `audio-graph.js` | singleton graph, `resume()`, `getFrequencyData()`, gain hook |
| `viz-spectrum.js` | pure math: bin to bar mapping, smoothing, bass average |
| `viz-bars.js` | draws the mirrored bars (one mirrored series) |
| `viz-ring.js` | draws ring, spokes, halo, dot rings |
| `viz-canvas.js` | canvas sizing, rAF loop, frame governor, visibility rules |
| `viz-fullscreen.js` | Fullscreen API with overlay fallback, auto-hide controls, `V` and `Esc` |
| settings wiring | `Settings` toggle, persisted via `storage.js` |

### Spectrum mapping (`viz-spectrum.js`)

- Resample the 1024 analyser bins to about 128 log-spaced bars, 20 Hz to 16 kHz.
- Per-bar smoothing with separate attack (fast) and release (slow); optional peak hold.
- Bass average (bins 0-8) drives the ring radius pulse and the glow strength.

### Rendering and budget

- `requestAnimationFrame` loop runs only while visible and playing; stops on `visibilitychange` hidden, off-screen (`IntersectionObserver`), route change and pause.
- 30 fps cap on touch and low-power devices (`matchMedia('(pointer: coarse)')` plus a frame-time governor that lowers bar count and glow when the average frame time exceeds budget).
- `devicePixelRatio` capped at 2.
- `prefers-reduced-motion: reduce`: visualizer off, static frame, short note in Settings.
- `prefers-contrast: more`: no glow, solid bars, higher contrast.
- Budget: below 8% CPU on a mid-range phone at 30 fps. Measurement plan: browser Performance panel, 60 s of playback per placement, record mean frame time and dropped frames, on one phone and one desktop.
- Colours only from design tokens (below); light and dark backgrounds both supported.

### Design tokens (never hand-edit `web/tokens.css`)

Read at runtime with `getComputedStyle`: `--accent` and `--accent-ink` (bars, ring), `--ink` and `--ink-faint` (idle, horizon), `--ground` and `--surface` (backdrop), `--glow-accent` (halo). The gradient (accent to a second stop) is two CSS variables in `web/style.css` derived with `color-mix` from the tokens; if the design needs a violet, magenta or amber stop with no token, add it to the Electrophone design system, re-export `tokens.json` and run `scripts/sync-design-system.py` (ADR-0009). The reference palette is inspiration only; no hex value is copied into code.

### Accessibility

- Canvas is decorative: `aria-hidden="true"`, not focusable.
- A visible "Visualizer" button with `aria-pressed` and an accessible name; `V` is ignored in inputs, dialogs and with modifiers (as PLY-090).
- WCAG 2.3.1 (no more than three flashes in any second): beat response is bounded by smoothing (release at least 150 ms) and a per-frame luminance-change cap; covered by a test.
- Full-screen overlay traps nothing: `Esc` always exits, focus returns to the opening button.

## Risks

- **iOS audio session quirks:** the context may suspend on lock or background, and routing the element through Web Audio may change background playback; mitigation: device test, resume on `play`, never build the graph where it breaks playback.
- **`createMediaElementSource` is irreversible** per element; design the singleton and the task-0020 gain hook together so there is one graph.
- **Battery:** continuous canvas drawing; mitigation: loop only while visible and playing, 30 fps, governor, background default off.
- **Seizure and flash safety:** beat-driven brightness; mitigation: smoothing, luminance cap, test, reduced-motion switch.
- **Canvas glow cost:** `shadowBlur` is expensive on low-end GPUs; mitigation: glow on a half-resolution offscreen layer or fewer glowing elements; the governor drops it first.
- **Volume normalisation interplay:** **(proposed)** the gain sits before the analyser, so the visual follows what is heard.
- **Playback beats features:** if a device shows playback regressions, the graph is removed from the default path (key principle).

## Phase 2 status (WebGL terrain, 2026-10-14)

Built, wired (one visualizer at a time: Mirrored spectrum, Ring, Terrain; segmented switch, key `M`, Settings mode and height; see visualizer.md VIZ-040..045), tested with a fake WebGL context, not seen on a real GPU. `docs/specs/visualizer.md` did not exist yet, so the terrain requirements live here (move them into the spec as `VIZ-1xx` when it lands).

### Terrain requirements

- Perf: at most about 8% CPU on a mid-range phone; GPU light: default 72x56 grid is 7936 line segments plus 4032 dots, DPR cap 2, one `bufferSubData` of a `Float32Array` per frame; bloom (half-res framebuffer, two blur passes) only at quality 2 and only if the framebuffer is complete.
- Fallback: no WebGL, shader compile or link failure, or `createTerrain` returning `null` gives the 2D bars and ring (`createModeRenderer` reports the effective `id`); modes needing WebGL are hidden by `availableModes(caps)`.
- Context loss: `webglcontextlost` stops drawing (default prevented), `webglcontextrestored` rebuilds programs, buffers and framebuffers; history is kept.
- Reduced motion: the renderer never animates itself; the caller draws one static frame and does not start the loop (same rule as phase 1).
- Flash safety: terrain brightness derives from the already smoothed spectrum; the camera shake is clamped (0.03 units) and the horizon glow lies in 0.35..1.

### Modules and interface

- `viz-terrain-math.js`: pure (ring-buffer history, height function, grid and index generation, colour ramp, camera path, mat4 helpers, row clock, seeded stars).
- `viz-terrain-gl.js`: `createTerrain(canvas, { quality = 1, gl?, onError? })` returns `{ resize(cssW, cssH, dpr), draw(spectrum, tMs), setQuality(0..2), dispose(), quality, lost, bloomActive }` or `null`. `spectrum` is the smoothed per-bar array in 0..1 (any length, resampled to 64 bins); `tMs` is the rAF timestamp in milliseconds. Also exports `isWebGLAvailable()`.
- `viz-modes.js`: `MODES`, `pickMode(saved, caps)`, `nextMode(id, caps)`, `availableModes`, `detectCaps()`, `MODE_STORAGE_KEY = 'ap2.viz.mode'`, and `createModeRenderer(id, canvas2d, canvasGL, { draw2d(spectrum, t), createTerrain?, terrainOpts? })` returning `{ id, usesGL, draw, resize, setQuality(governorLevel), dispose }`; it toggles `hidden` on the two canvases.

### Integration steps (done)

1. `index.html`: add a second `<canvas class="viz-canvas">` (WebGL, same size, stacked under the 2D one) in `#viz-full` (and optionally `#viz-bg-layer`); a WebGL context cannot share a canvas with a 2D context.
2. `viz-canvas.js` `paint()`: replace the direct `drawRing`/`drawBars` calls by a `draw2d(bars, now)` closure passed to `createModeRenderer`; call `renderer.draw(st.bars, ts)` with the smoothed `st.bars` (values 0..1, already produced by `smoothBars`); in `resize()` also call `renderer.resize(w, h, dpr)`; map the governor with `renderer.setQuality(gov.level)`; `settle()` (idle, reduced motion) calls `renderer.draw(zeros, 0)` once; `destroy()` calls `renderer.dispose()`. Add `setVizMode(id)` that disposes and recreates the renderer.
3. `viz-ui.js`: mode button (aria-label "Visualizer mode") and key `M` (ignored in inputs, dialogs and with modifiers) calling `nextMode(current, caps)`; label via `modeLabel`.
4. `viz-settings.js` and Settings: "Visualizer default mode" select from `availableModes(caps)`, persisted under `MODE_STORAGE_KEY` via `storage.js`; start with `pickMode(saved, caps)`.
5. Done: the wiring tests (`viz-canvas.test.mjs`, `viz-mode-ui.test.mjs`, `viz-terrain.test.mjs`); NFR-023 and screens.md describe the wired behaviour. Superseded: the combined modes (Bars + ring, Terrain + bars) were dropped; the mode list is Mirrored spectrum, Ring, Terrain.
