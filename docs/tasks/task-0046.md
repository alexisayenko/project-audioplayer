# Native macOS app with the web GUI

> Alex: a native macOS app whose GUI matches the web UI.

## What exists

Target `ElectrophoneMac` in `ios/project.yml` (XcodeGen, macOS 14, sources in `ios/MacSources/`, shared logic from `ios/Sources/`). Spec: [macos-gui.md](../specs/macos-gui.md); decision: ADR-0028.

- Shell: sidebar in the web's order (Playback, Playlists, Library, Genres map, Song stats, Music theory, Settings), account and server LED at its foot, bottom transport bar, sign-in sheet, toasts.
- Library: search, sort, filter sheets, rows, song card, Add and Edit through one shared form, download ring for server fetches.
- Playback: now playing page, queue, transport bar, media keys, Now Playing info, queue and volume saved in `UserDefaults`.
- Settings: account, library, Playback (Auto-download, which asks the server to fetch audio, as on the web).
- Playlists (the web's "coming soon" placeholder), Genres map (`Gen*.swift`), Song stats (`Stat*.swift`), Music theory (`Thy*.swift`): ports of the web pages, built 2026-10-17.
- Visualizer: Mirrored spectrum and Ring from an `MTAudioProcessingTap` (`MacAudioTap`, `MacVisualizer*.swift`), in-window overlay (V, M, Esc, dock key).
- Menu: Playback commands, Add Song (Cmd-N), page shortcuts; the dock title scrolls to the playing row.

## v1 decision: stream, no on-device download

The Mac plays from `GET /files/{id}` with the Bearer header (`MacPlayback.item(for:)`) and uses a local file only if one already exists. It never copies audio to the Mac: the catalog sync runs with `auto: false`, and "download" in the UI always means "ask the server to fetch the audio". iOS is unchanged.

## Open items

- No `DEVELOPMENT_TEAM`, so the app is unsigned (`CODE_SIGNING_ALLOWED=NO` builds only); no Mac app icon.
- Google sign-in may need a Mac OAuth client id; the server must accept the Mac client ids (API-007 audiences).
- Not built: visualizer Terrain/Synthwave, native full screen, style panel, share link, song info (the Library has no Song info), per-song download and save-file controls, BPM detection, metadata backfill, Genres map rework, real Playlists.
- Visualizer tap is unverified on the real server stream: it needs Range support on `/files` (works in a harness on local and Range-capable HTTP files); if no callback arrives within 3 s the key is disabled.
- The new pages (Playlists, Genres map, Song stats, Music theory) and the visualizer have not been seen on a real UI or run with real data.
- Genres map and Song stats each fetch `/genres/graph` separately.
- `ios/project.yml` declares explicit schemes `AudioPlayer` and `ElectrophoneMac` (XcodeGen otherwise listed only `ElectrophoneMac` in `xcodebuild -list`; TestFlight archives `AudioPlayer`).
- Builds, launches and stays up for several seconds; not tested with a real account, so sign-in, catalog sync, streaming, Add and Edit are unverified on the Mac.
- Known limit: v1 streams only; without sign-in (or the API token) nothing plays, and cued or restored songs get their stream token when first played.
