# Architecture and code design audit 2026-10-26

> Alex (2026-10-26): audit the architecture and code design, read-only, and say whether refactoring is needed.

Read-only: no source file was changed. Measured at `origin/main` `c982fbf5`. The refactorings below are proposals; none is a task yet. Alex picks phases, then each phase becomes its own task.

Method: acorn AST for `web/js` (function spans, import graph, cycles, top-level state), Python `ast` for `server/app` (function spans, import graph, cycles, exception handlers, duplicate function bodies by hash), `wc`/`grep` for Swift, CSS and scripts. ## Verdict

**No broad refactoring is needed.** The structure holds: no static import cycle among 298 web modules, one two-module cycle on the server (`genre_filter` and `genre_vocab`), the longest of 1,719 server functions is 54 lines, SonarCloud duplication was 0.7% on 2026-10-24, and my hash search finds only 5 duplicated function bodies on the server and 5 in the web (all under 10 lines).

**About ten targeted changes are worth doing**, in this order of value: the on-phone index (F1), silent empty-on-corrupt side files (F2), Swift ports without parity tests (F3), then smaller server and build hygiene.

## Recommended plan

Principle first: nothing in a phase may touch the playback path of a shipped build without a device check, and `scripts/check.sh` stays green after every commit.

**Phase 0, hygiene (S, no behaviour change).** F13 stray files and ignores, F12 doc numbers, F6 three dead shims, F11 dist check in `check.sh`. One commit each.

**Phase 1, reliability (offline and data first).**
1. F2 corrupt-file handling on the server (S). Ship and deploy first: it is the only data-loss path found on the server.
2. F3 step 1: shared fixtures and Swift XCTest for tokens, url-clean, tags (M). No production code changes.
3. F1 on-phone index (M), after the other `ios/` agents land and with F3's tests in place. Needs a TestFlight build and a check on a real device with airplane mode before it is called done.

**Phase 2, server structure (low risk, any time).** F14 `backgroundjob`, F4 layering fixes, F10 additive error key, F5 stray backups first then the migration runner one migration at a time.

**Phase 3, web.** F6 closure-only dist hash; F8 split flow functions as features touch them; subfolders only in a quiet window.

**Phase 4, retire legacy (needs the iOS release).** F7 credits compatibility layer and migrations model 2 and 3; F9 player rules and `Components.swift`. Owner decision, not a refactor: when ADR-0045 v1 genres (`genres-classic`, `genre-graph.js`) are removed.

## Do not refactor

- Server module layout, `deps.X` access, one router per area (ADR-0017); 26 flat routers are fine.
- Git sync: per-save local commit, timer push, single writer, `gitstore.py` (916 lines) (ADR-0026 to ADR-0028). Working, high risk, no measured problem.
- JSON-in-git per-user storage with whole-file rewrite; no database migration at this scale (500 songs per user).
- Committed `web/dist/` with its fallback (ADR-0047); no framework (ADR-0003).
- Studio as a separate site built from shared `web/js` modules (ADR-0049); do not copy modules.
- Genres v1 and v2 side by side (ADR-0045) and the Genres map renderers (force, radial, tree): large, tested, accepted.
- Mac target as its own native pages with its own `MacPlayback` (ADR-0029); no Catalyst, no web view, do not merge it into `PlayerService`.
- The iOS player core, AVPlayer, background audio and remote commands, while ADR-0043 and the other `ios/` work are open.
- Canvas, WebGL and Studio card factories for size alone (F8).
- `response_model` on every route (F10); one node process per web test file and test pruning (task-0121 owns it).
- Fixture-driven cross-language tests: keep, and extend (F3).
- The string-named `window` event bus and the `store` singleton.
- A deduplication drive on the server or web: the hash search shows nothing worth merging beyond F5 and F14.
