> Alex (decision GR1, 2026-10-24): only Analyze and Synthesize move to a separate public site, https://studio.electrophone.cc; Modify stays in the main app.

Phases 1 and 2 are done (2026-10-24): `studio/` and the build and deploy scripts exist, and the site is live at https://studio.electrophone.cc (Pages project `electrophone-studio`, also `electrophone-studio.pages.dev`). Decision: [ADR-0049](../tech/decisions.md); requirements: [studio-site.md](../specs/studio-site.md) (STU-001 to STU-016). Follow-up of [task-0072](task-0072.md) and [task-0106](task-0106.md).

## Findings (code)

- Analyze = `studio-tools.js` (`mountTools`) with `mic-tool.js`, `mic-bpm.js`, `live-bpm.js` and `harmonics.js` (plus `harmonics-input.js`, `audio-graph.js`, `viz-constants.js`, `viz-color.js`); Synthesize = `simple-tone.js`. All also use `dom.js` (imports `constants.js`) and `icons.js`. None imports `api.js`, `store.js`, `guest.js` or `storage.js`, and none calls `fetch`: they need no sign-in, API or library.
- Only two ties to the main app: (1) the lab's Player source reads `document.getElementById('audio')` and the shared graph (`createPlayerInput`; `available` is false without the element, but `harmonics.js` does not check it yet); (2) `mic-tool.js` `CAPTION` mentions the player. The Live BPM "hint to library BPM" (`det.setHint`) is only in `live-bpm-ctl.js` for the song card, not in Analyze.
- CSS: the cards use `style.css` classes (`card`, `btn`, `seg`, `slider`, `muted`, `t-*`) and `studio.css` (`hm-*`, `mt-*`, `sm-*`); tokens are system fonts, no web fonts. `viz-synth.css` and the other stylesheets are not needed.
- Build today: `scripts/build-web.mjs` (esbuild 0.27.7 in the system temp dir) writes the committed `web/dist/` with a SHA-256 manifest that `server/app/webbundle.py` checks; a second entry fits as `scripts/build-studio.mjs` writing `studio/dist/` (not committed, hashed names, no manifest, no server involvement). `css-linked.test.mjs` requires every `web/*.css` to be linked from `index.html`, so site CSS lives in `studio/`, not `web/`.
- The main app maps `#/studio/tools` and `#/studio/simple` to the Studio page (`app.js` route); the tab ids stay `tools` and `simple`.

## Findings (Cloudflare, read-only, 2026-10-24)

- Token file `~/.config/cloudflare/token.env` is mode 600 and verifies as active. The token cannot read its own policies (`GET /user/tokens/<id>`: unauthorized), so its permission groups cannot be listed.
- Zone `electrophone.cc` exists (Free plan, active; id in [deploy.md](../tech/deploy.md#cloudflare-protection)); DNS records read: yes. DNS edit: not testable without a write call, unknown. There is one account.
- Cloudflare Pages: read of the projects list fails with an authentication error, so the token has no Pages permission. Pages edit: no.
- No DNS record for `studio` exists yet.

## Decisions (owner accepted the recommendations, 2026-10-24)

- B. Player source standalone: shown disabled with the note "Player needs the Electrophone app" (STU-009).

- D. Mac app: the studio links open in the default browser (the web view still lacks the microphone handler, task-0113 phase 1); no Mac code change now.
