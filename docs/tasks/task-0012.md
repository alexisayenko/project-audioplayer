# P7: Apple Music links as a metadata source

First step: verify the facts below against current Apple/vendor docs before building; they come from memory and are unverified.

Facts (unverified): the keyless iTunes Search/Lookup API returns, for a `music.apple.com` song or album link id, title, artist, album, release date, genre, duration and artwork whose size can be raised by editing the URL.

Scope: server Apple Music client, `applemusic-<id>` metadata-only records (title, artist, album, release date to year, genre, large artwork, duration), preview with "No audio yet", Add accepts `music.apple.com` links on web and iOS through the same flow as Spotify; "Get audio" then proposes the YouTube match. Done when: pasting an Apple Music song link saves a metadata-only record with cover, no key is needed or stored, error cases show a clear message, and CAT-040..042 are implemented.

Depends on: task-0006, task-0007 (shared URL and preview parts). Specs: [`catalog.md`](../specs/catalog.md).
Order: after Spotify. Gate: ADR-0010 must be Accepted before code starts.
