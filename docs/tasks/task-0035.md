# Genre vocabulary and style level

A strict canonical `genre:` vocabulary (Discogs genres and styles plus a reviewed extras file) and a hybrid Genres outline (Discogs genre, Discogs style, Wikidata subgenres). Requirements: [tags.md](../specs/tags.md) (TAG-077 to TAG-084) and [genres.md](../specs/genres.md) (GEN-046 to GEN-050). Decision: ADR-0023 (accepted). Builds on [task-0033](task-0033.md). Planned; nothing built.

## Phases

1. Data and validator: build `server/data/genre_styles.json` (15 genres, about 550 styles, style to genre) from the Discogs Genres and Styles list (source, terms and refresh: TAG-084), and `server/data/genre_extras.json` (family and parent for each real genre Discogs lacks); validator tests (TAG-083).
2. Server: load the vocabulary once; reject out-of-list `genre:` writes with 422 and suggestions (TAG-079); check ALIASES and RETAGS targets; startup migration with the `genre-review.json` report for unmappable tags (TAG-082); retire `genre_families.json` in favour of the new files (GEN-038 step 1).
3. Web: genre picker with autocomplete in the song form and tag editor, no free text (TAG-080); hybrid outline with the style level and Wikidata nodes hung on their style (GEN-046 to GEN-050); GEN-036 kept as a fallback only.
4. iOS later: the same picker over the same list (served by the API or bundled), after the web ships.

## Open points

- Discogs source file: the help article lists genres and styles; confirm the exact page, its terms and whether a data dump is allowed before committing the list (TAG-084).
- Review of the extras file (about 25 entries to start) and of the unmappable-tag report after the first migration run.

## Steps

Per phase above; ship docs with each phase, flip this task to `done` when phase 3 is deployed (phase 4 then gets its own task).
