# iOS: structured music metadata fields

Split from [task-0036](task-0036.md) (Alex, 2026-10-21: iOS is a different scope). Needs Alex's permission to edit `ios/`.

## Context

The server and web store and edit structured credits ([ADR-0024](../tech/decisions.md), data model v2 in ADR-0025, [task-0043](task-0043.md)). The iOS app still works unchanged through the derived legacy keys (`title`, `artist`, `remixer`, `year`, `remix_year`; contract test `server/tests/fixtures/ios_contract.json`), but it shows and edits only those flat strings.

## What the iOS app must do

- Decode the structured fields (main artists, featured artists, first released year, version with kind, name, year, remix by) and show one display line built from them, like the web (ADD-111/112, LIB-134, IOS-072 to IOS-074).
- Add and Edit use the shared song form with the same fields as the web: Artists, Featuring, First released, Version (kind, name, remix year, remixed / mixed by, cover of), and the Suggested split with Apply and Dismiss.
- Keep sending the old flat names or the new structure the server accepts; never rewrite ambiguous credits silently; parsing stays a suggestion.
- Keep existing songs playable and the contract test green.

## Acceptance

- A song with a version and featured artists shows and edits the same credits on iOS as on the web.
