# Save queue as playlist

> Alex: Save queue as playlist - create a followup task

Phase 3 of [task-0058](task-0058.md) (decision F) and rule PLS-013. iOS "Save queue as playlist" is built (2026-10-26, not run on a device); the web is not built.

## Behaviour

- A button "Save queue as playlist..." in the Playback queue creates a playlist from the current queue, in its current order.
- It asks for a name. Default: the playing song's title, or the date when nothing plays. On a clash the UI suggests "Name (2)" (server answer 409 `playlist_name_taken`).
- The playlist gets the queue's song ids. Songs that are not in the library or have no id are skipped.
- It uses `POST /playlists {name, song_ids}`, already live (API-229 to API-238). Caps: 200 playlists per user and 2000 songs per playlist for non-owners; a cap error shows a toast.
- Success toast: "Saved N songs as playlist <name>" with an "Open" link to the playlist.
- The button shows only for signed-in users. With an empty queue it is disabled.

## Relations

- The queue toggle is "Add to queue" / "In queue" (done, PLS-128).
- "Play playlist" replaces the queue (done, PLS-123, PLS-124, PLS-139).
- The YouTube-playlist import also creates playlists ([task-0059](task-0059.md), done).

## Open questions (recommendations, not decisions)

- A. Where does the button live? Recommended: the queue panel header, next to "Clear".
- B. Does "Save" include the playing song and the already played part? Recommended: the whole queue as shown; played songs only if the queue view shows them.
- C. After saving, offer "Replace playlist" for an existing playlist? Recommended: not now.
