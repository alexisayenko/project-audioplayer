# YouTube playlist import creates or extends a playlist

> Alex: create task md: when importing a YouTube playlist - import all entries and create a playlist. If the playlist already exists - add to the existing

Depends on: [task-0058](task-0058.md) (playlists: the model, the API and the Playlists page). The import view it changes is specified in [add-song.md](../specs/add-song.md) ADD-150 to ADD-159.

## Today

The import view (ADD-150 to ADD-159) lists a YouTube playlist as a table of rows, ticks the rows that are available, not duplicates and not over 5 minutes (ADD-152), and "Add N songs" saves the ticked rows as catalog entries (ADD-155). The YouTube playlist itself is forgotten: nothing records which songs came together, and importing it again starts from scratch.

## Proposed behaviour

- Importing a YouTube playlist adds the entries to the library as today **and** creates a saved playlist ([task-0058](task-0058.md)) named after the YouTube playlist title, with the songs in the YouTube order.
- **Matching an existing playlist** is by the YouTube playlist id stored on it: `source: {type: "youtube", id, url}`. A playlist created by hand has no `source` and is never matched. A renamed playlist still matches by id.
- **Re-importing** the same YouTube playlist **adds** the entries that are not yet in the playlist: appended in YouTube order, no duplicates. Entries removed on YouTube are not removed from the playlist, and the playlist's own order is not touched.
- **Which entries go into the playlist** when some rows are unticked (over 5 minutes by default) or unavailable: the playlist holds every entry that is in the library after the import, that is the ticked new songs plus the duplicates matched to existing songs (ADD-153); unticked and unavailable entries are skipped. Open question A.
- **Opt out:** the import table gets a checkbox "Save as playlist" (default on) with an editable name (default: the YouTube playlist title). Unticked, the import behaves exactly as today. When a playlist with this YouTube id already exists the line reads "Add to playlist "<name>"" and the name field is replaced by the existing name.
- The playlist is created even when every entry was already in the library (the duplicates are referenced, no song is added).
- **Summary** (toast and the persistent line of ADD-155), for example: `Added 12 songs, 3 already in the library; playlist "Music. Synthwave": 12 added, 3 skipped (already in the playlist)`. A first import says `playlist "Music. Synthwave" created: 15 songs`.
- **Limits:** 200 entries per import (ADD-156); the playlist caps of task-0058 apply (200 playlists per user, 2000 songs per playlist for non-owners). A cap hit stops the playlist step with a message and leaves the already saved songs in place.
- Guests and the public read-only view are unaffected (no import, no playlists, ADR-0018). iOS later.

## Storage and API

- The playlist keeps `source: {type: "youtube", id, url}` (the field is added to the playlist model of task-0058, optional, null for hand-made playlists). Matching looks up `source.id` among the user's playlists.
- Preferably **one server call** for the playlist step, so the git sync makes one commit instead of one per song: `POST /import/youtube-playlist/playlist` with `{name, source, songIds}` (the ids of the songs that are in the library after the add step, in YouTube order). The server creates the playlist, or appends the missing ids to the one whose `source.id` matches, and answers `{playlistId, name, created, added, skipped}`.
- Alternative if the endpoint is not wanted: the web calls `POST /playlists` and `POST /playlists/{id}/songs` (task-0058) after the song creates; same result, two commits.
- Order of work in the web: songs first (ADD-155, unchanged), playlist step after the last song, so a failure in the playlist step never loses songs.
- Storage and caps follow task-0058 (`users/<uid>/playlists.json`, atomic, git-synced).

## Open questions

- A. Which entries go into the playlist: every entry that is in the library after the import (ticked new songs plus matched duplicates); unticked and unavailable ones are skipped. **Recommended.** Alex said "import all entries": the alternative is that the import adds ALL available entries with no selection step (over-5-minute songs included), then the table's ticks only decide what is added to the library. Which one?
- B. A hand-made playlist with the same name: create "Name (2)" and link it by id, never merge by name. **Recommended.**
- C. Keep the playlist in sync with YouTube automatically: no, only on re-import. **Recommended.**
- D. Entries that fail to be added (refused, over quota, unavailable): skip them, report them in the summary, leave them out of the playlist. **Recommended.**
