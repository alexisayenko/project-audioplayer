# Separate persistent queue playback from visible-song audition

Accepted design: [ADR-0043](../tech/decisions.md#adr-0043-persistent-queue-and-ephemeral-visible-song-audition), [playback requirements](../specs/playback.md#two-independent-playback-contexts-adr-0043) and [user journeys](../ui-ux/journeys.md#queue-playback-and-temporary-audition-agreed-target).

The decision and user flows are documented; implementation has not started.
Library and Song Details currently use the queue player, and Library Play replaces
its contents with the matching downloaded songs. The separate audition player,
simultaneous output and visibility/lifecycle stop rules do not exist yet.

## Implementation scope

- Preserve the queue player and its background, lock-screen and offline reliability.
- Give Library/Song Details a separate, single-song audition player with only Play/Pause; allow its audio to overlap the queue without changing it.
- Stop audition when its row/details is no longer visible, on navigation, locking, backgrounding or exit; never restore it automatically.
- Keep explicit Add to queue separate from audition; future Playlists can populate the queue.
- Bind dock state and queue actions to the queue; make row/details Play/Pause reflect audition, not queue state.
- Resolve the open points in the playback spec before implementing affected behavior: system control ownership, Play all matched and other existing queue commands, audio availability, audition resume, statistics and audio interruptions.

## Acceptance checks (not run; implementation pending)

- Audition A over queue B; both are audible, and queue position and sequence remain intact.
- Pause audition A; B continues. Pause B in the dock; A continues while visible.
- Start audition C; A stops, B is unaffected, C alone occupies audition.
- Scroll the owning row offscreen, hide it with filters, leave Library, open/dismiss details, lock or background: audition stops; queue remains independent.
- Returning/unlocking does not restart audition; downloaded queue playback remains available offline and signed out.
- Queue membership/status and audition Play/Pause never impersonate each other, including when both contexts use the same song.

Documentation records an agreed target, not a shipped feature; no code, TestFlight
upload or deployment is part of the documentation work.
