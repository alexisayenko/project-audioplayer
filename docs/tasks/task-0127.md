# Plan a native Android app

> Alex (2026-11-09): "Electrophone Android app, plan first".

Status 2026-11-11: accepted and built in source, not run on a device. Alex: "accept everything and do whatever you think is needed, create a new android app similar to the iOS app GUI". Phases 0 to 4 are written in `android/`: it builds (debug, and release with R8, unsigned), 411 JVM unit tests pass (shared fixtures, API with a mock server, downloads with a fake clock, playback rules, the form, Robolectric tests of the worker, the playback service and app start) and every screen was checked from JVM screenshots in day and night themes. Nothing has run on a phone or emulator: sign-in, WorkManager on a real OS, the Keystore, the notification, lock screen, headset, audio focus and all gestures are unverified. Phase 5 (release) is not started.

## Goal

The iOS app's job on an Android phone: pick songs on the server, get the audio onto the phone through the existing client-paced flow, play it offline with the screen locked, with the Electrophone look and the same account.

Key principle check ([CLAUDE.md](../../CLAUDE.md)): everything in v1 downloads, stores or plays songs; nothing else is in scope until v1 is verified on a device.

## What exists today (read 2026-11-09)

- Nothing for Android: no folder, no Kotlin, no Gradle, no Play or APK mention anywhere in the repo (`docs/ui-ux/style-guide.md` and `performance-guide.md` list Material 3 and the Android Studio Profiler as general references only).
- What the Android app reuses as it is: the server and its API (`GET /catalog` with ETag, `POST /songs`, `POST /songs/{id}/audio`, `GET /songs/{id}/status`, `GET /files/{id}` with Range capped at 768 KiB per request (API-318), `POST /plays`, `GET /me/usage`; API-007 Bearer tokens; ADR-0012 quotas); the data shapes on the phone (`library.json`, `phone-index.json`, `library.json.good`; song state `onServer` plus local file); `docs/brand/tokens.json` and `scripts/sync-design-system.py` (iOS and web outputs, the `platform` rule, `--check`); the web icon set `web/js/icons.js` (68 icons); the shared test fixtures in `server/tests/fixtures`; the iOS screens and rules as the reference ([ios.md](../specs/ios.md)).
- What the server needs: nothing in v1 (the web Google client id is the token audience); later one redirect endpoint for Apple sign-in on Android (AND-075).
- What Google Cloud needs: an Android OAuth client (package `com.alexisayenko.audioplayer.android`, the debug and release SHA-1) in the existing project.
