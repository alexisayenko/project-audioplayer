# Deploy POST /metadata to the live server

`POST /metadata` (API-048) merges yt-dlp, MusicBrainz and Wikidata into an album, a year and `genre:` / `country:` tags, and stops suggesting `lang:` tags in `/preview` and `/lookup/wikipedia`. It is on `main` (commit `a787c37`) but not on the server behind `https://play.isayenko.net`: `POST /metadata` answers 405 there (the static-file handler, no route), and the iOS "Get metadata" button in the Add form shows "Couldn't load metadata".

## To do

1. Deploy `main` and restart the server, the same way as task-0017.
2. Check the route exists: `curl -s -o /dev/null -w "%{http_code}" -X POST -H 'Content-Type: application/json' -d '{}' https://play.isayenko.net/metadata` must answer 401 (needs sign-in), not 405.
3. Run `cd server && python -m pytest -q` on Python 3.11+: `tests/test_metadata.py` (endpoint test), `tests/test_genre_lookup.py` and `tests/test_wiki_lookup.py` were checked only with `--noconftest` or `py_compile`, because the dev machine has Python 3.9 without `fastapi`.
4. In the iOS Add sheet: fetch `https://youtu.be/Tx9zMFodNtA`, tap Get metadata; Album, Year, Genres and Countries should fill without overwriting fields that already have a value.

Spotify is not used (decided 2026-10-13); languages are no longer suggested.
