# Share a song link at a time with a visualizer

## User story

As a listener I want to copy a link to a song that starts at a chosen moment, in the visualizer I picked, so that a friend opens it and hears and sees what I meant.

## Scope

- Web only. A Share link button on Playback and in the full-screen visualizer, and a "Share link" item in the Library row menu, open a dialog that builds the link.
- The link is a hash route: `https://<host>/#/play/<songId>?v=1&t=83&viz=terrain&style=single&bg=1&fs=1&cam=3.7,-13,0`. Specs: [share.md](../specs/share.md) (SHARE-001..SHARE-016).
- Opening a link loads the song, applies the shared visualizer settings for that visit only (the viewer's saved preferences are not overwritten), and shows a "Tap to play at 1:23" gate because browsers block autoplay. The same tap unlocks the AudioContext (VIZ-036).
- Out of scope, noted for later: iOS universal links (`apple-app-site-association`) so the link opens the app, link previews (Open Graph needs server-rendered HTML), short links, expiring links.

## Acceptance criteria

- [x] The dialog offers Start at current time, an editable mm:ss field, Open in full-screen visualizer, Include camera (only when the camera was changed in the vizdebug panel), a read-only link field, and Share (Web Share API when present) or Copy link; the confirmation "Link copied" is announced in a polite live region.
- [x] `buildShareUrl` / `parseShareParams` in `web/js/share.js` validate everything and clamp values; unknown parameters are ignored; no emails or tokens appear in the URL.
- [x] A link to a missing or invisible song shows "This song is not available" and stays on Library.
- [x] A song without server audio opens its catalog card with "No audio on the server yet".
- [x] Shared mode, Terrain style, background and camera apply to the visit without changing `localStorage` preferences.
- [x] `fs=1` opens the full-screen visualizer on the tap; keyboard operable, reduced motion respected, Electrophone tokens only.
- [x] Unit tests pass (`share.test.mjs`, `share-open.test.mjs`).

## Risks

- A link only works for people who can see the song: guests see the owner's library (ADR-0018), so a signed-in user's private song gives the recipient "This song is not available".
- A signed-out visitor with no public view lands on Settings and the link is dropped; they must open it again after signing in.
- Song ids are YouTube or SoundCloud ids, so a link reveals which track it is, nothing more.
- Terrain needs WebGL; without it the recipient falls back to the default mode, as for any saved Terrain setting.
- Not checked in a real browser or on a phone (Web Share sheet, native fullscreen after the tap).
