# Genre visuals in the Genre info panel

Waiting for the owner's decision FA (which option below). Nothing is built.

## The idea

The owner proposed adding an illustration to a genre's panel. The example was a mosaic-style Forest Psytrance image credited to Melodigging. That image is NOT usable: it is a third-party image, its licence is unknown, it looks AI-generated, and the repo is public. The Melodigging row of [genre-research-sources.md](../tech/genre-research-sources.md) records this.

## Options

1. Not now. The panel stays text only.
2. An optional image slot at the top of the panel, shown only when an image file exists for the genre; only images the owner owns or has a licence for. Recommended: it gives the owner's own images a place later and costs nothing for genres without one. Storage idea: files under `web/img/genres/` named by genre slug, served with the web, or a `genre_images` mapping; a licence and credit field per image.
3. A generated abstract header per genre, drawn in code from the family colour (no assets, no licence question, but no real illustration either).

## Constraints

- The panel is narrow (300 to 360 px) and scrolls as one block ([GEN-110, GEN-111](../specs/genres.md)).
- 535+ genres: any scheme must work with most having no image.
- Design tokens only; no colour, size or radius invented in code.
- The header must not push the reference tracks far down: max height about 96 to 120 px.
- The collapsed pill is unchanged.
- Dark mode must look right.
- Accessibility: the image is decorative (empty alt), the genre name stays the heading.

## Open questions for the owner

- A. Which option: 1, 2 or 3?
- B. For option 2, are there images the owner owns or has a licence for, and how many genres would get one at first?
- C. Credit line: shown under the image, or only in the data?

## Phases

1. 🔲 Decision FA.
