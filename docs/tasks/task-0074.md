# Show source links (Wikipedia, Discogs, Apple Music, Rate Your Music) for every genre

> Alex: every genre should carry sources and the UI should display links to them: Apple Music, Discogs, Wikipedia.

## Findings

The data and the server half already exist (GEN-066, ADR-0033): `server/data/genre_sources.json` stores the matched ids and titles, and `GET /genres/vocabulary` rows carry `sources` and `source_links` (`[{source, url, kind}]`, kind `page` = curated catalogue page, `search` = generated fallback), built only by `genre_source_links` in `server/app/genre_sources.py`. The web already parsed them into `node.sourceLinks` but nothing displayed them ("No UI yet"). No second `links` object is added; that would duplicate `source_links`.

## Done

- Server: Discogs now always has a link; a genre not in Discogs gets a plain release search for its name (`?q=<name>&type=release`, kind `search`) instead of none. Rate Your Music (rym, Alex 2026-10-21) comes only from the curated `server/data/genre_rym.json` (`{genre: url}`, kind `page`, empty for now: Alex supplies the URLs); no entry means no link is shown. Every genre has Wikipedia, Apple Music and Discogs links.
- Web: selecting a genre on the genre map shows a "Genre sources" row with Wikipedia, Apple Music, Discogs and Rate Your Music, opening in a new tab (`rel="noopener noreferrer"`); other sources (Spotify, MusicBrainz) stay in the payload and are not shown.
- Curated vs fallback: `kind: "page"` (Wikipedia article when matched; MusicBrainz) is curated, `kind: "search"` is a generated fallback. Apple Music is always a search (Apple genre pages no longer resolve).

## Open

- Apple Music is always a search link; real genre pages need a working Apple URL scheme.
- Alex supplies the Rate Your Music URLs; fill `server/data/genre_rym.json`.
