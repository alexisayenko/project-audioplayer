# P1: catalog data model, audio state and catalog sync API

Scope: `sources` list and nullable `file` in the song record; derived audio state `none` / `server`; `GET /library` returns records without audio; migration of existing files; update DATA-005. Done when: records without audio save, load and sync through the git store, old libraries load unchanged, server tests cover both, and CAT-001..005 are implemented.

Depends on: none. Specs: [`catalog.md`](../specs/catalog.md).
Gate: ADR-0010 Accepted 2026-10-13.

Delivered: no migration of existing records (state derived at read time, `file` absent still defaults to `<id>.m4a`, explicit `file: null` is metadata-only); `GET /catalog` (ETag, `since`); `POST /songs` with `audio:false`; `DELETE /songs/{id}/audio`; ids `spotify-`/`applemusic-`/`shazam-` accepted. Tests: `server/tests/test_catalog.py`, `test_gitstore.py`. Left for clients: web and iOS use `audio_state`, `/catalog` polling and the two deletes (CAT-005, CAT-030..033).
