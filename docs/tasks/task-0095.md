# Standard identifiers for songs: ISRC, ISWC, MusicBrainz ids

> Alex (2026-10-23): "for books there's ISBN, a guid for books; is there something like this for songs?" ... "just create a task md for now".

Analysis only, no code. Related: ADR-0024, ADR-0025, ADR-0039, ADR-0044; [task-0036](task-0036.md), [task-0042](task-0042.md), [task-0043](task-0043.md), [task-0083](task-0083.md), [task-0093](task-0093.md).

## Answer: yes, but music has several layers

Unlike a book, a "song" is two things (the work and its recordings) plus the releases it ships on, and each layer has its own identifier.

| Layer | Identifier | Notes |
|---|---|---|
| Recording | ISRC (International Standard Recording Code), 12 characters, e.g. `CC-XXX-YY-NNNNN` | Assigned by the label. One recording per code: a remaster, remix or live take gets its own ISRC. Closest thing to an ISBN for "this audio". |
| Work (composition) | ISWC (International Standard Musical Work Code), `T-123.456.789-C` | One per composition, shared by every recording and cover of it. The last digit is a check digit. |
| Release | UPC/EAN barcode, catalogue number | Identify an album, single or EP, not a track. |
| Open database | MusicBrainz ids (MBID): recording, work, release, release group, artist | Free, open API; one MBID per entity; links to ISRC and ISWC. The practical hub. |
| Other catalogues | Discogs ids, Spotify and Apple Music ids | Useful as links; Spotify is not used for now. |
| Audio fingerprint | AcoustID | Fingerprint resolves to a MusicBrainz recording. The app already has "Identify from audio" (AcoustID, Discogs). |

No single global "song GUID" exists; ISRC (recording) plus ISWC (work) is the nearest, and MBID covers both in one open namespace.

## Why it matters here

- Dedupe the same recording across sources (YouTube vs SoundCloud) without fuzzy title matching.
- Tell versions apart: in the version model (ADR-0024/0025) the recording is the version, so an ISRC or recording MBID maps to it naturally.
- Link covers and remixes to the original work (ISWC or MusicBrainz work).
- Reliable metadata lookup (credits, dates, genres) by id instead of search.
- Reference tracks (ADR-0044) match library songs exactly, no fuzzy matching.
- External ids for the Artist and Release entities (ADR-0039): artist and release MBIDs, Discogs ids.

## Proposed model (to analyse)

- Optional per song: `ids: { isrc?, mbid_recording?, mbid_work?, iswc? }`. Never required; a song without ids behaves as today.
- Per-source or per-release ids where they belong (for example release MBID, barcode on the release; a source URL stays a source).
- Filled by lookup (MusicBrainz via AcoustID, or by search on artist and title) or by manual edit in the Edit dialog.
- Shown in the song card as small copyable chips; hidden when empty.
- Validation: ISRC format (2 letters country, 3 alphanumeric registrant, 2 digit year, 5 digit designation; hyphens optional on input, stored without); ISWC format with check digit; MBID as a UUID.
- Be careful that one ISRC can legitimately appear on several releases, and a label sometimes reuses or mis-assigns one: treat ids as strong hints, not proof, until confirmed.

## Privacy and licensing

- MusicBrainz core data is CC0; the API allows about 1 request per second and requires a descriptive User-Agent with contact.
- Ids are public catalogue data, no personal data. Per-user libraries store them as part of the user's own song record.
- Discogs and AcoustID keep their existing keys and terms (see [deploy](../tech/deploy.md#identification-keys)).
