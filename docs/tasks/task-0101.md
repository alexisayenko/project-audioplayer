# Microgenre flag, phase 2: decisions and build

Follow-up of [task-0100](task-0100.md). Phase 1 (the candidate review, proposal of what the flag does) is in [microgenre-candidates.md](../tech/microgenre-candidates.md). Nothing is built until the owner answers the seven open points below.

## Open points from the phase 1 review (with the review's recommendation)

1. Policy: may an unattested but real scene style enter the vocabulary only as a flagged microgenre (twilight psytrance)? Recommended: yes, with the Wikipedia or two-source rule.
2. Which rows get the flag? The 22 "microgenre" rows are a proposal; the doubtful ones are low-confidence (nu-nrg, ghettotech, psybreaks, psydub, lowercase, illbient, spacesynth).
3. Map default: hide all microgenres, only those without songs in the viewer's library, or show them dimmed? Risk: 7 of the 8 synthwave children are candidates, so a hide-all default leaves synthwave almost empty. The review leans to a softer rule (hide only microgenres with no songs in the viewer's library, or dim them with the chip).
4. Names to check on RYM (the owner, since RYM returns HTTP 403 to automated fetches): list and instructions in [task-0102](task-0102.md).
5. dreamsynth: the same style as dreamwave (fold it, review recommends a synonym) or separate?
6. UI label: "Microgenre", "Micro" or "Niche"? (the review proposes a small chip; the word is never a level name, AD stays).
7. Drops: sunshine house, deep trance, worldbeat and vocal are existing names; removing them needs `REMOVED_GENRES` and a tag migration (one library song each for sunshine house, worldbeat and vocal). Confirm each. (psystep is only a new name, nothing to remove.)

## First candidate

`twilight psytrance`: RYM has no page of its own for it (the owner: a variant inside Full-On); today it is only a synonym of `full-on psytrance`. Proposal: its own level 4 genre under full-on psytrance with `microgenre: true`; the RYM name "night full-on" stays a synonym of it. No library song carries it, so no migration.

## Build plan (all after approval)

1. 🔲 Data model: optional boolean `microgenre` on `genre_levels.json` and `genres_v2.json`; validation (boolean only).
2. 🔲 API: `microgenre` (always served, `false` when absent) on `GET /genres/vocabulary` and `GET /genres/v2`.
3. 🔲 Web UI: chip on the genre card and in the picker, "Microgenres" switch on the Genres map (default per point 3).
4. 🔲 Docs: the source-policy clause in [genre-terminology.md](../tech/genre-terminology.md#source-policy-for-new-genres), the AD line, the new names and approved drops.
5. 🔲 Optional: Library filter "microgenres only / exclude" (with [task-0065](task-0065.md)).
