# Group genres by top-level group in the song card, Edit and Add

Status: the song-card grouping is built and deployed (LIB-158, `genreLines` in `web/js/genre-levels.js`). Not built: the grouping in Edit and Add, and a labelled "Other" line (genres with no place in the tree go on a final line without a family chip).

> Alex: "for genres: when you display them in the info card (view, edit, add), group genres per umbrella group; display each group on a separate line."

## Context and current behaviour

- Song card (`web/js/song-card.js`, `tagBlock`): the `Genre` tag group is one flat row of `tag ns` chips (plain `span`s, not links or buttons), labelled by `group-name`.
- Edit and Add (`song-form.js`, `token-field.js`, `chipField('genre')`): one flat token field; unknown genres are rejected with "is not in the genre list" (`genre-vocab.js`).
- Library row (`library-rows.js`, `genre-cell.js` `genreText`): flat comma list.
- Data: `server/data/genre_levels.json` gives each style `genre` (the top-level group: one of the 15 Discogs groups, e.g. Electronic, Rock, Pop), `parent`, optional `also_in_genres` (disco is also a node under Electronic), `display`, `status`, `provisional`. Loaded by `genre-vocab.js` / `genre-levels.js` (`buildTree`, `alsoIn`). The Genres map orders families by `FAMILY_ORDER` (`genre-data.js`).

## Rule

- Each genre tag is placed by `levels[style].genre`. A style listed under several groups (`also_in_genres`) appears in its primary group only.
- Tags not in the vocabulary (and provisional entries without a group) go to a last line "Other"; never dropped.
- One line per group: muted group label at the start, chips after it.
- Chip text is `display` (e.g. "psy-trance", "drum & bass").

## Decisions (proposed defaults; open questions for Alex)

- A. Order of group lines. Default: the group holding most of the song's genres first, ties by `FAMILY_ORDER`; "Other" always last. Alternative: always the fixed `FAMILY_ORDER`.
- B. Chip order within a line. Default: level 2 before level 3, then alphabetical. Alternative: order entered.
- C. Edit and Add. Default: the same grouped layout while typing; the token field renders grouped lines, a new tag jumps to its group on commit, order stable while typing (no reshuffle on each keystroke).
- D. Library row column. Default: keep the flat comma list; grouped only in card, Edit and Add. Alternative: group separators (for example `;` between groups).
- E. Badges. Default: approved/question badges only in the Genres map, not on chips in the card.

## Design notes

- Accessibility: each line is `role="group"` with `aria-label="Genres: Electronic"`; chips keep today's semantics in the card (plain text chips); token-field chips keep their remove buttons and keyboard behaviour.
- Mobile 360px: lines wrap; if the label is too wide, it sits above the chips. No horizontal overflow.
- Guests: same read-only rendering. Tokens only (WEB-010), no new colours or sizes.
- Performance: the levels are already loaded once with the vocabulary; build a style-to-group map once per vocabulary load; grouping is O(tags).
