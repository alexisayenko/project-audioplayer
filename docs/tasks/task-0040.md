# Now Playing queue GUI rework

## Context

Alex's request: (1) reorder queue items by dragging (vertical grip lines on the left as the handle) and drop "Move up" / "Move down" from the "..." menu; (2) drop "Edit song" from the "..." menu; (3) add an (i) button on each queue item that opens the song info card.

Read first: [playback.md](../specs/playback.md) (PLY-040, PLY-046, PLY-060, PLY-073, PLY-142, PLY-146), [web.md](../specs/web.md), [screens.md](../product/screens.md), [ios.md](../specs/ios.md) (IOS-033, IOS-041).

## Current behaviour

- `queueRow` in `web/js/player-ui.js` builds each `li.qrow`: position number, cover button (`row-cover.js`, PLY-073), title button (plays it) with artist line and download state, duration, and a "..." button.
- The "..." menu (`openMenu`, `web/js/menu.js`) holds, in order: Edit song (only with `can('edit')`), Download (song has audio and `can('download')`), Move up (disabled on the first row), Move down (disabled on the last row), Remove.
- Move up / down call `player.move(i, delta)`, which calls `Q.moveItem(qs, i, delta)` in `web/js/queue-logic.js`: a neighbour swap that keeps the current song current by identity (PLY-046). The list is rebuilt with `replaceChildren` in `web/js/player.js` after each commit.
- The song info card is `openSongCard(song, opener)` in `web/js/song-card.js`; the Library row and the Now playing "view" button already use it. Edit is reachable from the card.
- Since PLY-146 the transport is the standard mini-player dock; the queue card is the only place with row actions.
- iOS: the web queue is the reference; iOS keeps its own queue screen (IOS-041: jump, remove, clear; Song details in the Playback menu). Parity is a follow-up.

## New row layout

Left to right: grip handle (vertical grip lines icon, a real `<button>` with `aria-label` "Reorder: <title>"), position number, cover button (unchanged), title, artist and download state (unchanged), duration, (i) button, "..." menu.

- The "..." menu keeps Download (as today) and Remove. Removed: Move up, Move down, Edit song. (Play next and Add to playlist do not exist in the web queue menu today; out of scope.)
- Guests: no grip (read-only); the implementation picks the `can(...)` key that already gates queue edits and Remove follows the same key.
- Mobile (360px): the grip has a 44px touch target but a narrow look (icon about 16px); the position number may hide below 480px if the title would truncate; (i) and "..." keep 44px hit areas; the title uses the marquee (PLY-142); no horizontal scroll.
- Design tokens only (`web/tokens.css`); the grip and (i) icons come from `web/js/icons.js`; no new colour, size or radius.

## Drag and drop

- Pointer Events (`pointerdown`, `pointermove`, `pointerup`, `pointercancel`) on the grip only, `touch-action: none` on the grip so the page still scrolls and swipes work everywhere else; pointer capture on the grip. No HTML5 drag API (poor touch support).
- On pick-up the row gets a lifted style (shadow token) and follows the pointer vertically; a visible insertion marker (accent line between rows) shows the drop slot; other rows do not jump.
- Auto-scroll: within about 48px of the top or bottom edge of the scroll container (or viewport), scroll at a speed rising toward the edge; stops on drop or cancel.
- Keyboard: focus the grip; Space picks up (Alt+ArrowUp / Alt+ArrowDown moves one step directly without pick-up); ArrowUp / ArrowDown move the item one slot; Space or Enter drops; Escape cancels and restores the original position. Focus stays on the grip.
- Screen reader: a polite live region announces "Picked up <title>, position 3 of 12", "Moved to position 2 of 12", "Dropped <title> at position 2 of 12", "Reorder cancelled".
- Reduced motion (`prefers-reduced-motion`): no lift animation and no smooth auto-scroll; marker and result stay.
- Dropping where it started changes nothing and writes nothing.

## Queue semantics

- New pure function `moveTo(state, from, to)` in `queue-logic.js` (`moveItem` becomes a wrapper). The current song stays current by identity wherever it lands, whether the dragged row is the current song or crosses it. Playback is not interrupted and the audio element is not reloaded. Shuffle history and round, loop and tag chips are untouched; manual / tag-derived flags travel with the item.
- Persistence: `items`, `index`, `tags` are written to `localStorage` `ap2.queue` once on drop (not per hover step; PLY-060). The web queue is local to the browser, so there is no server sync; `syncLibrary` still removes deleted songs afterwards.
- The list is not fully rebuilt during a drag; focus and the in-place cover repaint (PLY-073) survive; one in-place reorder or rebuild after the drop.

## (i) button

- `info` icon button, `aria-label` "Song info: <title>", tooltip "Song info", between duration and "...".
- Opens the same card as the Library row via `openSongCard(song, opener)`; focus returns to the (i) button on close; Enter and Space work natively. Hidden when the song is unknown in the store.
- Edit stays reachable from the card, so removing it from the menu loses no function.

## Test plan

- Unit (`web/js/queue-logic.test.mjs` or new `queue-reorder.test.mjs`): `moveTo` up, down, first, last, no-op, out of range, single item; dragging the current song; moving an item across the current song from above and below; index follows by identity; manual and tag flags preserved.
- DOM tests with fake pointer events: pointerdown on the grip starts a drag, pointermove shows the marker at the right slot, pointerup commits once; pointerdown elsewhere on the row does not start a drag; `pointercancel` restores order; guests see no grip; auto-scroll tick near an edge.
- Keyboard test: Space pick up, ArrowDown twice, Enter drops at +2; Escape restores; Alt+ArrowUp moves one step; live region text for each step.
- Regression: after a series of moves the index still points at the playing song, Next and Previous continue from its new neighbours, and a reload restores order and index (PLY-060, PLY-061).
- Menu test: no Edit song, Move up or Move down; Remove present (Download when applicable). (i) opens the card and focus returns.
- Manual: 360px layout (no overflow, 44px targets), touch scrolling works away from the grip, reduced motion.
