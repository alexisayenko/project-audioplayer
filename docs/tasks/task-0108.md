# Studio Tools: analysis sources for the views

> Alex (2026-10-24): step 1 is only the synth; "the rest: create follow-up tickets".

Follow-up of [task-0106](task-0106.md). Waiting for the owner's answer to question FS. Nothing is built.

## Goal

Let the waveform, spectrum and spectrogram views of the harmonics lab show more than the synth.

## Scope

- A source switch **Synth / Microphone / Player** above the three views.
- Synth: the lab's own signal (step 1).
- Microphone: the live input. Its signal is analysed only and never sent to the speakers (no feedback); permission is asked on first choice.
- Player: the song that is playing, read from the visualizers' analyser (`getAnalyser()` in `web/js/audio-graph.js`, VIZ-001 to VIZ-005; same origin, so no CORS silencing). Playback is not changed.
- One small source interface (an `AnalyserNode` plus a state) so the views do not care where the signal comes from. Step 1 builds the views on that interface, which keeps this follow-up small.

## Relations

- Audio graph and analyser rules: [visualizer.md](../specs/visualizer.md). Its graph is created lazily on a user gesture and the analyser exists only while the context runs.
- Reused by the [note detector](task-0107.md) and the [spectrum analyzer tool](task-0112.md).

## Open questions (recommendations, not decisions)

- FS. Do Microphone and Player work as sources for the three views? The owner has not answered. Recommended: yes, both.
- A. Player when nothing plays or the visualizer graph is off? Recommended: a hint "Play a song" and build the graph on the click that selects Player.
- B. Is the source remembered across visits? Recommended: remember Synth and Player; Microphone always needs a tap.
- C. Player analyser settings (`fftSize` 8192, smoothing 0.5 are tuned for the visualizer)? Recommended: reuse as is, set per-view smoothing in the view.
- D. Spectrogram while paused? Recommended: freeze it, keep the last frame.
