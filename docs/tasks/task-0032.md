# Connect YouTube (import playlists and Liked videos)

Settings > "YouTube" card with Connect; Google OAuth; the user picks playlists (and Liked videos) and the server imports them as catalog songs without audio. Requirements: [youtube-connect.md](../specs/youtube-connect.md) (YTC-001 to YTC-053). Decision: ADR-0020 (accepted).

## Decisions

Decided 2026-10-16 (Alex; CX and CY delegated to the recommendation):

- CW, who may connect: owner only first (phase 3, all users, needs Google verification of `youtube.readonly`, stays future).
- CX, consent screen mode: Production, unverified (refresh token does not expire after 7 days, cap of 100 users, "unverified app" warning).
- CY, what an import leaves behind: songs plus an Electrophone playlist per imported list with Refresh (imports the diff).

## Open decisions

- CZ, the long-video cap (YTC-052, ADD-081). Options: 1. 300 s = 5 minutes (default, recommended); 2. another value; 3. owner-configurable setting.

## Phasing

1. Phase 1, owner only: connect, list, import with dedupe, progress and summary, Disconnect.
2. Phase 2: keep lists as playlists, Refresh imports the diff.
3. Phase 3: all users (Google verification) and the iOS app.

## Routes

`GET /yt/connect`, `GET /yt/callback`, `GET /yt/status`, `GET /yt/playlists`, `POST /yt/import` (+ `GET /yt/import/{job_id}`), `DELETE /yt/connect`.

## Owner prerequisites (Google Cloud Console)

1. Enable "YouTube Data API v3" in the project.
2. OAuth consent screen: User type External; add the scope `youtube.readonly`; publish the app (Production, unverified; CX).
3. Create credentials > OAuth client ID > "Web application" with the authorised redirect URI `https://electrophone.cc/yt/callback`.
4. Put the client id and secret into `/etc/audioplayer/env` on the server as `GOOGLE_YT_CLIENT_ID` and `GOOGLE_YT_CLIENT_SECRET`, `chmod 600`. Never paste them in chat, a repo or a doc.

## Steps

1. Decisions CW, CX, CY recorded; ADR-0020 accepted (2026-10-16).
2. Open: CZ (cap value).
3. Server: `ytauth.py` (state, token exchange, Fernet store, revoke), `ytimport.py` (paging, cleaning, dedupe, caps, job), `routes/yt.py`; env keys in deploy docs.
4. Web: Settings "YouTube" card, checklist, progress, summary (`web/js/youtube-connect.js`).
5. Docs in the same commits as the code: `api.md` (routes, errors), `web.md` (card), `deploy.md` (env vars `GOOGLE_YT_CLIENT_ID`, `GOOGLE_YT_CLIENT_SECRET`, secrets directory `/var/lib/audioplayer/secrets`), `terminology.md` ("Connect YouTube", "Liked videos", "imported list"), CHANGELOG.

## Acceptance checks

- Connect from Settings returns to Settings with the card showing Connected; the refresh token file exists at `/var/lib/audioplayer/secrets/<uid>.json`, mode 0600, content not plain text, absent from the data repo and the logs.
- A tampered, expired or foreign `state` is refused (400 `bad_state`).
- The checklist shows the user's playlists and "Liked videos" first.
- Importing a list with a duplicate, a private video and a deleted video reports the right added, skipped and duplicates counts; a second import of the same list adds nothing.
- An import that would pass 500 songs stops at the cap and says so (non-owner).
- A metadata-only import does not touch the hourly add counter.
- Disconnect revokes at Google, deletes the file, and Connect works again.
- A non-owner and a guest get 403 and 401.

## Test plan

Server tests against a fake Google (a local HTTP app standing in for `accounts.google.com`, `oauth2.googleapis.com` and `www.googleapis.com`, set through `GOOGLE_OAUTH_BASE` and `YT_API_BASE`): state signing and expiry, code exchange, refresh and `invalid_grant`, encrypted storage and file mode, revoke failure still deletes, paged playlists, `LL`, private and deleted placeholders, Topic channel cleaning, dedupe on video id across lists, cap and hourly counter behaviour, quota error mapping, token never in logs (caplog check). Web tests for the checklist, progress and summary rendering in `web/js/*.test.mjs`. Real-account check by the owner after deploy.

## Risks

- Unverified-app warning and a 100-user cap; verification (phase 3) needs a privacy policy and a demo video.
- The YouTube Music private library is not available through the API.
- A long import ties up one background job; the git write per batch of 50 keeps commits few.
