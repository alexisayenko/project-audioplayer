# Split long tracks into songs by time

Type: analysis first. NO code changes until Alex approves the analysis below.

## Context

A long source (a DJ mix, a live set, a full album uploaded as one YouTube video or SoundCloud set) is one library item today. Alex wants to offer splitting it into separate songs by time, with suggestions from timestamps in the description and/or from periods of silence.

Read first: [catalog vs audio concept](../product/concept-catalog-and-audio.md) (states none/server/phone), [data-model.md](../specs/data-model.md), [add-song.md](../specs/add-song.md), [api.md](../specs/api.md), [library.md](../specs/library.md), [playback.md](../specs/playback.md), [task-0036](task-0036.md) (metadata model).

Inventory (to verify during analysis):

- `server/app/extractor.py` keeps only title, artist, duration, thumbnail, dates and genre from yt-dlp. `description` and `chapters` are returned by yt-dlp but dropped today.
- Audio reaches the server only through the iOS download; the web saves metadata and plays audio already on the server.
- iOS plays with AVPlayer and lock-screen controls; the song record has `id`, `file`, `duration`, `sources[]`, `tags`, `year`, `remix_year` and no notion of a time range.

## Suggestion sources, in priority

1. YouTube chapters, if present.
2. Timestamps parsed from the description or pinned comment: `00:00 Artist - Title`, `1:02:33 - Title`, numbered lists, "Tracklist" blocks; many formats. Always a suggestion, never applied silently; show uncertainty (confidence per line, unparsed lines listed).
3. Silence detection on downloaded audio (ffmpeg `silencedetect`: noise floor, minimum silence length, minimum segment length). Works only when the audio exists on the server or phone, so a "Suggest from audio" action, like Identify from audio.
4. Beat or energy change detection: deferred.

## Behaviour

- A timeline shows suggested split points with proposed names (split with the existing Artist - Title splitter, Title, Artist and Remix token pills).
- Alex accepts, edits, adds or removes points, previews by playing around a point, then creates N library items.
- No auto-split without approval.

## Design choice to analyse

Virtual segments (each item references the same audio file with start and end offsets; no re-encoding, fast, no extra storage) versus physical cut files (ffmpeg stream copy or re-encode; more storage, simpler players). Lean: virtual segments with `start` and `end` offsets, plus an optional "export as file" later. The analysis must give reasons and list consequences for:

- playback and gapless seeking on iOS and web (AVPlayer time ranges, boundary accuracy of m4a);
- progress and queue logic; lock-screen metadata and artwork;
- offline download (download once, play segments);
- library listing and counts; stats;
- deleting one segment vs the source;
- duplicates and share links;
- search and tags (segments inherit source tags; per-segment tags editable);
- the metadata model of [task-0036](task-0036.md): keep the models compatible;
- year and remix semantics: source publish date vs per-track release.

## Constraints

- Smallest coherent model.
- Never lose the original source link or item.
- Splitting is reversible (merge back, or delete segments).
- Signed-in owner only; guests stay read-only.
- Web and iOS have equivalent semantics.
- Do not auto-split without approval; show uncertainty for parsed timestamps.
