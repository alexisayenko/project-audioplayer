# Import YouTube playlists into Drafts

> Alex: when a YouTube playlist link is put into Drafts, the app goes through the playlist video by video and adds each as a draft.

Whole feature (ADR-0032 Drafts, API-199):

- Server resolver: `GET /youtube/playlist?url=` returns the flat list of a public playlist (id, title, channel, duration, watch URL), max 500 entries, private and deleted videos skipped and counted, de-duplicated by video id, cached 5 minutes, per-user limit shared with the existing playlist import (API-162). Mixes (`RD...`), Liked and Watch later answer 422 `playlist_unavailable`. It reuses `urlclean.parse_playlist` and `extractor.playlist`; the older `POST /import/youtube-playlist` (API-160, the Add-from-playlist table) is unchanged.
- Web (separate agent): a playlist link pasted into Drafts calls the resolver, shows progress while the videos are added as drafts one by one (the existing paste path, API-182), reports skipped and truncated counts, and says plainly when the list is unavailable.

No open questions.

Server part built, not deployed, tests not run.

Web part built, not deployed, tests written but not run, not seen in a browser (LIB-200..205 in [library.md](../specs/library.md)): `web/js/drafts-import.js` (pure parsing, splitting, dedupe, chunked runner), `api.youtubePlaylist`, the progress row in `web/js/drafts.js`, `web/drafts.css`; tests `web/js/drafts-import.test.mjs` and `web/js/drafts-import-ui.test.mjs`. Each entry is added as the line "Artist - Title <watch link>" through the normal `POST /drafts` in chunks of 10 (one save per chunk), so the server runs its quick lookup per entry as for a pasted link; a long playlist can hit the hourly lookup budget (API-185), after which the rest stay "Not fetched yet" with a per-row Refresh. A watch link with `list=RD...` (auto mix) stays a plain video link.
